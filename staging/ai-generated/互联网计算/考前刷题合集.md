# 一、2025 习题课 — 全部题目（中文版）

## Ch1 计算机网络和因特网

**Q1.** 与分组交换网络相比，电路交换网络有哪些优点？TDM 比 FDM 有哪些优点？

> **答案**：电路交换优点：① 通信线路专用，数据直达，时延非常小；② 物理通路一旦建立，可随时通信，实时性强；③ 按发送顺序传送，不存在失序问题；④ 既适用模拟信号也适用数字信号；⑤ 设备控制较简单。
> TDM 优于 FDM：① 拥塞时 TDM 只丢部分数据，FDM 可能丢大部分；② TDM 适合数字信号（现代网络主流）；③ 统计时分下 TDM 按需分配时隙，空闲带宽可给其他连接用。

**Q2.** 因特网协议栈的 5 个层次及各层主要任务？

> **答案**：物理层：定义电气/机械/功能特性，传输原始比特流。链路层：相邻节点间可靠传输，帧编号、检错、重传。网络层：逻辑寻址(IP)、路由选择。运输层：端到端通信，可靠性、流量控制、拥塞控制。应用层：用户接口，HTTP/FTP/SMTP。

**Q3.** 什么是应用层报文、运输层报文段、网络层数据报、链路层帧？

> **答案**：应用层报文 = 应用协议交换数据的基本单位（如 HTTP 请求）。运输层报文段 = TCP/UDP 数据单位，含序列号/确认号/检验和。网络层数据报 = IP 数据单位，含源/目的 IP。链路层帧 = 实际传输单位，含 MAC 地址 + FCS 校验。

**Q4.** 路由器、链路层交换机、主机各处理哪些层次？

> **答案**：路由器 = 网络层 + 链路层 + 物理层。交换机 = 链路层 + 物理层。主机 = 全部五层。

## Ch2 应用层

**Q5.** 如何区分客户和服务器进程？

> **答案**：发起通信的是客户，等待连接的是服务器。

**Q6.** 运行在一台主机上的进程使用什么信息来标识另一台主机上的进程？

> **答案**：目标主机的 IP 地址 + 目标进程中套接字的端口号。

**Q7.** Alice 用 Web 邮箱（Gmail）向 Bob 发邮件，Bob 用 IMAP 收邮件。列出报文经过的各种应用层协议。

> **答案**：Alice 主机 →(HTTP)→ Alice 邮件服务器 →(SMTP)→ Bob 邮件服务器 →(IMAP)→ Bob 主机。

**Q8.** CDN 的两种服务器放置方法？

> **答案**：① **深入**：在遍及全球的接入 ISP 中部署服务器集群，靠近端用户，低时延高吞吐，但维护成本高；② **邀请做客**：在少量关键位置（IXP）建大集群，维护成本低但时延和吞吐量较差。

**Q9.** 考虑图 2-12（机构网络连因特网）。对象平均 850,000bit，请求率 16 个/秒，接入链路 15Mbps，因特网时延 3 秒。求：a) 总平均响应时间 b) LAN 中装缓存，命中率 0.4，求总响应时间。

> **答案**：a) Δ=850000/15M=0.0567s, Δβ=16×0.0567=0.907, 接入时延=0.0567/(1-0.907)≈0.6s, 总=0.6+3=**3.6s**。b) 命中 40%→β'=0.6×0.907=0.5442, 接入时延=0.124s, 总=(0.4×0)+(0.6×(0.124+3))=**1.874s**。

**Q10.** 向 N 个对等方分发 F=20Gb 文件。服务器上载 30Mbps，每对等方下载 2Mbps。对 N=10/100/1000 且 u=300kbps/700kbps/2Mbps，计算最小分发时间（C-S 和 P2P）。

> **答案**：C-S：T=MAX(NF/u_s, F/d_min)。P2P：T=MAX(F/u_s, F/d_min, NF/(u_s+Σu_i))。见表格。

## Ch3 运输层

**Q11.** 为什么语音和图像流量常走 TCP 而非 UDP？（与拥塞控制无关）

> **答案**：① **可靠性**：TCP 检测丢包、重复、错误，语音/图像对丢失不可容忍；② **有序性**：TCP 保证按序到达，UDP 不保证；③ **流量控制**：TCP 根据接收方能力调节发送速率；④ **防火墙穿透**：大多数防火墙配置为阻止 UDP 流量，TCP 可以通过。

**Q12.** 主机 C 端口 80 的 Web 服务器使用持续连接，接收 A 和 B 的请求。所有请求通过相同套接字吗？都具有端口 80 吗？

> **答案**：不通过相同套接字。每个持续连接创建单独的"连接套接字"，由四元组(源IP, 源端口, 目的IP, 目的端口)标识。两个套接字都具有端口 80。

**Q13. 是非题**：a. A 向 B 发大文件，B 无数据发回，所以 B 不发确认。b. TCP 的 rwnd 在连接过程中决不变化。c. A 发但未确认的字节数不会超过接收缓存大小。d. 序号 m 的后继报文段序号必然是 m+1。e. TCP 报文段首部中有 rwnd 字段。f. 最后 SampleRTT=1s，则 TimeoutInterval 必定 ≥1s。g. A 向 B 发序号 38 的 4 字节报文段，确认号必定是 42。

> **答案**：❌❌✅❌✅❌❌
> a. ❌ 即使无数据捎带，B 也会发送纯 ACK。
> b. ❌ rwnd 随接收缓存变化而动态改变。
> c. ✅ 发送窗口 ≤ rwnd（接收方缓存大小），所以未确认字节数不会超过接收缓存。
> d. ❌ 序号是字节偏移，与报文段数据量有关，不是 +1。
> e. ✅ TCP 首部有接收窗口(rwnd)字段（2 字节）。
> f. ❌ TimeoutInterval = EstimatedRTT + 4×DevRTT，不一定 ≥ SampleRTT。
> g. ❌ 确认号是期望收到的下一个字节号，不一定等于收到的序号+数据量。

**Q14. (P1)** 客户 A 和 B 都向服务器 S 发起 Telnet 会话。求各报文段的源端口和目的端口。e) 不同主机源端口号可否相同？f) 同一主机呢？

> **答案**：a. (A的临时端口, 23) b. (B的临时端口, 23) c. (23, A的临时端口) d. (23, B的临时端口)。e) **可能相同**——不同主机的 OS 各自独立管理端口池，可能碰巧分配同一号。四元组中 IP 不同，仍可区分。f) **不可能相同**——同一台主机的 OS 只有一个端口池，不会把同一端口分给两个进程连同一服务器。

**Q15. (P3)** UDP 和 TCP 用反码计算检验和。有 3 个 8 比特字节：01010011, 01100110, 01110100。求反码和。为什么用反码？1 比特错能检测吗？2 比特错呢？

> **答案**：和=00101110，反码=**11010001**。用反码是简单奇偶校验——接收方将数据+检验和，结果全 1 则正确。1 比特错一定能检测。2 比特同时错**可能检测不出**（0→1 和 1→0 同时发生且位置对应时抵消）。

**Q16. (P5)** UDP 接收方检验和匹配，能绝对确信无差错吗？

> **答案**：不能。两个 16 位字的对应位同时翻转（0↔1），和不变，检验和仍匹配。

**Q17. (P27)** 主机 A 已收到 B 的最长 126 字节的所有字节。A 发两个报文段：80 字节（序号 127, 源端口 302, 目的端口 80）+ 40 字节。a) 第二段序号/端口？b) 第一段先到，确认号？c) 第二段先到，确认号？

> **答案**：a) 序号=127+80=**207**，源端口=302，目的端口=80。b) 确认号=**207**（期望下一字节），源端口=80，目的端口=302。c) 确认号=**127**（乱序，仍期待第一段）。

**Q18. (P32)** TCP RTT 估计，α=0.1。a) 4 个样本 RTT 表示 EstimatedRTT。b) 一般化到 n 个。c) 为什么叫指数移动平均？

> **答案**：a) ERTT = α·SRTT₁ + α(1-α)·SRTT₂ + α(1-α)²·SRTT₃ + α(1-α)³·SRTT₄ + (1-α)⁴·ERTT₀。b) ERTT_n = Σ α(1-α)^{k-1}·SRTT_k + (1-α)^n·ERTT₀。c) 权重 α(1-α)^{k-1} 呈**指数衰减**，"移动"=每新样本进来重新算。

**Q19. (P40)** TCP Reno 图 3-61。a) 慢启动间隔？b) 拥塞避免间隔？c) 第 16 轮丢包是 3 dupACK 还是超时？d) 第 22 轮？e) 初始 ssthresh？f) 第 18 轮 ssthresh？g) 第 24 轮 ssthresh？h) 第 70 个报文段在哪轮发送？i) 第 26 轮后 3 dupACK，cwnd 和 ssthresh？j) TCP Tahoe 第 16 轮 3 dupACK，第 19 轮状态？k) Tahoe 第 17-22 轮共发多少分组？

> **答案**：a) [1,6] [23,26] b) [6,16] [17,22] c) 3 dupACK d) 超时 e) 32 f) 21 g) ≈14 h) 第 7 轮 i) cwnd=4, ssthresh=7 j) ssthresh=21, cwnd=1（Tahoe 无 Fast Recovery）k) **52 个**（Tahoe 从 cwnd=1 开始慢启动：1+2+4+8+16+21=52）

**Q20. (P48)** 一条 TCP(Reno)，10Mbps 链路，无缓存。MSS=1500B，双向传播时延=150ms，始终处于拥塞避免。a) 最大窗口（报文段计）？b) 平均窗口和平均吞吐量？c) 丢包恢复到最大窗口需多久？

> **答案**：a) BDP=10M×0.15=1,500,000bit, W=1,500,000÷8÷1500=**125 报文段**。b) 平均窗口=0.75W≈94, 吞吐量=94×1500×8÷0.15≈**7.52Mbps**。c) (125-62)×0.15=**9.45 秒**。

**Q21. (P52)** 简化 TCP AIMD：拥塞窗口用报文段数度量。C1(RTT=50ms) 和 C2(RTT=100ms) 共享 30seg/s 链路。a) t₀ 时 cwnd=10，1000ms 后各多少？b) 长期公平吗？

> **答案**：a) 都降为**1 个报文段**（总速率超标→反复丢包减半→死锁在 1）。b) **不公平**——C1 吞吐量=1/0.05=20seg/s，C2=1/0.10=10seg/s。C1 约为 C2 的 **2 倍**（RTT 短→同 cwnd 下速率更高）。

## Ch4-5 网络层（数据平面 + 控制平面）

**Q22.** 运输层分组叫报文段，链路层叫帧，网络层叫什么？路由器与链路层交换机的根本区别？

> **答案**：网络层分组叫**数据报**。根本区别：交换机基于**链路层帧的 MAC 地址**转发（L2），路由器基于**网络层数据报的 IP 地址**转发（L3）。

**Q23.** DHCP 获取哪些值？

> **答案**：IP 地址、网络掩码、默认网关 IP、本地 DNS 服务器 IP。

**Q24.** 应用每 20ms 生成 40 字节数据块，封装在 TCP 段 → IP 数据报。每个数据报开销多大？应用数据占比？

> **答案**：开销=IP 首部(20B)+TCP 首部(20B)=**40 字节**（不含选项）。总数据报=80 字节，应用数据=40 字节，占比=**50%**。

**Q25. (P11)** 路由器互联 3 个子网，前缀 223.1.17/24。子网 1 需 60 接口，子网 2 需 90 接口，子网 3 需 12 接口。提供 3 个网络地址。

> **答案**（从大到小分配）：子网2(90→128): **223.1.17.128/25**；子网1(60→64): **223.1.17.64/26**；子网3(12→16): **223.1.17.48/28**。（答案不唯一，不冲突即可）

**Q26. (P15)** 从 214.97.254/23 分配 6 个子网：A(250接口), B(120), C(120), D/E/F(各 2 接口)。给出地址和转发表。

> **答案**：A: 214.97.254.0/24(256地址), B: 214.97.255.0/25(128), C: 214.97.255.128/25(128), D/E/F: 各分配 /31 子网（2 地址）。

**Q27.** 比较链路状态(LS)和距离向量(DV)路由算法。

> **答案**：LS 需要全网拓扑→报文复杂度高、收敛快、健壮性强。DV 仅与邻居交换→报文复杂度低、收敛慢（计数到无穷）、健壮性较弱。

**Q28. (P3)** 用 Dijkstra 计算从 x 到所有节点的最短路径。

> **答案**：逐步将最近节点加入 N'，松弛邻居距离。

**Q29. (P5 + P7)** 距离向量：显示节点 z 的距离表；x 对 w/y/u 的距离向量；何时 x 通知邻居新最低开销路径？

> **答案**：Dₓ(w)=2, Dₓ(y)=4, Dₓ(u)=7 (via w: 2+5=7)。c(x,w) 减小到 1 时 → Dₓ(u)=6 更小 → 通知。c(x,w) 保持 2 不变 → 不通知。

**Q30. (P12)** BGP 如何检测路径中的环路？

> **答案**：收到 AS 路径中包含**自己 AS 编号**的路由 → 判定为环路，丢弃。

**Q31. (P14)** AS3/AS2 用 OSPF，AS1/AS4 用 RIP，AS 间用 eBGP/iBGP。各路由器从哪个协议学到前缀 x？
> **答案**：3c→**eBGP**, 3a→**iBGP**, 1c→**eBGP**, 1d→**iBGP**。

## Ch6 链路层

**Q32.** 两个节点同时经速率 R 的广播信道发长度为 L 的分组。若 d_prop < L/R，会碰撞吗？

> **答案**：会。传播时延小于传输时延 → 一个节点在发送时可能收到另一个节点的信号 → 碰撞。

**Q33.** CSMA/CD 第 5 次碰撞后，节点选 K=4 的概率？对应 10Mbps 以太网多少时延？

> **答案**：概率=1/2⁵=**0.03125 (1/32)**。时延=4×51.2μs=**204.8μs**。

**Q34.** 为什么大周长局域网中令牌环协议低效？

> **答案**：节点发送帧后必须等帧在**整个环中传播完**才能释放令牌。L/R 与 t_prop 相比较小时，大部分时间在等令牌转圈，效率极低。

**Q35. (P2)** 举例说明二维奇偶校验能纠正单比特错，但某些双比特错只能检测不能纠正。

> **答案**：单比特错→错误行和错误列的校验位同时报警→交叉定位可纠正。双比特错在同一行→行的校验位仍正确（两错抵消），只知道列出错，不知道具体哪行→无法纠正。

**Q36. (P3)** 字符串 "Internet" 的 ASCII 组成 10 字节数据，计算因特网检验和。

> **答案**：将 ASCII 两两组合为 16 位字求和，取反码。最终结果：01011101 11110011。

**Q37. (P5)** G=10011(5位), D=1010101010。求 CRC 校验码 R。

> **答案**：D 后补 4 个 0 → 1010101010 0000 ÷ 10011（模 2 除法）→ 余数 **R=0100**。

**Q38. (P8)** 时隙 ALOHA 效率 = Np(1-p)^{N-1}。a) 求最优 p。b) N→∞ 效率极限？

> **答案**：a) 求导得 **p=1/N** 时效率最大。b) lim N·(1/N)·(1-1/N)^{N-1} = **1/e ≈ 0.368 (36.8%)**。

**Q39. (P18)** A 和 B 在 10Mbps 广播信道，传播时延=325bit。A 发一帧（512+64=576bit），B 在 A 发完前发帧。A 能完成传输而不检测到碰撞吗？

> **答案**：**可以**。B 最晚在 t=324 发第一比特（A 的第一比特即将到 B 时），该比特 t=324+325=649 到 A。但 A 在 t=576 已经发完了→A 错误地认为帧成功传输。

**Q40. (P19)** A 和 B 在 10Mbps 广播信道，传播时延=245bit。t=0 同时发帧，t=245 检测碰撞。K_A=0, K_B=1。B 何时重传？A 何时开始发？A 信号何时到 B？B 抑制传输吗？

> **答案**：
> t=245+48=293: Jam 结束，退避开始
> t=293+245=538: A 检测到信道空闲
> t=538+96=634: A 开始重传
> t=293+512=805: B 醒来
> t=634+245=879: A 信号到达 B
> t=805+96=901: B 准备发 → 信道忙 → **抑制传输**

**Q41. (P26)** 6 节点(A-F)星形连接交换机，事件：i) B→E ii) E→B iii) A→B iv) B→A。显示交换机表状态和转发动作。

> **答案**：
> i) 学到 B→泛洪（E 未知）
> ii) 学到 E→单播到 B（B 已知）
> iii) 学到 A→单播到 B
> iv) B 刷新→单播到 A

## 2010 年

**单选题**：
1. POP **不是**网络层协议
2. IP 是 **Routed Protocol**（被路由协议）
3. 100BASE-TX 使用**屏蔽双绞线**
4. 802.1q=VLAN, 802.2=LLC, 802.3=MAC(以太网核心协议), 802.11=无线网
5. Hub = 集线器（物理层）
6. Transceiver = 第一层设备
7. CIDR 提供**路由聚集**功能
8. 根桥上所有端口都是**指定端口(Designated Ports)**
9. 无线速率：802.11(1-2M), 802.11b(11M/2.4GHz), 802.11a(54M/5GHz/OFDM), 802.11n(100M+)
10. 802.11b 的 MAC 机制是 **CSMA/CA**（非 CSMA/CD）
11. Host ID 全 0 和全 1 不可用
12. 组播地址：OSPF Hello=224.0.0.5, DR/BDR=224.0.0.6, RIPv2=224.0.0.9
13. 以太网用 CSMA/CD，无线网用 CSMA/CA

**多选题**：
- IP 和 IPX 是 Routed Protocols
- 冲突域 = 共用同一网线；广播域 = 广播是否被转发
- MAC 地址共 48 bit
- 以太网交换机通过 MAC 地址过滤流量
- IP 地址**不出现在**以太网帧首部

**编码汇总**（必考）：
| 编码 | 规则 |
|------|------|
| 单极性 | 0 电平=0, 正电平=1 |
| NRZ | 负电平=0, 正电平=1 |
| NRZI | 翻转=1, 不翻转=0 |
| 归零制 | 负=0, 正=1, 后半归零 |
| 曼彻斯特 | 低→高=0, 高→低=1 |
| 差分曼彻斯特 | 有跳变=0, 无跳变=1 |

## 2013 年

**单选题**：
1. IEEE 802.3 不是网络层协议（是 MAC 层）
2. 地址分类：A(0-127), B(128-191), C(192-223), D(224-239 组播), E(240-255 研究)
3. PDU 名称：链路层=**帧**, 网络层=**包/数据报**, 传输层=**数据段**, 以上=**报文**
4. 交换机收到未知目的 MAC → **泛洪到所有端口**
5. B 信道=64kbps, D 信道=16kbps, BRI=144kbps
6. 直通交换(Cut-through)：读目的 MAC 后立即转发，不等收完整帧
7. 应用层协议：SMTP
8. 以太网核心协议：802.3
9. CIDR 特点：**路由聚集**
10. 根桥上所有端口 = 指定端口
11. 广播增多导致拥塞 → 用**路由器**解决（隔离广播域）
12. 802.11a 工作在**5GHz**；802.11b 的 MAC 机制是 CSMA/CA（非 CSMA/CD）

**多选题**：
- 路由器可隔离广播，交换机需 VLAN 才能隔离广播
- 距离向量：周期性向所有活动接口发送**完整路由表**
- 链路状态：向全网路由器发送**自己链路的状态更新**
- FTP 用两个端口：21(控制) + 20(数据)
- Telnet=TCP/23, SMTP=TCP/25, DNS=UDP/53, TFTP=UDP/69, SNMP=161, HTTP=TCP/80, HTTPS=443
- DHCP 用 UDP
- PAP：中心路由器询问远端密码，不限制次数
- CHAP：每个路由器必须知道密码，中心路由器发起

**大题**：
1. ping 路径 + MAC 地址逐跳变化（IP 全程不变）
2. 曼彻斯特编码：0101100011
3. 子网划分：192.168.20.0/24
4. 路由聚合

## 2015 年

**名词解释**：PPP, UDP, Split Horizon(水平分割), CSMA/CD, HTTP, TDM(时分复用), DNS, RARP

**简答**：
1. OSI 与 TCP/IP 异同：同 = 都有层次、分组交换、基于报文。异 = TCP/IP 4 层(实用标准)，OSI 7 层(教学模型)
2. 子网划分：195.3.1.0 分 5 个子网，每子网 ≤15 台 → /28(16地址)
3. TCP 序号：A→B 序号 70 和 100。(1)第一包 30 字节数据 (2)确认号 100 (3)第二包 80 字节数据

## 2016 年

**新增考点**：
- 直通线（PC↔交换机）、反转线（Console 线缆）、交叉线（PC↔PC，同种设备）
- IPv4(32位) vs IPv6(128位)：IPv6 地址空间更大，路由表更小，安全性更强
- 解决路由环路 4 种方法：最大跳数(15→16)、水平分割、路由毒化+毒性逆转、计时器
- TCP 连接建立：SYN→SYN-ACK→ACK
- TCP 连接释放：FIN→ACK→FIN→ACK

## 2017-2019 年

**2017**：
- UTP 特点：直径小、便宜、易安装，**必须用中继器**
- NAT/PAT：一个公网 IP 给多用户使用
- 收邮件=POP3，发邮件=SMTP
- 静态路由优点：快速收敛、不占带宽、更安全、用更少 CPU
- 交换机学习不到广播地址（广播地址永远是目的地址，非源地址）
- RIP v2 特点：支持 CIDR（带子网掩码）、组播 224.0.0.9、需身份认证

**2018**：
- 数据封装：data→segments→packets→frames→bits
- Socket = (IP 地址, Port)
- 使用 TCP 的协议：HTTP, FTP, SMTP
- 使用 UDP 的协议：RIP, DNS, SNMP, TFTP, DHCP
- 私有地址：10/8, 172.16/12, 192.168/16

**2019**：
- 电磁干扰无影响：**光纤(Fiber)**
- IPv6 不是 64 位 → ❌（是 128 位）
- 不能隔离冲突域：**Hub(集线器)**
- UDP 报文解析：源端口 3122, 目的端口 53 → DNS 查询
- RIP 路由更新
- 子网划分（63, 31, 16, 12）
- 透明网关 MAC 寻址：源MAC=本机, 目的MAC=网关MAC；IP 全程不变
- 不归零/曼彻斯特/差分曼彻斯特编码

# 四、报文格式速查

| 报文 | 关键字段 | 长度 |
|------|---------|------|
| **MAC 帧** | 前导码(8B)→目的MAC(6B)→源MAC(6B)→类型(2B)→数据(46-1500B)→CRC(4B) | 64-1518B |
| **IPv4** | 版本(4b)→IHL(4b)→TOS(8b)→总长(16b)→ID(16b)→标志(3b)→片偏移(13b)→TTL(8b)→协议(8b)→检验和(16b)→源IP(32b)→目的IP(32b) | 20-60B |
| **UDP** | 源端口(16b)→目的端口(16b)→长度(16b)→检验和(16b)→数据 | 8B 头 |
| **TCP** | 源/目的端口(各16b)→序号(32b)→确认号(32b)→首部长度(4b)→保留(6b)→标志(URG/ACK/PSH/RST/SYN/FIN)→rwnd(16b)→检验和(16b)→紧急指针(16b) | 20-60B |
| **ARP** | 硬件类型→协议类型→硬件地址长度→协议地址长度→操作码→发送方MAC→发送方IP→目标MAC→目标IP | 28B |
| **ICMP** | 类型(8b)→代码(8b)→检验和(16b)→内容 | 8B 头 |
| **PPP** | Flag(01111110)→Address(FF)→Control(03)→Protocol→Data→FCS | |
| **OSPF** | Hello 报文：路由器 ID + Area ID + 邻居列表 | 直接在 IP 上(协议号89) |
