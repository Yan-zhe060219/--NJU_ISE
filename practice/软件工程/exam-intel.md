## 三、各模块考点与优先级

### 模块一：软件工程基础 🟡

- 基本概念需**明白**，不会考太深
- 项目管理基本概念了解即可

### 模块二：需求工程 🔴 核心

| 考点 | 说明 |
|------|------|
| **需求层次性** | 业务需求 → 用户需求 → 系统需求（三层递进，理解每层含义） |
| **需求分类** | 功能性需求 vs 非功能性需求 |
| 需求获取 | 目的是什么，获取什么 |
| **用例建模** | 文本描述 + **用例图**（都要会） |
| 用户故事 | 表达用户需求 |
| **系统顺序图** | Actor 与系统的交互 |
| **概念类图** | 类 + 属性，**没有方法** |
| 需求文档化 | 了解结构，不写完整规格说明 |

> 关键链路：业务需求（可度量业务指标）→ 用户需求（用例/用户故事表达）→ 系统需求（规格化，交互细节，迭代产生）

### 模块三：体系结构设计 🔴 核心

| 考点 | 说明 |
|------|------|
| 体系结构基本概念 | 构建、接口、连接件 |
| **体系结构风格** | 主程序/子程序、面向对象、**分层**（重点）、**MVC**（重点） |
| **包图** | 必须画出 PO/VO + 接口 + 层间依赖 |
| 4+1 View | 逻辑视图用包图表达 |
| 构建接口 | 供接口（提供什么）+ 需接口（需要什么） |

> 包图要点：展示层↔逻辑层(VO)↔数据层(PO)；接口表示：实现=实线+空心三角，依赖=虚线+鱼骨箭头

### 模块四：详细设计 🔴🔴 最高重点

| 考点 | 说明 |
|------|------|
| **GRASP 模式** | 控制器、信息专家、创建者、低耦合/高内聚（课件详讲5种）+ 多态/纯虚构/间接性/保护变化（标准GRASP体系·教师未逐一列举·见memory/ai-list-completion-risk.md） |
| **类的设计原则** | **约10+个，一定会考**（可能考其一，可能组合考多个） |
| 模块化与信息隐藏 | 基本概念 |
| 内聚和耦合 | ⚠️ **降级**：讲得弱，不深考。了解基本概念即可 |

> 老师原话："类的原则都会考的，我们总结了那么多类的原则，十来个都会考的"

### 模块五：人机交互 🟢

- 开发过程、基本概念了解
- **设计原则**：回答有道理即得分，不要求背文字
- 老师原话："只要你能说有道理，它都是可以对的"

### 模块六：构造、测试、开发过程 🟡

- 测试（黄老师负责，群内发布）
- 过程模型（瀑布/迭代/螺旋等）基本概念
- 维护与演化基本概念

## 四、设计模式 — 今年新考法 🔥

> **重大变化**：不再是往年那种"考某个设计模式"。

- 分解为多个小问题，给出充分的**引导材料**
- 考察能否用学过的**设计原则**扩展应用到新场景
- **不需要**提前背诵其他设计模式
- 甚至不要求写出具体模式名
- 核心能力：用类的设计原则去分析和设计

## 五、图类总览 — 各阶段必会

| 阶段 | 图名 | 关键要点 |
|------|------|----------|
| 需求 | **用例图** | Actor + 用例 |
| 需求 | **系统顺序图** | Actor 与系统交互 |
| 需求 | **概念类图** | 类 + 属性，**无方法** |
| 体系结构 | **包图** | 分层 + PO/VO + 接口 + 依赖方向 |
| 详细设计 | **顺序图** | 类/对象间消息交互 |
| 详细设计 | **状态图** | 先确定主体 → 再画状态转移 |
| 详细设计 | **流程图** | 方法内部流程 |
| 数据库 | ER 图 | 参考数据库课 |

### 消息箭头规范

| 类型 | 表示 |
|------|------|
| 同步消息 | **实线 + 实心三角箭头** |
| 异步消息 | **虚线 + 鱼骨箭头** |

### 状态图三步法
1. **确定主体**（最重要！一个红绿灯 vs 整个十字路口）
2. 确定状态 + 转移条件 + 动作
3. 转化代码：switch/if-else → 数据驱动 → State 模式

### 关联/聚合/组合
- 三者都属**关联**（长期持有引用为成员变量）
- 聚合：整体-部分，**无**生命周期约束
- 组合：整体-部分，**有**生命周期约束

## 六、关键概念速查

| 概念 | 说明 |
|------|------|
| **VO** (Value Object) | 展示层↔逻辑层，只返回所需内容 |
| **PO** (Persistent Object) | 数据层↔逻辑层，持久化对象 |
| **DAO** | ORM 映射：DB记录 ↔ 对象 |
| **控制耦合** | 传参当flag，方法内switch-case（理解即可，不考） |
| **印记耦合** | 传整个对象只需少量字段（理解即可，不考） |
