⑧ 画双边框矩形 再选科目成绩（弱实体），连属性椭圆：科目名称（下划线，部分码）、成绩

```
⑭ 画普通菱形"包含"，连接 专业组(M) 与 招生专业(N)

```
⑲ 画双边框矩形 志愿填报专业（弱实体——依赖于院校专业组志愿），连属性：

㉑ 画普通菱形"选择"，连接 志愿填报专业(N) 与 招生专业(1)

### EER 符号速查表（对照画图用）

| 元素 | 符号 | 本题中出现位置 |
|------|------|--------------|
| 强实体 | 矩形 | 考生、高校 |
| 弱实体 | **双边框** 矩形 | 招生专业、专业组、再选科目成绩、院校专业组志愿、志愿填报专业 |
| 属性 | 椭圆，无向边连实体 | — |
| 标识符（码） | 属性名下划线 | 准考证号、高校代码、专业代码、专业组代码、科目名称、志愿顺序、专业填报顺序 |
| ISA 联系 | △ 三角形 | 考生 → {文史考生, 理工考生} |
| 不相交约束 | △ 内画 × | 考生不能同时为文史和理工 |
| 完全特化 | △ 到子类用**双线** | 每名考生必属文史或理工之一 |
| 分类属性 | △ 旁标注属性名 | 考生类型 |
| 普通联系 | 单线菱形 | 包含(专业组↔招生专业)、指向(志愿→专业组)、选择(志愿填报专业→招生专业) |
| 识别联系 | **双线**菱形（双边框菱形） | 设置(高校→招生专业)、设置(高校→专业组)、拥有(考生→再选科目)、填报(考生→院校专业组志愿)、内设(院校专业组志愿→志愿填报专业) |
| M:N | 连线两端标注 M、N | 包含 |
| 1:N | 连线两端标注 1、N | 所有识别联系 |
| N:1 | 连线两端标注 N、1 | 指向、选择 |

## 1.1 实体与属性设计

### 强实体

| 实体 | 标识符 | 描述属性 |
|------|--------|---------|
| **考生** | 准考证号 | 姓名、性别、总成绩、语文、数学、外语、考生类型（分类属性） |
| **高校** | 高校代码 | 名称 |

### ISA 特化 — 考生按类型分化

> 分类属性 = `考生类型`，取值 `文史` / `理工`。不相交（Disjoint，△内有×）+ 完全特化（Total，双线连接）。

```
                    ┌──────────────┐
                    │     考生      │
                    │ 准考证号(PK) │
                    │ 姓名、性别   │
                    │ 总成绩       │
                    │ 语文 数学 外语│
                    │ 考生类型     │ ─── 分类属性
                    └──────┬───────┘
                           │
                     ISA (×, 双线 = total)
                           │
             ┌─────────────┴─────────────┐
             │                           │
      ┌──────┴──────┐            ┌──────┴──────┐
      │  文史考生    │            │  理工考生    │
      │ 历史         │            │ 物理         │
      └─────────────┘            └─────────────┘
```

### 弱实体一览

| 弱实体 | 依赖的强实体 | 识别联系 | 部分码 | 描述属性 | 与其他实体的 N:1 联系 |
|--------|------------|---------|--------|---------|---------------------|
| **招生专业** | 高校 | 设置 | 专业代码 | 名称 | — |
| **专业组** | 高校 | 设置 | 专业组代码 | 首选科目、再选科目 | — |
| **再选科目成绩** | 考生 | 拥有 | 科目名称 | 成绩 | — |
| **院校专业组志愿** | 考生 | 填报 | 志愿顺序 | 是否同意调剂 | **指向** → 专业组 (N:1) |
| **志愿填报专业** | 院校专业组志愿 | 内设 | 专业填报顺序 | — | **选择** → 招生专业 (N:1) |

> **关键理解**：志愿填报专业是**嵌套弱实体**——它的存在依赖于院校专业组志愿（第二层弱实体），形成三级依赖链：考生 → 院校专业组志愿 → 志愿填报专业。

### M:N 联系

| 联系名 | 参与实体 | 属性 |
|--------|---------|------|
| **包含** | 专业组(M) ↔ 招生专业(N) | 招生计划数 |

> 业务约束：一个专业组包含若干招生专业；一个招生专业可出现在多个专业组中。

## 1.3 EER 扩展成分总结

| 扩展成分 | 本题位置 | 课堂知识点 |
|---------|---------|-----------|
| **ISA 联系** | 考生 → {文史考生, 理工考生} | △ + 不相交(×) + 完全特化(双线) + 分类属性(考生类型) |
| **弱实体** | 招生专业、专业组 | 标识依赖高校，专业/专业组代码仅校内唯一 |
| **弱实体** | 再选科目成绩 | 多值属性按规则2处理为弱实体 |
| **弱实体（嵌套）** | 院校专业组志愿 → 志愿填报专业 | 两层弱实体形成三级依赖链 |
| **识别联系** | 设置、拥有、填报、内设 | 双边框菱形，弱实体通过它获得主码的一部分 |
| **M:N 联系含属性** | 包含（专业组 ↔ 招生专业） | 普通菱形 + 属性椭圆"招生计划数" |
| **N:1 联系** | 指向（志愿 → 专业组）、选择（专业选择 → 招生专业） | 弱实体可以参与除识别联系外的其他联系 |

## 1.4 关键业务约束

| # | 约束 | 在模型中的体现 |
|---|------|--------------|
| 1 | 同一考生对同高校同专业组最多填报一次 | R9 候选码 `(准考证号, 高校代码, 专业组代码)` |
| 2 | 每考生最多 48 个志愿 | 志愿顺序 ∈ [1, 48] |
| 3 | 每志愿最多选填 6 个专业 | 专业填报顺序 ∈ [1, 6] |
| 4 | 专业组包含的专业必须属同一高校 | `专业组.高校代码 = 招生专业.高校代码` |
| 5 | 志愿中的专业必须在该专业组包含的集合内 | 参照完整性约束 |
| 6 | 考生科目组合必须匹配所报专业组的首选/再选要求 | 应用层 CHECK：文史考生 → 首选=历史的专业组，再选科目需覆盖 |

# 第二题：EER → 关系模型转换

## 2.1 转换规则应用

| EE-R 元素 | 使用规则 | 所得关系 |
|-----------|---------|---------|
| 考生（强实体） | **规则1**：实体集 → 关系，标识符 → 主码 | R1 |
| 文史考生（ISA 子类） | **规则8-方式1**：每实体一个关系，继承父类主码 | R2 |
| 理工考生（ISA 子类） | **规则8-方式1** | R3 |
| 再选科目成绩（弱实体/多值属性） | **规则2**：多值属性 + 实体主码 → 独立关系 | R4 |
| 高校（强实体） | **规则1** | R5 |
| 招生专业（弱实体） | **规则1**：弱实体 → 关系，继承识别实体主码 + 部分码 = 主码 | R6 |
| 专业组（弱实体） | **规则1** | R7 |
| 包含（M:N 联系，有属性） | **规则5**：m:n → 独立关系，主码 = 两端实体主码之和 | R8 |
| 院校专业组志愿（弱实体） | **规则1**：继承考生主码 + 部分码(志愿顺序) = 主码；N:1 联系"指向" → 加入专业组主码作外码 | R9 |
| 志愿填报专业（弱实体） | **规则1**：继承院校专业组志愿主码 + 部分码(专业填报顺序) = 主码；N:1 联系"选择" → 加入招生专业主码作外码 | R10 |

> **为什么 ISA 选"方式1"（每实体一关系）？**
> - 无 NULL 值（文史考生表中不会出现物理成绩）
> - 查询各自类型时直接访问，不需 WHERE 过滤
> - 符合 3NF（非主属性完全函数依赖于主码）

---

**R9 — 院校专业组志愿** ⭐ *题目核心*

> **来源**：弱实体"院校专业组志愿"（规则1），识别联系"填报"继承考生主码，N:1 联系"指向"引入专业组主码作外码。

| 属性 | 类型 | 约束 |
|------|------|------|
| <u>准考证号</u> | CHAR(14) | PRIMARY KEY（联合）, *FK → R1(准考证号)* |
| <u>志愿顺序</u> | INT | PRIMARY KEY（联合）, CHECK (1 ≤ 志愿顺序 ≤ 48) |
| *高校代码* | CHAR(5) | *FK → R7(高校代码)* |
| *专业组代码* | VARCHAR(10) | *FK → R7(专业组代码)* |
| ~~准考证号~~ + ~~高校代码~~ + ~~专业组代码~~ | — | **候选码** |
| 是否同意调剂 | BOOLEAN | NOT NULL, DEFAULT FALSE |

> **主码与候选码分析：**
>
> | | 属性组 | 依据 |
> |---|--------|------|
> | **PK** | `(准考证号, 志愿顺序)` | 弱实体结构决定：识别联系"填报"引入准考证号 + 自身部分码志愿顺序 |
> | **CK** | `(准考证号, 高校代码, 专业组代码)` | 业务约束：同一考生对同一高校同一专业组最多填报一次 |
>
> **两者都唯一**。选 PK 作图结构自然（弱实体语义），CK 需加 UNIQUE 约束。等价方案：也可以选 CK 作主码、将 `(准考证号, 志愿顺序)` 设为 UNIQUE。只要确保两个属性组都唯一即可。

---

**R10 — 志愿填报专业** ⭐ *题目核心*

> **来源**：弱实体"志愿填报专业"（规则1），识别联系"内设"继承院校专业组志愿主码，N:1 联系"选择"引入招生专业主码作外码。

| 属性 | 类型 | 约束 |
|------|------|------|
| <u>准考证号</u> | CHAR(14) | PRIMARY KEY（联合）, *FK → R9(准考证号)* |
| <u>志愿顺序</u> | INT | PRIMARY KEY（联合）, *FK → R9(志愿顺序)* |
| <u>专业填报顺序</u> | INT | PRIMARY KEY（联合）, CHECK (1 ≤ 专业填报顺序 ≤ 6) |
| *高校代码* | CHAR(5) | *FK → R6(高校代码)* |
| *专业代码* | VARCHAR(10) | *FK → R6(专业代码)* |
| ~~准考证号~~ + ~~志愿顺序~~ + ~~专业代码~~ | — | **候选码** |

> **主码与候选码分析：**
>
> | | 属性组 | 含义 |
> |---|--------|------|
> | **PK** | `(准考证号, 志愿顺序, 专业填报顺序)` | 弱实体结构：继承 R9 主码 + 自身部分码 |
> | **CK** | `(准考证号, 志愿顺序, 专业代码)` | 同一志愿中不会重复选同一个专业 |
>
> "第几位选的"和"选了哪个专业"分别唯一标识一条记录。同时保证 `(准考证号, 志愿顺序, 高校代码, 专业代码) ∈ R8`（所选专业必须在该专业组包含的专业集合内）。

## 2.3 完整关系模式总表

```
R1  = 考生(准考证号, 姓名, 性别, 总成绩, 语文, 数学, 外语, 考生类型)
      PK: {准考证号}

R2  = 文史考生(准考证号, 历史)
      PK: {准考证号}
      FK: {准考证号} → R1

R3  = 理工考生(准考证号, 物理)
      PK: {准考证号}
      FK: {准考证号} → R1

R4  = 再选科目成绩(准考证号, 科目名称, 成绩)
      PK: {准考证号, 科目名称}
      FK: {准考证号} → R1

R5  = 高校(高校代码, 名称)
      PK: {高校代码}

R6  = 招生专业(高校代码, 专业代码, 名称)
      PK: {高校代码, 专业代码}
      FK: {高校代码} → R5

R7  = 专业组(高校代码, 专业组代码, 首选科目, 再选科目)
      PK: {高校代码, 专业组代码}
      FK: {高校代码} → R5

R8  = 专业组包含(高校代码, 专业组代码, 专业代码, 招生计划数)
      PK: {高校代码, 专业组代码, 专业代码}
      FK: {高校代码, 专业组代码} → R7
      FK: {高校代码, 专业代码} → R6

R9  = 院校专业组志愿(准考证号, 志愿顺序, 高校代码, 专业组代码, 是否同意调剂)
      PK:  {准考证号, 志愿顺序}                 ← 弱实体结构
      CK:  {准考证号, 高校代码, 专业组代码}      ← 业务约束"不重复填报"
      UNIQUE: {准考证号, 高校代码, 专业组代码}
      FK: {准考证号} → R1
      FK: {高校代码, 专业组代码} → R7

R10 = 志愿填报专业(准考证号, 志愿顺序, 专业填报顺序, 高校代码, 专业代码)
      PK:  {准考证号, 志愿顺序, 专业填报顺序}     ← 弱实体结构
      CK:  {准考证号, 志愿顺序, 专业代码}         ← "不重复选专业"
      UNIQUE: {准考证号, 志愿顺序, 专业代码}
      FK: {准考证号, 志愿顺序} → R9
      FK: {高校代码, 专业代码} → R6
```

## 2.4 答疑：常见疑问

| 疑问 | 解答 |
|------|------|
| **Q: 院校专业组志愿为什么要建模为弱实体？** | 志愿离开考生没有意义（存在依赖），且 `志愿顺序` 只在同一考生内唯一（部分码）——完全符合弱实体定义 |
| **Q: 为什么 R9 不用 `(准考证号, 高校代码, 专业组代码)` 做主码？** | 两种都可以。用志愿顺序做主码体现弱实体语义；用高校+专业组做主码更贴近业务。只要另一个加 UNIQUE 即可 |
| **Q: 再选科目放在子类属性行不行？** | 可以但不推荐——考试中 EER 更看重对"多值属性→弱实体"规则的理解 |
| **Q: 志愿填报专业为什么也是弱实体？** | 它依赖于院校专业组志愿（不是强实体），形成三级依赖链——这完全合法 |

## 设计关键点总结

| 设计点 | 决策 | 依据 |
|--------|------|------|
| 考生 → ISA 特化 | 不相交(×) + 完全特化(双线) | 必属文史或理工之一 |
| 再选科目 | 弱实体 `(准考证号, 科目名称, 成绩)` | 多值属性的标准 EER 处理（课件规则2） |
| ISA → 关系 | 方式1，每实体一关系 | 无 NULL，查询直观 |
| 招生专业、专业组 | 弱实体（依赖高校） | 代码仅校内唯一 |
| 包含 | M:N 独立关系 + 属性 | 课件规则5（m:n → 独立关系） |
| 院校专业组志愿 | 弱实体（依赖考生）+ N:1 指向专业组 | 存在依赖 + 部分码志愿顺序 |
| 志愿填报专业 | 嵌套弱实体（依赖院校专业组志愿）+ N:1 选择招生专业 | 三级依赖链：考生 → 志愿 → 专业选择 |

# 附录：考试写法速查

## PK / FK / CK 含义

| 缩写 | 全称 | 含义 | 考试表示法 |
|------|------|------|----------|
| **PK** (主码) | Primary Key | 唯一标识一个元组，从候选码中选出 | 属性下加 <u>实线下划线</u> |
| **FK** (外码) | Foreign Key | 本关系中的属性，引用另一个关系的 PK | 属性下加 <u>虚线下划线</u>（波浪线），并注明 `FK → 目标关系` |
| **CK** (候选码) | Candidate Key | 能唯一标识元组的属性组，PK 是其中一个 | 同下划线，旁注"候选码" |

> **注意**：有些教材/老师用实线下划线 = 主码、虚线下划线 = 候选码。写清楚即可，关键是逻辑正确。

## 考试时关系模型怎么写

**不需要**写数据类型、CHECK 约束、NOT NULL。**只需要**写属性名 + 标注 PK/FK/CK：

```
关系名(主码属性, 普通属性, 外码属性)
```

换算公式：**实体名→关系名，属性→列，标识符→主码，弱实体继承识别实体的码做外码**。
