## 1. E-R 图 → 关系表

### 核心规则

| 联系类型 | 处理方式 | 联系属性放哪 |
|----------|----------|-------------|
| 1:1 | 合并到任一侧 | 跟过去 |
| 1:N | 合并到 **N 端** | 跟到 N 端 |
| M:N | **必须独立建表** | 放新表里 |

### 易错点
- ❌ 把 1:N 的联系属性放到 1 端 → ✅ 放到 N 端
- ❌ M:N 不建表，直接在实体表加 FK → ✅ M:N 必须独立建中间表
- ❌ 忘记带联系属性 → ✅ 联系属性跟着联系走

### 2022 Q1 示例

商店(商店号,地点,商店名) —1:N— 聘用(聘用时间,月薪) — 职工(职工号,...)
商店 —M:N— 经营(销量) — 商品

```
商店(商店号, 地点, 商店名)          PK: 商店号
职工(职工号, 职工名, 年龄, 性别, 商店号, 聘用时间, 月薪)  PK: 职工号  FK: 商店号→商店
商品(商品号, 商品名, 种类)          PK: 商品号
经营(商店号, 商品号, 销量)         PK: (商店号,商品号)  FK: 商店号→商店, 商品号→商品
```

## 2. 关系代数

### 五种基本运算速记

| 运算 | 符号 | 作用 | 线索词 |
|------|------|------|--------|
| 选择 | σ | 筛行 | "满足条件" |
| 投影 | π | 选列 | "查询…列" |
| 并 | ∪ | 合并同类 | "…或…" |
| 差 | − | 剔除 | "没有"、"不" |
| 笛卡尔积 | × | 全组合 | 极少单独用 |

### 常用扩充

| 运算 | 符号 | 线索词 | 等价于 |
|------|------|--------|--------|
| 自然连接 | ⋈ | "…和…一起查" | π(σ(×)) |
| 除法 | ÷ | "所有"、"全部"、"每一个" | π(π×π−π)/π |

### 写法顺序口诀

```
先拼表（⋈）→ 再筛行（σ）→ 最后选列（π）
π 列 (σ 条件 (表1 ⋈ 表2 ⋈ ...))
```

### 五大经典查询模式

**① 简单查**：`π 列 (σ 条件 (表))`
```
π 职务, 部门编号 (σ 姓名="王三" (员工))
```

**② 多表连接**：`π 列 (σ 条件 (表1 ⋈ 表2 ⋈ 表3))`
```
π 项目名称, 姓名 (σ 工时>50 (项目 ⋈ 施工 ⋈ 员工))
```

**③ "没干过"**（差运算）：`全体 − 干过的`
```
π_aname((π_aid(A) − π_aid(σ_pid='p01'(O))) ⋈ A)
→ 没卖过p01的供应商
```

**④ "只干过X和Y"**（交 + 差）：`都干过的 − 还干过别的`
```
π_cid(σ_X(O)) ∩ π_cid(σ_Y(O)) − π_cid(σ_其他(O))
→ 只买过X和Y的顾客
```

**⑤ "在所有的X都Y过"**（除法）：`π_主体,范围(⋈) ÷ π_全部`
```
π_aid,city(O ⋈ C) ÷ π_city(C)
→ 在所有有顾客的城市都销售过的供应商
```

## 3. SQL 核心模板

### 基础查询骨架
```sql
SELECT [DISTINCT] 列
FROM 表1
JOIN 表2 ON 表1.x = 表2.x
WHERE 条件
GROUP BY 列
HAVING 聚合条件
ORDER BY 列 ASC/DESC;
```

### JOIN 写法
```sql
-- 多表拼接（最常用）
SELECT ...
FROM 表A
JOIN 表B ON A.x = B.x
JOIN 表C ON B.y = C.y
WHERE ...
```

### 视图
```sql
CREATE VIEW 视图名 AS
SELECT ...
FROM ...
WHERE ...;
```

### 更新
```sql
UPDATE 表
SET 列 = 表达式
WHERE 列 IN (SELECT ...);
```

### SQL 除法：NOT EXISTS 双重否定

> "满足所有…" = 不存在任何一个…是没干过的

```sql
SELECT ... FROM A
WHERE NOT EXISTS (           -- 不存在任何一个
    SELECT * FROM B
    WHERE NOT EXISTS (       -- A 没干过 B
        SELECT * FROM 中间表
        WHERE 中间表.Akey = A.key
          AND 中间表.Bkey = B.key
    )
);
```

**2022 Q1(3) 示例**：高级工程师 + 至少参与一个预算>100w项目 → 部门名
```sql
SELECT DISTINCT 部门.部门名称
FROM 员工
JOIN 施工 ON 员工.员工编号 = 施工.员工编号
JOIN 项目 ON 施工.项目编号 = 项目.项目编号
JOIN 部门 ON 员工.部门编号 = 部门.部门编号
WHERE 员工.职务 = '高级工程师' AND 项目.预算 > 100;
```

### 聚集函数 + GROUP BY
```sql
-- 统计每人总工时
SELECT 员工编号, SUM(工时) AS 总工时
FROM 施工
GROUP BY 员工编号;

-- 筛选累计≥1000
SELECT tno, COUNT(*), SUM(hours)
FROM TC
GROUP BY tno
HAVING SUM(hours) >= 1000
ORDER BY SUM(hours) DESC;
```

| 聚集函数 | 作用 | 注意 |
|----------|------|------|
| COUNT(*) | 行数 | 不计 NULL |
| COUNT(col) | 非空值数 | DISTINCT 去重 |
| SUM / AVG | 求和/均值 | 只算数值 |
| MAX / MIN | 最大/最小 | — |

### 易错点
- ❌ WHERE 里用聚集函数 → ✅ HAVING 里才能用聚集函数
- ❌ GROUP BY 漏了 SELECT 中的非聚合列 → ✅ 非聚合列必须出现在 GROUP BY 里
- ❌ 更新忘了 WHERE → ✅ UPDATE 必须加条件，先 SELECT 确认范围

## 4. 函数依赖与规范化（过往遗留）

> 详见复习思考题14、20 的练习。此处仅列核心规则。

### Armstrong 公理
- **自反律**：Y ⊆ X → X → Y
- **增广律**：X → Y → XZ → YZ
- **传递律**：X → Y, Y → Z → X → Z

### 范式判别速查
```
1NF：属性不可再分
2NF：非主属性完全依赖于每个候选码（消除部分依赖）
3NF：非主属性不传递依赖于候选码
BCNF：每个函数依赖的左边都包含候选码
4NF：消除非平凡的多值依赖
```

### 最小覆盖 / 候选码 / 模式分解
- 最小覆盖：删除冗余FD → 删除左部冗余属性 → 合并右部
- 候选码：从属性闭包出发，最小能推全集的属性集
- 无损分解：R1 ∩ R2 → R1 − R2 或 R1 ∩ R2 → R2 − R1

## 5. 常见错误速查

| 场景 | 错误 | 正确 |
|------|------|------|
| E-R 转表 | 1:N 联系属性放 1 端 | 放 N 端 |
| E-R 转表 | M:N 不建表 | 必须独立建表 |
| 关系代数 | σ 和 π 写反 | 先 σ 后 π |
| 关系代数 | 连接条件漏写 | 自然连接不用条件，但 σ 条件要写 |
| SQL | WHERE 后用聚集函数 | 用 HAVING |
| SQL | GROUP BY 缺列 | SELECT 非聚合列全进 GROUP BY |
| SQL | UPDATE 无 WHERE | 先 SELECT 确认再 UPDATE |
| 范式 | 候选码找漏 | 属性闭包全推一遍 |
| 范式 | 传递依赖误判 | 经过候选码的"传递"不算传递依赖 |
