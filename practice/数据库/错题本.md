## 6.27 · 2026 练习卷 — 关系代数

### Q16 · 关系代数 6 大模式速查

- **来源**：2026 练习卷 · 第二大题 6 小题
- **弱项**：🔴 不会用 ⋈ 偏爱 × + σ；Q3-Q6 无思路
- **核心思维转换**：

  | 中文信号 | SQL思维 | 关系代数等价 |
  |---------|---------|------------|
  | "没有"、"不" | NOT EXISTS | **−** (差)：全体 − 有的 = 没有的 |
  | "最高/最低" | MAX/MIN | **自× + −**：不存在比它更高的 |
  | "所有…都" (全局) | NOT EXISTS(NOT EXISTS...) | **÷** (除)：覆盖S中全部值的X |
  | "所有…都" (分组) | 同上但分组 | **⋈自身 + −**：应有−实有=缺失 |

  **× vs ⋈ 选择规则**：
  - 等值连接 + 同名属性 → **⋈**（简洁，标准答案用这个）
  - 不等值条件(≠, <, >) → **σ + ×**（⋈ 只能等值）
  - 大多数题：⋈ 负责连接 + σ 负责筛选

  **Q3 模板（NOT EXISTS）**：`π(全体) − π(全体 ⋈ 条件表)` 
  **Q4 模板（MAX per group）**：`Temp − π(σ_{T1.key=T2.key ∧ T1.val < T2.val}(ρT1(Temp)×ρT2(Temp)))`
  **Q5 模板（ALL 全局÷）**：`π_{X, Y}(事实表) ÷ π_Y(全集)`
  **Q6 模板（ALL 分组）**：`π_X(全局) − π_X( (应有) − (实有) )`

- **回看**：考试遇到关系代数 → 先识别信号词 → 套对应模板 → 逐层写出

### Q17 · 关系代数 ÷（除法）— "所有…都" 模式

- **来源**：2026 练习卷 · Q5 + Q6
- **弱项**：🔴 识别不出除法场景，不会构造被除关系和除关系
- **问题**：Q1-Q4 已掌握，Q5-Q6 无思路

**除法 ÷ 的直觉理解**：

  > R ÷ S = { x | 对于 S 中的**每一个** y，(x, y) 都在 R 中 }
  >
  > 翻译：x 和 S 中**所有**值都配对过 → x 是"全覆盖"的

  **三步构造法**：
  1. **识别"所有"修饰的是谁** → 这就是除关系 S（一列）
  2. **识别"谁"要覆盖所有** → 这就是结果（X）
  3. **构造被除关系 R(X, Y)** = 事实表中每条记录对应的 (谁, 所有修饰的列)

  **Q5 拆解**："在所有有顾客的城市中都销售过商品的供应商"
  
  | 步骤 | 内容 |
  |------|------|
  | "所有"修饰谁？ | 所有**有顾客的城市** → S = π_{city}(C) |
  | 谁要全覆盖？ | 供应商 sid |
  | 被除关系 R？ | 每个供应商在哪些城市销售过 → π_{sid, C.city}(C ⋈ O) |
  | 结果 | **R ÷ S** = π_{sid, C.city}(C ⋈ O) ÷ π_{city}(C) |

  **Q6 拆解**："向自己所在城市中所有顾客都销售过商品的供应商"
  
  | 步骤 | 内容 |
  |------|------|
  | "所有"修饰谁？ | 每个供应商**自己城市**中的所有顾客 |
  | 谁要全覆盖？ | 供应商 sid |
  | 复杂点 | "所有顾客"不是全局的，是按供应商分组的 |
  | 解法 | 用差运算：π_{sid}(S) − π_{sid}( (π_{sid,cid}(S ⋈ C)) − π_{sid,cid}(O) ) |
  | 解读 | 应有（S⋈C得到每个供应商城市的全部顾客）− 实有（O中实际销售记录）= 缺失 → 缺失为空者为全覆盖 |

  **Q5 vs Q6 对比**：
  | | Q5 全局除法 | Q6 分组除法 |
  |--|-----------|-----------|
  | "所有"范围 | 全局所有城市 | 每个供应商自己的城市 |
  | 解法 | ÷ 一步到位 | 差运算 (应有 − 实有) |
  | 关键区别 | 除关系固定 | 除关系随供应商变化 |

- **回看**：①÷ 三步构造法 ②Q5=全局÷ / Q6=分组差 ③"所有…都"先想÷，÷不了就用差

## 6.27 · 2026 练习卷 — 选择题

### Q8 · 三级模式结构：外模式/模式/内模式

- **来源**：2026 练习卷 · 选择题第 2 题
- **题目**：用于描述数据库用户（包括应用程序员和最终用户）使用的局部数据的逻辑结构和特征的是____
- **选项**：A. 外模式 B. 内模式 C. 物理模式 D. 逻辑模式
- **弱项**：🟡 概念遗忘
- **正确答案**：**A. 外模式**
- **详细讲解**：

  数据库系统的三级模式结构（ANSI/SPARC 架构）：

  | 层级 | 别名 | 描述对象 | 数量 |
  |------|------|---------|------|
  | **外模式** (External Schema) | 子模式/用户模式 | 用户视角的**局部**数据逻辑结构 | 多个（每个用户/应用一个） |
  | **模式** (Schema) | 逻辑模式/概念模式 | 全体数据的**全局**逻辑结构 | **唯一** |
  | **内模式** (Internal Schema) | 存储模式/物理模式 | 数据的**物理**存储结构 | **唯一** |

  **解题关键**：题干关键词"局部数据"→ 外模式。模式描述的是全局数据，内模式/物理模式描述的是存储，都不涉及"局部"。

  **二级映像**（配套机制）：
  - 外模式/模式映像 → 保证逻辑独立性（模式变，外模式不变）
  - 模式/内模式映像 → 保证物理独立性（内模式变，模式不变）

- **记忆口诀**：**"外用局部，内管存储，模式全局唯一"**

### Q9 · 基本关系操作：5 种基本运算

- **来源**：2026 练习卷 · 选择题第 4 题
- **题目**：下列关系代数操作符中，不是基本关系操作的是____
- **选项**：A. 并运算 B. 交运算 C. 差运算 D. 笛卡尔积
- **弱项**：🔴 错选 D（笛卡尔积）
- **正确答案**：**B. 交运算**
- **错误原因**：以为笛卡尔积不是基本操作，实际上笛卡尔积是 5 种基本操作之一，交运算才是可由差运算导出的非基本操作。

  关系代数的 **5 种基本运算**（不可由其他运算导出）：
  
  | 运算 | 符号 | 是否基本 |
  |------|------|---------|
  | 并 (Union) | ∪ | ✅ 基本 |
  | 差 (Difference) | − | ✅ 基本 |
  | **笛卡尔积** (Cartesian Product) | × | ✅ 基本 |
  | 选择 (Selection) | σ | ✅ 基本 |
  | 投影 (Projection) | π | ✅ 基本 |
  
  **非基本运算**（可由基本运算导出）：
  - **交** ∩：R ∩ S = R − (R − S) ← 可由差导出 ← **本题答案**
  - **连接** ⋈：R ⋈ S = σ(R × S) ← 可由笛卡尔积+选择导出
  - **除** ÷：可由投影+差+笛卡尔积导出

  > 🔴 **你选 D 的思维链条**：笛卡尔积 → 感觉不像"基本" → 选它。纠正：笛卡尔积无法由其他运算导出（没有乘法基础你做不了笛卡尔积），恰恰是基础运算；交运算可由 R − (R − S) 导出，反而不是基本的。

- **记忆口诀**：**"并差积选投，五基本；交连除，三导出"**

### Q10 · 候选码 vs 主码 vs 超码

- **来源**：2026 练习卷 · 选择题第 5 题
- **题目**：若关系 R 中的某一属性组的值能唯一地标识一个元组，而其所有的真子集都不能，则该属性组被称为关系 R 的____
- **选项**：A. 主码 B. 外码 C. 超码 D. 码
- **弱项**：🔴 概念混淆 — 错选 A（主码）
- **正确答案**：**D. 码**（Candidate Key，即候选码）
- **详细讲解**：

  **"码"相关概念的层级关系**（从宽到严）：

  ```
  超码 (Superkey)
    ├── 能唯一标识元组的属性组（真子集可能也能）
    │   例：{学号, 姓名} 是超码（学号单独就能唯一标识）
    │
    └── 候选码 (Candidate Key) = 题干中的"码"
         ├── 能唯一标识元组 AND 任何真子集都不能
         │   "最小的超码"——去掉任何属性就失去唯一性
         │   例：{学号} 是候选码
         │
         └── 主码 (Primary Key)
              └── 从多个候选码中**人为选定**的一个
                  例：{学号} 和 {身份证号} 都是候选码，选 {学号} 作主码
  ```

  **解题关键**：题干"所有真子集都不能唯一标识"→ 排除了超码（超码允许真子集也能标识）→ 候选码。而主码是人为选定的，不是数学定义的。

- **区分记忆**：
  - 超码 = 能唯一标识（不管是否最小）
  - 候选码(码) = **最小**超码 ← 题干定义
  - 主码 = 人为选中的候选码

### Q11 · 完整性约束的定义位置：触发器不在 CREATE TABLE 中

- **来源**：2026 练习卷 · 选择题第 6 题
- **题目**：在下述数据完整性约束中，不是在基表 (base table) 创建命令中定义的是____
- **选项**：A. 主码 B. 外码 C. 触发器 D. 非空约束
- **弱项**：🔴 错选 B（外码）
- **正确答案**：**C. 触发器**
- **详细讲解**：

  **CREATE TABLE 中可定义的约束**（列级或表级）：
  - `PRIMARY KEY` → 主码约束
  - `FOREIGN KEY ... REFERENCES` → 外码约束
  - `NOT NULL` → 非空约束
  - `UNIQUE` → 唯一约束
  - `CHECK` → 检查约束

  **触发器 (Trigger)** 是独立的数据库对象，用 `CREATE TRIGGER` 命令单独创建，**不在 CREATE TABLE 语句中定义**。

  ```sql
  -- 这些都在 CREATE TABLE 中定义
  CREATE TABLE Student (
    sno CHAR(8) PRIMARY KEY,        -- 主码 ✓
    sname VARCHAR(20) NOT NULL,     -- 非空 ✓
    dept VARCHAR(20),
    FOREIGN KEY (dept) REFERENCES Dept(dname)  -- 外码 ✓
  );
  
  -- 触发器独立创建，不在 CREATE TABLE 中
  CREATE TRIGGER grade_check
  BEFORE INSERT ON Enrollment
  FOR EACH ROW
  WHEN (NEW.grade < 0 OR NEW.grade > 100)
  BEGIN
    RAISE EXCEPTION '成绩必须在0-100之间';
  END;
  ```

- **记忆口诀**：**"主外非空检查唯，表内定义；触发器，独立创建"**

### Q12 · 外码违约处理：CASCADE / RESTRICT / SET NULL

- **来源**：2026 练习卷 · 选择题第 7 题
- **题目**：在下述选项中，不是外码约束的违约处理规则的是____
- **选项**：A. CASCADE B. CHECK C. RESTRICT D. SET NULL
- **弱项**：🔴 完全不了解
- **正确答案**：**B. CHECK**
- **详细讲解**：

  当对被参照表进行 **DELETE** 或 **UPDATE** 操作，导致参照表中的外码值"悬空"时，**4 种违约处理策略**：

  | 策略 | 行为 | 示例（删除被参照元组时） |
  |------|------|------------------------|
  | **CASCADE** (级联) | 同步操作传递到参照表 | 删除学生 → 自动删除该学生的选课记录 |
  | **RESTRICT** (限制) | 如果有参照元组则**拒绝**操作 | 有选课记录的学生 → 拒绝删除 |
  | **SET NULL** (置空) | 将外码值设为 NULL | 删除学生 → 选课记录的 sno 设为 NULL |
  | **SET DEFAULT** (设默认值) | 将外码值设为默认值 | （部分 DBMS 支持） |

  **CHECK 是什么？** CHECK 是一种**完整性约束类型**（检查某个条件是否成立，如 `CHECK(grade BETWEEN 0 AND 100)`），不是外码违约的处理策略。

  ```sql
  -- 外码定义 + 违约处理
  FOREIGN KEY (sno) REFERENCES Student(sno)
    ON DELETE CASCADE    -- 级联删除
    ON UPDATE RESTRICT   -- 限制更新
  ```

- **记忆口诀**：**"级联CASCADE传下去，限制RESTRICT不让删，置空SET NULL留个空，CHECK只是做约束"**

### Q13 · 无损连接分解的形式化定义

- **来源**：2026 练习卷 · 选择题第 8 题
- **题目**：设 R 为关系模式，F 为函数依赖集，ρ = {R₁, R₂} 构成 R 的一个分解，该分解具有"无损连接性"的定义是____
- **选项**：涉及投影、自然连接、并的公式组合（A/B/C/D 四个形式化表达式）
- **弱项**：🔴 错选 D
- **正确答案**：**A**（即 ρ 具有无损连接 ⇔ 对于 R 的任意合法实例 r，有 r = π_{R₁}(r) ⋈ π_{R₂}(r)）
- **详细讲解**：

  **无损连接分解 (Lossless-Join Decomposition)** 的核心定义：

  > 将 R 分解为 R₁ 和 R₂ 后，对**任意**满足 F 的关系实例 r，将其投影到 R₁ 和 R₂ 上再自然连接，能**精确恢复**原始关系 r。
  >
  > 即：**r = π_{R₁}(r) ⋈ π_{R₂}(r)**

  **两个等价条件**（更实用的判定法）：
  
  对于 ρ = {R₁, R₂}：
  - 分解无损 ⇔ **(R₁ ∩ R₂) → (R₁ − R₂) ∈ F⁺** 或 **(R₁ ∩ R₂) → (R₂ − R₁) ∈ F⁺**
  
  即：两个子关系模式的**公共属性**能函数决定其中一个的**独有属性**。

  **实例理解**：
  ```
  R(A, B, C), F = {A → B}
  R₁(A, B), R₂(A, C)
  
  交集 = {A}，R₁独有 = {B}，R₂独有 = {C}
  A → B ∈ F⁺ ✓ → 无损！
  
  投影再连接：
  r:  (1, b1, c1), (1, b1, c2)  
  → π_{R₁} ⋈ π_{R₂} = 原样恢复 ✓
  ```

  **有损分解反例**：
  ```
  R(A, B, C), F = {A → B}
  R₁(A, B), R₂(B, C)
  
  交集 = {B}，既不能决定 {A} 也不能决定 {C} → 有损！
  投影再连接可能产生多余的"假元组"
  ```

- **记忆口诀**：**"无损 = 投影连回去不丢不增；判定 = 公共属性决定一方独有"**

### Q14 · SQL 权限管理：GRANT 授予 / REVOKE 回收

- **来源**：2026 练习卷 · 选择题第 10 题
- **题目**：在 SQL 语言中，从用户那里回收访问权限的 SQL 命令动词是____
- **选项**：A. DELETE B. DROP C. GRANT D. REVOKE
- **弱项**：🔴 完全不了解
- **正确答案**：**D. REVOKE**
- **详细讲解**：

  SQL 的**自主存取控制 (DAC)** 使用两个命令管理权限：

  | 命令 | 方向 | 语法 |
  |------|------|------|
  | **GRANT** | 授予权限 | `GRANT SELECT ON Table TO User` |
  | **REVOKE** | 回收权限 | `REVOKE SELECT ON Table FROM User` |

  区分其他"删除/去除"类命令：

  | 命令 | 作用对象 | 效果 |
  |------|---------|------|
  | `DELETE` | 元组（行） | 删除表中的数据行 |
  | `DROP` | 数据库对象 | 删除整个表/视图/索引/数据库 |
  | `REVOKE` | 权限 | 收回用户的访问权限 |

  ```sql
  -- 示例
  GRANT SELECT, INSERT ON Student TO user1;        -- 授予查询和插入权限
  REVOKE INSERT ON Student FROM user1;             -- 收回插入权限
  ```

- **记忆口诀**：**"GRANT 给，REVOKE 收；DELETE 删行，DROP 删表"**

### Q15 · 游标操作：DECLARE → OPEN → FETCH → CLOSE

- **来源**：2026 练习卷 · 选择题第 12 题
- **题目**：在下述的游标操作命令中，用于返回一条结果元组的是____
- **选项**：A. CLOSE B. DECLARE C. FETCH D. OPEN
- **弱项**：🔴 完全不了解
- **正确答案**：**C. FETCH**
- **详细讲解**：

  **游标 (Cursor)** 是 SQL 中逐行处理查询结果的机制。嵌入式 SQL 中**游标的 4 步生命周期**：

  ```
  DECLARE → OPEN → FETCH (循环) → CLOSE
   声明      打开     取一行        关闭
  ```

  | 步骤 | 命令 | 作用 |
  |------|------|------|
  | 1️⃣ 声明 | `DECLARE cur CURSOR FOR SELECT ...` | 定义游标，绑定查询（不执行） |
  | 2️⃣ 打开 | `OPEN cur` | 执行查询，将结果集载入游标，指针指向第一行之前 |
  | 3️⃣ 取元组 | `FETCH cur INTO :var1, :var2` | **返回当前一行数据**，指针后移。循环调用逐行获取 |
  | 4️⃣ 关闭 | `CLOSE cur` | 释放游标资源 |

  ```sql
  -- 完整示例：逐行处理学生信息
  DECLARE stu_cursor CURSOR FOR 
    SELECT sno, sname FROM Student WHERE dept = 'CS';
  
  OPEN stu_cursor;
  
  LOOP
    FETCH stu_cursor INTO :sno_var, :sname_var;  -- 取一行 ← 本题答案
    IF NOT FOUND THEN EXIT;                      -- 无更多行则退出
    -- 处理当前行数据...
  END LOOP;
  
  CLOSE stu_cursor;
  ```

  **解题关键**：FETCH 是唯一"返回一行数据"的操作。DECLARE 只是声明，OPEN 只是打开结果集，CLOSE 只是释放。

- **记忆口诀**：**"DECLARE 声明 OPEN 开，FETCH 取数 CLOSE 关"**

### Q20 · NOT EXISTS 必须通过外层别名关联（🔴 核心坑）

- **来源**：2026 练习卷 · 第三大题第 3 题
- **原题**：查询**只讲授过自己工作所在院系开设的课程**的教师的**工号和姓名**
- **我的答案**：
  ```sql
  SELECT tno, tname
  FROM Teacher
  WHERE NOT EXISTS (
      SELECT *
      FROM Teacher, Courseclass, Course
      WHERE Teacher.dept != Course.dept
        AND Course.cno = Courseclass.cno
        AND Courseclass.tno = Teacher.tno
  );
  ```
- **弱项**：🔴 NOT EXISTS 关联逻辑错误
- **错误原因**：子查询 FROM 中包含了一个**独立的 Teacher 表**，与外层 Teacher 无任何关联条件。子查询中的 `Teacher.tno`、`Teacher.dept` 引用的是子查询自己的 Teacher 实例，不是外层的当前教师行。后果：子查询对所有外层教师返回**同一个结果**（全选或全不选），无法逐行判断。
- **正确答案**：
  ```sql
  SELECT T.tno, T.tname
  FROM Teacher T
  WHERE NOT EXISTS (
      SELECT *
      FROM Courseclass CC, Course C
      WHERE CC.tno = T.tno              -- ← 关联外层！
        AND C.cno = CC.cno
        AND C.dept != T.dept            -- 课程院系 ≠ 该老师院系
  );
  ```
- **NOT EXISTS 黄金法则**：子查询**必须**通过外层别名（如 `T.tno`）关联外层当前行。不关联 = bug。
- **回看**：每写 NOT EXISTS → 检查子查询中是否有 `外层别名.列 = 子查询.列` 的关联条件。

### Q22 · 双重 NOT EXISTS 逻辑方向

- **来源**：2026 练习卷 · 第三大题第 5 题
- **原题**：查询修读了自己就读院系开设的**所有"核心"课**的学生的**学号和姓名**
- **我的答案**（初版，已废弃）：
  ```sql
  -- ❌ 错误的初版：NOT EXISTS 内部语义写反
  SELECT s.sno, s.sname
  FROM Student s
  WHERE NOT EXISTS (
      SELECT *
      FROM Course c
      WHERE c.opt = '核心' AND c.dept = s.dept
        AND EXISTS (...)     -- 逻辑方向反了
  );
  ```
- **弱项**：🟡→🟢（最终纠正）
- **错误原因**：双重 NOT EXISTS 中，"所有 X 都满足" = `NOT EXISTS (X 不满足)` = `NOT EXISTS (X AND NOT EXISTS (配对))`。我初次书写时把内层写成 `EXISTS` 而非 `NOT EXISTS`，忽视了外层 NOT EXISTS 自身的否定语义。
- **正确答案**：
  ```sql
  SELECT s.sno, s.sname
  FROM Student s
  WHERE NOT EXISTS (                          -- 不存在
      SELECT * FROM Course c
      WHERE c.opt = '核心' AND c.dept = s.dept   -- 一门核心课
        AND NOT EXISTS (                      -- 且该学生没修读 ← 内层也是 NOT EXISTS
            SELECT * FROM Enrollment e, Courseclass cc
            WHERE s.sno = e.sno
              AND e.ccno = cc.ccno
              AND cc.cno = c.cno
        )
  );
  ```
- **SQL 除法模板**：`NOT EXISTS (S中元素 AND NOT EXISTS (R中配对))` — 内外层**都是** NOT EXISTS。
- **回看**：双重 NOT EXISTS 每次都要默念一遍模板，防止写成 EXISTS + NOT EXISTS 的混搭。

### Q23 · GROUP BY / HAVING 子句顺序

- **来源**：2026 练习卷 · 第三大题第 6 题
- **原题**：针对**所有课程都及格**的学生，统计每一位同学的课程学习情况，返回学生的**学号、姓名、课程平均成绩、总学分数**，按平均成绩降序
- **我的答案**：
  ```sql
  SELECT s.sno, s.sname, AVG(e.grade), SUM(c.credit)
  FROM Student s, Enrollment e, Course c, Courseclass cc
  WHERE s.sno = e.sno AND e.ccno = cc.ccno AND cc.cno = c.cno
  HAVING (MIN(grade) >= 60)        -- ❌ HAVING 在 GROUP BY 之前
  GROUP BY s.sno                    -- ❌ 非聚合列 sname 未进 GROUP BY
  ORDER BY AVG(e.grade) DESC;
  ```
- **弱项**：🟡 SQL 子句顺序 + 非聚合列规则
- **两个错误**：
  1. **子句顺序错**：SQL 子句有固定顺序 — `FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY`。`HAVING` 必须在 `GROUP BY` 之后。
  2. **非聚合列未进 GROUP BY**：SELECT 中未被聚合函数包裹的列（sno, sname）必须全部出现在 GROUP BY 中。`sname` 遗漏。
- **正确答案**：
  ```sql
  SELECT s.sno, s.sname, AVG(e.grade), SUM(c.credit)
  FROM Student s, Enrollment e, Course c, Courseclass cc
  WHERE s.sno = e.sno AND e.ccno = cc.ccno AND cc.cno = c.cno
  GROUP BY s.sno, s.sname           -- ✅ 所有非聚合列
  HAVING MIN(e.grade) >= 60         -- ✅ GROUP BY 之后
  ORDER BY AVG(e.grade) DESC;
  ```
- **回看**：写完 SQL 检查两件事 — ① GROUP BY 是否在 HAVING 之前？② SELECT 中的非聚合列是否全部进入 GROUP BY？

### Q25 · 多候选码下的部分依赖判定

- **来源**：2026 练习卷 · 第四大题第 3 题 — 范式判定
- **关系 R(cno, sdate, room, tno)**，F_min = {cno→sdate, (sdate,room)→cno, (sdate,tno)→room}
- **候选码**：(tno, cno) 和 (tno, sdate)
- **主属性**：tno, cno, sdate | **非主属性**：room（唯一一个）

  **部分依赖判定规则（有多个候选码时）**：
  > 对**每个**候选码，检查其**每个真子集**的闭包是否包含非主属性。只要有一个真子集能推出非主属性 → 违反 2NF。

  本例验证：
  ```
  非主属性 room。

  对 CK₁(tno, cno)，真子集 {tno} → {tno}⁺ = {tno} 不含 room ✓
                         {cno} → {cno}⁺ = {cno, sdate} 不含 room ✓

  对 CK₂(tno, sdate)，真子集 {tno} → {tno}⁺ = {tno} 不含 room ✓
                           {sdate} → {sdate}⁺ = {sdate} 不含 room ✓

  全部不包含 → room 不对任何候选码部分依赖 → 2NF ✓
  ```

- **回看**：多候选码时，**每个**候选码的**每个**真子集都要查，不能漏。

### Q26 · 多候选码下的传递依赖判定

- **来源**：同上
- **传递依赖三要素**：CK → Y（Y 不是超码）→ 非主属性 Z。三个环节缺一不可。

  本例验证：
  ```
  非主属性 room，FD 中只有 (sdate, tno) → room 直接推出 room。
  (sdate, tno) 本身是候选码 CK₂ → 非主属性直接由 CK 决定，不算传递。

  是否存在 CK → Y(非超码) → room 的间接链条？
  - CK₁(tno,cno) → cno→sdate 推得 sdate，sdate⁺={sdate} 不含 room → 链断了
  - CK₂(tno,sdate) → (sdate,tno)→room 直接得出 → 无中间环节

  结论：不存在完整传递链 → 3NF ✓
  ```

  **BCNF 判定（有多个候选码时）**：
  > 检查**每个**FD 的左部是否都是超码（闭包是否等于全部属性 {cno,sdate,room,tno}）。

  ```
  cno → sdate            cno⁺ = {cno,sdate} ≠ 全部 ❌
  (sdate, room) → cno    闭包 = {sdate,room,cno} ≠ 全部 ❌
  (sdate, tno) → room    闭包 = {sdate,tno,room,cno} = 全部 ✅

  有不满足的 → 最高 3NF
  ```

- **回看**：BCNF 不看主属性/非主属性，只看 FD 左部是否超码。即使左部全由主属性构成，闭包不等于全部就违反。

### Q27 · BCNF 分解算法

- **来源**：2026 练习卷 · 第四大题第 2 题第 (3) 问
- **F_min = {A→F, B→DE, CD→AB}**，3NF 分解：R1(A,F), R2(B,D,E), R3(A,B,C,D)
- **R3 的 FD**：CD→AB 和 B→D（B→DE 投影到 R3 去掉 E → B→D）
- **BCNF 检查**：`B→D` 中 B⁺={B,D} ≠ R3 全部 → 违反

  **拆分算法**（递归）：
  ```
  ① 找到违反 FD：X → Y（X 不是超码）
  ② 拆成 R_a = X∪Y  和  R_b = R − Y
  ③ 递归检查每个子关系
  ```

  本例用 `B→D` 拆分 R3(A,B,C,D)：
  ```
  R31 = (B,D)       FD: B→D    CK: B    ✅ BCNF
  R32 = (A,B,C)     CK: BC              ✅ BCNF
  ```

  **去重规则**：若子关系 head(R_a) ⊆ head(R_b)，则 R_a 可被 R_b 替代，删 R_a。
  ```
  head(R31) = {B,D} ⊆ head(R2) = {B,D,E} → R31 冗余 → 删
  ```

  最终 BCNF：**R1(A,F), R2(B,D,E), R3(A,B,C)**
  BF→C 等依赖跨关系丢失 ← BCNF 的代价。

- **回看**：① 找投影后的 FD ② 选一个违反的 FD 拆 ③ 检查子集去冗余 ④ 确认丢依赖是 BCNF 的正常代价

### Q28 · 极小函数依赖集三步法

- **来源**：2026 练习卷 · 第四大题第 1 题
- **原始 F = {A→E, B→ADE, DF→AC, ADF→B}**
- **正确答案**：{A→E, B→AD, DF→BC}

  **三步法**：
  ```
  Step 1 · 右部单属性化
    B→ADE   → B→A, B→D, B→E
    DF→AC   → DF→A, DF→C
    ADF→B   → ADF→B
    其余保持
  
  Step 2 · 去掉冗余 FD（逐个删，看剩余能否推出被删的）
    B→E：剩余推 B⁺={A,B,D,E} 含 E → 冗余，删
    ADF→B：DF→A 可得 A，剩余推得 B → 冗余，删
  
  Step 3 · 去掉左部冗余属性（逐属性试删，看剩余能否推出原 FD）
    DF→A：D 和 F 都不可去
    DF→C：D 和 F 都不可去
    DF→B：由 DF→A + A→E + E→... 不直接，答案直接合写 DF→BC
  ```
  > DF→BC 是 DF→C 与 DF→B（可经 DF→A 推导）的简写，考试接受。

- **回看**：Step 2 用闭包判断冗余；Step 3 逐属性试探。顺序不可乱——先去 FD 再去左部属性。
