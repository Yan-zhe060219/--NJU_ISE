## 一句话总结

链路层（Link Layer）负责在**物理相邻的节点之间**传输数据报——封装成帧（frame），用 CRC 检测差错，用 CSMA/CD 等 MAC 协议协调共享信道访问，用 MAC 地址和 ARP 实现局域网内的帧交付。它是五层协议栈的最底层，数据报离开主机或路由器之前，最后一道封装就在这里完成。

---

## 场景设定：一个帧的诞生与旅行

前三章我们在网络层和运输层——数据报怎么路由、TCP 怎么可靠传输。但这些都是"大脑"层面的决策。现在下沉到最底层：**数据报真正变成电信号或光信号之前，最后一步是什么？**

想象你是一台主机，浏览器刚请求了一个网页。运输层的 TCP 段封装完毕，网络层加了 IP 头部，现在这个数据报交到了你手上的**网络接口卡（NIC）**。NIC 要把它发给局域网内的下一跳——可能是网关路由器，也可能是同一交换机上的另一台主机。

但 NIC 面临几个问题：
1. 这个数据报在物理线路上传输时可能出错（电磁干扰、信号衰减）——**怎么让接收方发现？**
2. 你和其他主机共享同一根网线（或同一个 WiFi 频段）——**什么时候轮到你说话？**
3. 你知道目标 IP，但 NIC 只认 MAC 地址——**IP 怎么翻译成 MAC？**

这三个问题分别对应本章的三大核心：**差错检测 → 多路访问协议 → MAC 地址与 ARP**。让我们从帧的结构开始。

## 一、链路层是什么——协议栈的最底层

### 1.1 职责：物理相邻节点之间的传输

链路层的职责，课件有一句精当的定义：

> "link layer has responsibility of transferring datagram from one node to **physically adjacent node** over a link"

翻译：链路层负责将数据报从一个节点通过链路传输到**物理相邻**的节点。

和第 06 章的网络层对比一下，立刻清楚两者的分工：

| | 网络层（IP） | 链路层 |
|---|---|---|
| **范围** | 端到端，跨越多台路由器 | 单跳，物理相邻的两个节点之间 |
| **数据单元** | Datagram（数据报） | Frame（帧） |
| **寻址** | IP 地址（32 位，分层） | MAC 地址（48 位，扁平） |
| **可靠性** | Best-Effort（尽力而为，不保证） | 可选——有线链路通常不保证，无线链路需要 |

**类比**：你从南京寄快递到北京——网络层负责"南京→北京"的全程路线规划（走哪条高速、经过哪些中转站），链路层负责每一段具体路程——"南京到滁州这一段高速怎么走"。

### 1.2 帧 = 数据报 + 头部 + 尾部

链路层把网络层交下来的数据报封装成**帧（frame）**：

```
┌──────────┬──────────────────────┬──────────┐
│  Header  │   Datagram (payload) │  Trailer │
│ (头部)    │   (网络层数据报)       │ (尾部)   │
└──────────┴──────────────────────┴──────────┘
           ↑                                       ↑
    包含 MAC 地址、          包含差错检测码（如 CRC），
    链路层控制信息              用于接收端校验帧是否损坏
```

封装在发送端 NIC 完成，解封在接收端 NIC 完成。帧到了接收端 → 剥掉头尾 → 把数据报上交网络层。

### 1.3 链路层的实现位置：NIC

**链路层实现在每个主机和路由器的网络接口卡（NIC，Network Interface Card）上**——这是硬件、软件和固件的组合。你的笔记本电脑、手机、路由器的每个网口上都有一块 NIC，它负责：

- 发送端：把数据报封装成帧，加上差错检测比特，执行 MAC 协议决定何时发送
- 接收端：检查差错，提取数据报上交网络层，可能发送确认

大部分链路层功能在 NIC 硬件中实现（为了速度），少部分在操作系统驱动中实现（为了灵活性）。

### 1.4 链路层提供的六种服务

不是所有链路层协议都提供全部服务——不同链路按需选用：

| 服务 | 说明 | 有线以太网 | 无线 WiFi |
|------|------|:---:|:---:|
| **成帧与链路接入（Framing & Link Access）** | 封装数据报成帧；在共享介质中协调信道访问 | ✅ | ✅ |
| **相邻节点间可靠交付（Reliable Delivery）** | 确认 + 重传，保证帧无差错到达 | ❌ 很少用 | ✅ 需要 |
| **流控（Flow Control）** | 相邻发送和接收节点之间的节奏控制 | 可选 | 可选 |
| **差错检测（Error Detection）** | 接收端检测比特差错，通知重传或丢弃 | ✅ | ✅ |
| **差错纠正（Error Correction）** | 无需重传，直接识别并纠正比特差错 | ❌ | 可选 |
| **半双工/全双工** | 半双工：两端可发但不能同时发；全双工：可同时收发 | 全双工 | 半双工 |

**为什么有线以太网不保证可靠交付？** 光纤和双绞线的误码率极低（10⁻¹² 以下）。与其在每一跳都确认/重传增加延迟，不如把可靠性推到端到端——让 TCP 来处理丢包。但无线链路不同——信号穿墙衰减、多径干扰，误码率高得多，所以 802.11 WiFi 在链路层做确认和重传。

## 二、帧的"防伪标签"——差错检测

物理线路不是完美的。电磁干扰、信号衰减、串扰都会翻转比特。链路层不能纠正所有错误，但至少要能**发现**——否则一个损坏的 IP 数据报被路由器转发，浪费沿途所有带宽。

三种检测方法，从简单到强大：

### 2.1 奇偶校验（Parity Checking）——最朴素的做法

**单比特奇偶校验**：在数据比特末尾加一个奇偶位，使所有 1 的总数为偶数（偶校验）或奇数（奇校验）。

```
数据： 0110101（4 个 1，已经是偶数）
偶校验位：0 → 发送 0110101 0
如果传输中一个比特翻转 → 1 的总数变奇数 → 检出！

但翻转两个比特 → 1 的总数还是偶数 → 漏检。
```

能力：检测**奇数个**比特差错。偶数个差错会漏检。

**二维奇偶校验**：把数据排成矩阵，每行每列各设奇偶位。单比特差错时，错误行的奇偶位和错误列的奇偶位同时报警——交叉定位到具体哪个比特出错了，**可以纠正**。

```
行奇偶
D1: 1 0 1 1 | 1
D2: 0 1 0 1 | 0
D3: 1 1 0 0 | 0
列奇偶: 0 0 1 0 | ？
            ↑ 这个比特出错了（第 3 列和第 2 行同时报警）
```

### 2.2 因特网校验和（Internet Checksum）

在前面运输层（UDP 校验和）已经见过。发送端将数据视为 16 比特整数序列，计算**反码和（one's complement sum）**填入校验和字段；接收端重新计算并比较。

优点：计算极快，开销小。缺点：检测能力弱于 CRC，16 位只有 65536 种校验值，不同的错误模式可能产生相同校验和。

### 2.3 CRC（循环冗余校验）——实战标准

> "CRC: more powerful error-detection coding... can detect all burst errors less than r+1 bits"

CRC 是实践中使用最广泛的差错检测编码——Ethernet、802.11 WiFi、4G/5G 都用它。它的检测能力远超前两种方法。

**核心原理**：

1. 发送端和接收端约定一个 **r+1 位的生成多项式 G**（generator）
2. 发送端对数据 D 进行计算，得出 r 位 CRC 校验码 R，使得 `<D, R>` 这个整体二进制数能被 G 整除（模 2 运算，即 XOR 代替减法）
3. 接收端用同样的 G 去除收到的 `<D', R'>`——余数非零 → 帧出错，丢弃

**为什么用模 2（XOR）运算？** XOR 在数字电路中是一种极简单的逻辑门。CRC 可以被硬件以线速实时计算——以太网一帧 1500 字节，CRC 硬件在帧传输过程中同步计算，不需要等整帧收完。这就是为什么交换机可以在微秒级转发——CRC 校验不增加额外延迟。

**检测能力**：
- 能检测所有长度 < r+1 比特的**突发差错**（burst error）
- 大多数更长的突发差错也能检测（漏检概率 ≈ 1/2ʳ）

以 Ethernet 为例：CRC-32 使用 33 位生成多项式（r=32），漏检概率 ≈ 1/2³² ≈ 2.3×10⁻¹⁰——几乎不可能漏检。

## 三、谁先说话——多路访问协议

两个节点用一根专线相连（点对点链路）时，什么时候发帧不是问题——只有一个接收方。但当**多个节点共享同一根线或同一个频率**时，如果两个站点同时发送，信号就会重叠——**碰撞（collision）**。

多路访问协议（Multiple Access Protocol）解决的就是这个问题：**一群节点共享一个广播信道，怎么决定谁什么时候发？** 课件给出了精当的定义：

> "multiple access protocol: distributed algorithm that determines how nodes share channel, i.e., determine when node can transmit"

关键约束：这是一个**分布式算法**——没有中央调度员。节点之间协调通信也只能用这个共享信道本身（没有带外控制通道）。

### 3.1 理想协议的四条标准

给定速率 R 的广播信道，理想的 MAC 协议应该：
1. 只有一个节点要发 → 它能以满速率 R 发送
2. M 个节点要发 → 每个平均获得 R/M
3. **完全去中心化**：无专用协调节点，无时钟/时隙同步
4. **简单**

实践中没有协议完美满足全部四条——不同方案在不同场景下各有取舍。

### 3.2 第一类：信道划分（Channel Partitioning）——"各占一条车道"

思路：把信道资源静态切成小块，每个站点独占一块。

**TDMA（时分多址）**：时间切为等长时隙，每个站点每轮分得一个固定时隙。

```
轮次：  [时隙1: A] [时隙2: B] [时隙3: C] [时隙4: D] | [时隙1: A] ...
如果只有 A 在发，B/C/D 的时隙空着 → 浪费 3/4 带宽。
```

**FDMA（频分多址）**：频谱切成频带，每个站点分得一段。同样——空闲站点的频带白白浪费。

| | 优点 | 缺点 |
|---|---|---|
| TDMA / FDMA | 高负载时高效公平，无碰撞 | 低负载严重浪费——即使只有一个活跃站点也只能用 1/N 带宽 |

**类比**：一条四车道高速公路，每辆车被分配了固定车道。你前面没车也只能在自己的车道上——隔壁车道空着也不能用。

### 3.3 第二类：随机访问（Random Access）——"先听后说，撞了重来"

思路：有帧要发就直接发（或先听一下再发）。碰撞了就随机退避重试。低负载效率极高，高负载碰撞增多。

#### Slotted ALOHA（时隙 ALOHA）

最原始的随机访问协议：

- 时间分成等长时隙（一个时隙 = 一帧的传输时间）
- 有帧要发 → 在**下一时隙开头**发送
- 如果碰撞（整个时隙内任何其他节点也发了）→ 以概率 p 在后续每个时隙重传

**最大效率 = 1/e ≈ 37%**

> "At best: channel used for useful transmissions 37% of time!"

为什么只有 37%？因为即使所有节点完美按最优概率发送，给定时隙内**恰好一个节点发送**的概率 = N × p × (1-p)^(N-1)。N 很大时，这个概率的极限是 1/e。换句话说，Slotted ALOHA 约 37% 的时隙有用、37% 空闲、26% 碰撞浪费。

优点：单活跃节点可满速发送，高度去中心化，极简。缺点：需要时钟同步，碰撞浪费时隙。

#### CSMA（载波侦听多路访问）

ALOHA 不管信道状态直接发——太"鲁莽"了。CSMA 聪明一点：**先听再发**。

> "CSMA: listen before transmit: if channel sensed idle: transmit entire frame; if channel sensed busy: defer transmission"

发送前先侦听载波（carrier sense）——信道空闲则发，信道忙则等。这大幅减少碰撞的概率。

**但碰撞仍然会发生**——因为信号有传播延迟（propagation delay）。信号从 A 传到 B 需要时间，在这个**传播延迟窗口**内，B 侦听到的仍然是"空闲"：

```
时间线（A 和 B 相距 200m，电信号传播 ~1μs）：

t=0     A 侦听 → 空闲 → A 开始发送
t=0.5μs B 侦听 → 空闲（A 的信号还没到！）→ B 也开始发送
t=1μs   B 的信号到达 A，两帧在信道上重叠 → 碰撞！
```

这就是 CSMA 无法根除碰撞的根本原因：**侦听只能告诉你"过去"的信道状态，不能预测"未来"**。传播延迟越大（距离越远）、传输速率越高（同样时间发更多比特），碰撞风险越大。CSMA/CD 比纯 CSMA 多了一步关键的补救——**边发边听，撞了立刻停**。

#### CSMA/CD（带碰撞检测的 CSMA）——以太网的灵魂

CSMA 的进阶版：不仅先听后发，还要**边发边听**。一旦检测到碰撞，立即**中止传输**——不浪费信道把整个碰撞的帧发完。

CSMA/CD 算法分三步：

```
┌──────────────────────────────────────────────────┐
│            CSMA/CD 算法                           │
│                                                   │
│  1. 载波侦听 (Carrier Sense)                      │
│     ├─ 信道空闲 → 等 IFG（96 bit time）→ 开始发送   │
│     └─ 信道忙   → 持续侦听，直到空闲 → 开始发送      │
│                                                   │
│  2. 碰撞检测 (Collision Detection)                 │
│     ├─ 发送同时监测线路电压                          │
│     ├─ 电压异常 → 碰撞！立即中止                     │
│     ├─ 发送 48-bit Jam Signal 强化碰撞信号           │
│     └─ 电压正常 → 帧发完，成功                       │
│                                                   │
│  3. 二进制指数退避 (Binary Exponential Backoff)     │
│     ├─ m = min(碰撞次数, 10)                       │
│     ├─ 从 {0, 1, ..., 2^m - 1} 随机选 K            │
│     ├─ 等待 K × 512 比特时间后回步骤 1               │
│     └─ 16 次碰撞 → 放弃，向上层报错                  │
└──────────────────────────────────────────────────┘
```

**碰撞检测如何做到？** 在有线（双绞线/同轴电缆）上，NIC 发送时同时监测线路电压。正常情况线路上是自己发出的信号；碰撞时另一站点的信号叠加过来 → 电压超出正常范围 → NIC 判断为碰撞。检测到碰撞后立即**中止发送有用数据**，并发出 **Jam Signal**（32~48 比特的强化干扰信号）——确保所有站点都明确感知到碰撞（有些站点可能只检测到微弱异常，Jam Signal 让碰撞信号"足够大声"）。

**二进制指数退避（Binary Exponential Backoff）**——CSMA/CD 最精妙的设计：

```
碰撞次数 m    窗口大小 2^m      K 的取值范围        等待时间范围
─────────────────────────────────────────────────────
   0         2^0 = 1         {0}                 0（首次发送，不等）
   1         2^1 = 2         {0, 1}              0 ~ 512 bit time
   2         2^2 = 4         {0, 1, 2, 3}       0 ~ 1536 bit time
   3         2^3 = 8         {0, ..., 7}         0 ~ 3584 bit time
  ...
  10         2^10 = 1024     {0, ..., 1023}      0 ~ ~524 ms (10Mbps)
 ≥10         1024（上限）     {0, ..., 1023}      不再增长
第 16 次     —               放弃，向上层报错
```

**为什么是指数？** 碰撞少 → 可能只是偶发冲突 → 窗口小 → 快速重试（低延迟）。碰撞多 → 网络负载高/很多站在争用 → 窗口指数扩大 → 各站的等待时间充分分散 → 降低再次碰撞的概率。**用随机化打破同步**：如果不用随机退避，所有碰撞站会在同一时刻重试 → 必然再次碰撞 → 死锁。随机 K 让它们自然错开。

**为什么上限是 10（窗口不再增大）和 16（放弃）？** m=10 时窗口已达 1024，再增大延迟不可接受——网络层 TCP 会超时重传，没必要在链路层无限重试。m=16 时已重试 16 次，网络大概率严重拥塞或故障，放弃并上报——让上层协议（TCP）处理。

**为什么是 512 比特时间？** 512 比特 = 64 字节 = 传统以太网的最小帧长。这个值正好等于传统以太网中**冲突窗口**（信号在最大直径网络中往返传播的时间 + Jam Signal 时间）。换句话说，等待 K×512 比特时间，实际上是在等待"K 个最小帧的传输时间"。单位时间的选择让退避和物理约束对齐。

**CSMA/CD 的效率公式**：

$$\text{效率} = \frac{1}{1 + 5 \cdot t_{prop} / t_{trans}}$$

- $t_{prop}$：信号在网络最远两站间的传播延迟
- $t_{trans}$：帧的传输时间（= 帧长 / 带宽）

直觉：帧越长（$t_{trans}$ 大）→ 分母趋近 1 → 效率趋近 100%（碰撞开销相对整个帧的传输时间可忽略）。距离越远（$t_{prop}$ 大）→ 效率下降（碰撞窗口更大）。

**最小帧长（64 字节）的由来**：CSMA/CD 有一个致命场景——帧太短，发完了才检测到碰撞 → 发送端以为成功了，实际上帧已被撞坏，且不会重传。最小帧长的约束是：**帧的传输时间必须 ≥ 往返传播时间**，这样即使最坏情况（信号刚到达远端时远端恰好开始发送），发送端在发完之前一定能检测到碰撞。

$$\text{最小帧长} = \text{带宽} \times 2 \times t_{prop}$$

传统 10 Mbps 以太网中最大往返延迟约 51.2 μs，所以最小帧长 = 10 Mbps × 51.2 μs = 512 比特 = 64 字节。不足 64 字节的帧需填充（padding）。这也是为什么千兆以太网必须用全双工交换机而非半双工 CSMA/CD——速率太高，即使最小帧长的传输时间也太短，碰撞检测窗口不够。

**与 Slotted ALOHA 的本质区别**：CSMA/CD 的效率不是固定值，而是关于 $t_{prop}/t_{trans}$ 的函数。Slotted ALOHA 固定 37% 是因为它不侦听——在时隙开头盲发，碰撞代价是整个时隙。CSMA/CD 通过"先听"避免大量碰撞，通过"边发边听"让发生的碰撞只浪费从开始发送到检测到碰撞这段极短时间——碰撞的代价被压到最低。

| | Slotted ALOHA | CSMA/CD |
|---|---|---|
| **侦听** | 不侦听，时隙到就发 | 先听后发 + 边发边听 |
| **碰撞检测** | 不检测 | 实时电压监测 |
| **碰撞代价** | 整个时隙浪费 | 仅浪费到检测出碰撞为止（极短） |
| **退避** | 固定概率 p | 二进制指数退避（自适应） |
| **效率** | 固定 1/e ≈ 37% | 取决于 t_prop/t_trans，远高于 37% |
| **同步要求** | 需要全局时钟同步时隙 | 不需要 |
| **适用** | 历史/教学 | 传统半双工有线以太网 |

### 3.4 第三类：轮流（Taking Turns）——"传令牌，轮到谁谁说话"

信道划分低负载浪费，随机访问高负载碰撞。能不能结合两者优点？

**轮询（Polling）**：集中控制器轮流"邀请"节点发送。Bluetooth 用这个。缺点：轮询开销、单点故障（控制器挂了全完）。

**令牌传递（Token Passing）**：一个特殊帧（令牌）在节点间按顺序传递。持有令牌才能发送，发完或时间用完传给下一个。优点：高负载高效公平，低负载无碰撞。缺点：令牌丢了要恢复（复杂）、单点故障。

### 3.5 DOCSIS（电缆接入）——三种协议的混合体

有线电视网络（DOCSIS 标准）是一个现实中的混合案例：
- **下行**（头端 → 用户）：广播，用 FDM 划分频道
- **上行**（用户 → 头端）：时隙分两类——一部分时隙按需分配（类似 TDMA），一部分时隙各用户竞争访问（类似 Slotted ALOHA + 二进制退避）

这就是工程实践：**不教条，按需组合。**

## 四、帧的"收件人"——MAC 地址与 ARP

解决了"什么时候发"的问题，下一个问题是**发给谁**。网络层有 IP 地址（32 位），但链路层的帧必须填 MAC 地址（48 位）——因为 NIC 硬件只认 MAC 地址。

### 4.1 MAC 地址 vs IP 地址：身份证号 vs 邮政地址

课件有一个极为精当的类比：

> "MAC address: like Social Security Number; IP address: like postal address"

| | MAC 地址 | IP 地址 |
|---|---|---|
| **位数** | 48 位（如 `1A-2F-BB-76-09-AD`） | 32 位（如 `128.119.40.136`） |
| **结构** | **扁平（flat）**——无层次 | **分层（hierarchical）**——网络号 + 主机号 |
| **分配** | IEEE 统一管理，制造商购买地址块，烧录在 NIC ROM | ISP 按子网分配，换子网就换 IP |
| **可移植性** | **可移植**——NIC 从一个 LAN 搬到另一个 LAN，MAC 不变 | 不可移植——换子网必定换 IP |
| **作用范围** | **同一子网内**的逐跳转发 | **全网范围**的端到端路由 |

**类比理解可移植性**：
- MAC 地址像你的身份证号——出生时分配，搬到哪个城市都不变
- IP 地址像你的收件地址——每次搬家都变。"上海市徐汇区…"只在上海市有效，搬到北京就换了

这个设计让链路层和网络层的寻址**正交**——换子网不需要换网卡，换网卡不需要改 IP 配置。

### 4.2 ARP：IP → MAC 的翻译官

> ARP（Address Resolution Protocol, 地址解析协议）解决的问题：**知道一个接口的 IP 地址，如何确定它的 MAC 地址？**

每台主机和路由器维护一张 **ARP 表**，存储 `<IP address; MAC address; TTL>` 映射。TTL 通常 20 分钟——过期删除，下次访问重新解析。

**同子网内的 ARP 过程**：

```
主机 A (192.168.1.1) 想发包给 主机 B (192.168.1.2)
A 的 ARP 表里没有 B 的 MAC 地址

① A 广播 ARP 查询报文：
   目标 MAC = FF-FF-FF-FF-FF-FF（广播地址，LAN 上所有人都会收到）
   内容："谁是 192.168.1.2？请告诉 192.168.1.1"

② LAN 上所有节点收到，B 认出自己的 IP → 单播 ARP 响应给 A：
   "我是 192.168.1.2，我的 MAC 是 1A-2F-BB-76-09-AD"

③ A 收到 → 存入 ARP 表 → 封装帧 → 发送
```

**为什么用广播？** A 不知道 B 在哪——B 可能接在同一个交换机的任何一个端口。广播是"喊一嗓子所有人都听到"——谁 IP 对上了谁回应。这是 LAN 的基本范式。

### 4.3 跨子网路由：IP 不变，MAC 逐跳变

这是链路层最容易混淆的知识点。假设主机 A 在子网 1，想发数据报到子网 2 的主机 B，中间经过路由器 R：

```
子网 1 (192.168.1.0/24)          子网 2 (192.168.2.0/24)
┌──────┐     ┌──────────┐     ┌──────┐
│  A   │ ←→  │ Router R │ ←→  │  B   │
│.1.1  │     │ .1.254   │     │.2.1  │
│MAC_A │     │ .2.254   │     │MAC_B │
└──────┘     │ MAC_R    │     └──────┘
             └──────────┘
```

**第一跳（A → R）**：
- IP 数据报：源 = A 的 IP（`192.168.1.1`），目的 = **B 的 IP**（`192.168.2.1`）← IP 地址端到端不变
- MAC 帧：源 = MAC_A，目的 = **MAC_R**（路由器的 MAC！不是 B 的 MAC！）

**第二跳（R → B）**：
- IP 数据报：源 = A 的 IP，目的 = B 的 IP（**完全不变**）
- MAC 帧：源 = MAC_R，目的 = MAC_B

**核心结论**：IP 数据报穿过整个互联网，源/目的 IP 始终不变；但承载它的帧在每一跳都要换 MAC 地址——因为 MAC 只在一个 LAN 内有效。

**类比**：你从上海寄一封信到北京——信封上的收件人和寄件人全程不变（IP）。但运输过程中——上海邮车上一段写"上海分拣中心→南京分拣中心"，南京写"南京→济南"，济南写"济南→北京"——每一段的"搬运标签"在变（MAC）。

## 五、回顾：一个帧从 NIC 到 NIC 的完整旅程

以太网 LAN 内，主机 A 第一次给主机 B 发数据报：

```
⏱ t=0: 网络层数据报到达 NIC
  ① NIC 查 ARP 表 → B 的 MAC 不在表中
  ② NIC 广播 ARP 查询 → B 单播 ARP 响应 → MAC 存入 ARP 表
  
⏱ t=1ms: 开始封装帧
  ① 帧头部填写 MAC_A（源）、MAC_B（目的）
  ② 数据区装入 IP 数据报
  ③ 尾部：对 (头部+数据) 计算 CRC-32 → 填入 FCS 字段

⏱ t=1.1ms: CSMA/CD — 决定何时发送
  ① 侦听载波 → 信道空闲
  ② 等待帧间间隔（IFG, 96 bit time）→ 开始发送
  ③ 边发边听 → 无碰撞 → 继续发送整个帧

⏱ t=1.2ms: 帧通过网线到达交换机
  ① 交换机收到前导码 → 同步时钟
  ② 收到完整帧 → CRC 校验 → 通过！
  ③ 查 MAC 表 → B 在端口 3 → 从端口 3 转发
  （交换机内部可能缓冲排队、可能同时有多个帧要转发——详见 11 号笔记）

⏱ t=1.3ms: 帧到达 B 的 NIC
  ① NIC 检查帧的目的 MAC → 是自己的 MAC → 接收
  ② CRC 校验 → 通过！
  ③ 剥掉帧头帧尾 → 提取 IP 数据报 → 上交网络层
```

整个过程不到 2 毫秒。中间经历了 ARP 解析、CSMA/CD 竞争、CRC 校验——链路层三大机制全部登场。**下一章（11 号笔记）**将进一步深入：帧到了交换机之后——交换机怎么学习 MAC 表？VLAN 怎么隔离广播域？数据中心怎么用 MPLS 加速转发？

## 难点突破

### 难点 1：CRC 多项式除法为什么用模 2 运算？

传统二进制除法有借位——`10 - 01 = 01`，借位使硬件实现复杂。模 2 除法用 **XOR（异或）** 代替减法——`10 XOR 01 = 11`，没有借位，硬件极简。

可以把模 2 除法理解成"对齐被除数最高位的 1，用除数的每一位和它对位 XOR"。不用管大小的概念，只看有没有 1。这使 CRC 可以在硬件中**以线速实时计算**——比特流经过 CRC 电路，一边移位一边 XOR，帧发完 CRC 也算完了。以太网 1500 字节的帧，CRC 计算不增加额外延迟。

### 难点 2：为什么 CSMA/CD 用在有线以太网，而 WiFi 用 CSMA/CA？

**碰撞检测（CD）需要发送方同时能听到信道**——如果发送时听到的电压和自己发出的不匹配，就是碰撞。这在有线（双绞线/同轴电缆）上容易：电压叠加后变化明显，比较器就能检测。

但在无线网络中，发送时的信号强度（比如 100mW）远远大于从几十米外传来的微弱信号（可能只有几 μW）——你自己的发射功率完全盖过了远端信号。你能听到自己的声音，听不到别人的。这就是**隐蔽站问题（Hidden Terminal Problem）**。

所以 WiFi（802.11）用**碰撞避免（CA, Collision Avoidance）**：
- 发送前用 RTS/CTS 短帧预约信道
- 发送后等 ACK，没收到 ACK 就重传（二进制指数退避）
- 核心区别：WiFi **无法检测碰撞**，只能通过"收不到 ACK"**推断**碰撞发生了

### 难点 3：Slotted ALOHA 的 37% 效率是怎么来的？

理解推导的关键：**一个时隙成功 = 恰好一个节点发送**。

N 个活跃节点，每个节点以概率 p 在一个时隙发送不碰撞。一个给定节点发送成功 = 它发送（概率 p）且其余 N-1 个都不发送（概率 (1-p)^(N-1)）。N 个节点各贡献一份成功概率，总效率 = N × p × (1-p)^(N-1)。

当 N → ∞ 且每个节点选择最优的 p = 1/N 时，这个表达式的极限 = 1/e ≈ 0.37。也就是说，**无论怎么优化，Slotted ALOHA 最多只有 37% 的时隙在做有效传输**——剩下的要么碰撞要么空闲。

CSMA/CD 能更高是因为**侦听避免了大量不必要的碰撞**——只在传播延迟窗口内有碰撞风险。

### 难点 4：二进制指数退避为什么设计成这样？——四个"为什么"

CSMA/CD 的退避机制有几个精妙的设计决策，每个背后都有工程理由：

**① 为什么随机而不固定？** 如果碰撞后所有站等相同时间 → 同时重试 → 再次碰撞 → 死锁。随机化打破同步，让各站自然分散——K 最小的先重试成功，K 大的还在等，后续不会干扰。

**② 为什么指数增长而不是线性？** 线性增长（如第 m 次等 m×T）在重载下不够快——即使 10 个站碰撞，线性退避需要很多轮才能把等待时间充分拉开。指数增长在每轮碰撞后将窗口翻倍 → 窗口快速膨胀 → 各站等待时间迅速分散 → 更快收敛到无碰撞状态。代价是单次碰撞后的平均等待时间也指数增长——但这是公平的：碰撞多说明负载高，理应退得更多。

**③ 为什么是 512 比特时间？** 512 比特 = 传统以太网最小帧长 64 字节 = 冲突窗口（最大往返延迟 + Jam Signal）。等待单位等于冲突窗口，意味着退避时间对齐到物理约束——不会因为等得太短而白等（碰撞窗口还没过去），也不会等得太长浪费空闲信道。

**④ 为什么 m 在 10 处封顶、16 次放弃？** m=10 时窗口 = 1024，等待上限约 524 ms（10 Mbps 下）。再大就超过 TCP 的典型超时重传时间（RTO）——链路层无限重试没意义，让 TCP 来处理。16 次碰撞 ≈ 网络极严重拥塞或故障，再试也是浪费——上报错误比无限等更好。

**核心原则**：二进制指数退避本质上是一个**无中心协调的分布式拥塞控制**——每个站点仅根据本地信息（自己碰撞了几次）独立调整行为，但全局效果是自动均分信道。这和 TCP 拥塞控制的 AIMD 共享同一个设计哲学：**用自适应退避来响应竞争**。

### 难点 5：ARP 为什么用广播而不是问交换机？

初学者的直觉："交换机知道每个端口连着谁，为什么不直接问交换机？"

交换机确实维护着 MAC 地址表（详见 11 号笔记），但**交换机不维护 IP↔MAC 的映射**——交换机只认 MAC 地址，不认 IP。IP 是第三层的概念，交换机工作在第 2 层，根本看不见 IP。

所以 ARP 只能自己动手：广播到整个 LAN，"谁 IP 是 XXX？"——因为发送方确实不知道 MAC 地址，也不知道目标在哪个交换机端口。广播是最简单、最可靠的做法。

## 关联

**与第 3 章（运输层可靠传输）的关联**：
- 链路层只保证单跳的帧不出差错（CRC），端到端的丢包（路由器缓冲区溢出等）由 TCP 处理
- 这就是分层设计：每一层解决自己范围内的问题。链路层不承诺"帧一定到达"，TCP 不假设"下层一定可靠"

**与第 6 章（网络层路由器与 IP）的关联**：
- 路由器收到帧 → 剥掉帧头帧尾 → 取出 IP 数据报 → 查转发表 → 重新封装成帧发出
- MAC 地址和 IP 地址的分工：IP 负责端到端寻址，MAC 负责逐跳转发——这是理解 ARP 和跨子网路由的基础

**与第 9 章（BGP 与 SDN）和后续第 11 章（以太网交换）的关联**：
- 第 9 章解决的"AS 之间怎么选路"和本章 ARP 的"子网内怎么找 MAC"——分别是全网最宏观和最微观的寻址问题
- 第 11 章展开交换机的内部工作原理（MAC 表学习、VLAN、生成树协议），是本章"帧到了交换机之后"的延续

## 关键原句

> "link layer has responsibility of transferring datagram from one node to physically adjacent node over a link"
> **翻译：** 链路层的职责是将数据报从一个节点通过链路传输到物理相邻的节点。

> "CRC: more powerful error-detection coding... can detect all burst errors less than r+1 bits"
> **翻译：** CRC 是更强大的差错检测编码……能检测所有长度小于 r+1 比特的突发差错。

> "multiple access protocol: distributed algorithm that determines how nodes share channel, i.e., determine when node can transmit"
> **翻译：** 多路访问协议是一个分布式算法，决定节点如何共享信道——即决定节点什么时候可以发送。

> "CSMA: listen before transmit: if channel sensed idle: transmit entire frame; if channel sensed busy: defer transmission"
> **翻译：** CSMA：发送前先侦听——若信道空闲则发送整帧；若信道忙则推迟发送。

> "At best: channel used for useful transmissions 37% of time!" (Slotted ALOHA)
> **翻译：** 充其量，信道只有 37% 的时间用于有效传输！

> "MAC address: like Social Security Number; IP address: like postal address"
> **翻译：** MAC 地址像身份证号（跟人走），IP 地址像邮政地址（跟位置走）。

> "MAC flat address: portability — can move interface from one LAN to another"
> **翻译：** MAC 扁平地址具有可移植性——接口可以从一个 LAN 搬到另一个 LAN 而地址不变。

## 记忆卡片

**Q: 链路层的主要职责是什么？它的数据单元叫什么？和网络层的分工如何？**
**A:** 链路层负责在物理相邻的节点之间传输数据报（transferring datagram from one node to physically adjacent node over a link）。数据单元叫帧（frame），封装网络层数据报。实现在 NIC 上。网络层管端到端路由，链路层管逐跳传输——类比：网络层规划南京到北京全程，链路层负责南京到滁州这一段高速。

**Q: CRC 相比校验和有什么优势？为什么用模 2 运算？**
**A:** CRC 能检测所有长度 < r+1 比特的突发差错，漏检概率 ≈ 1/2ʳ（CRC-32 几乎不可能漏检），广泛用于 Ethernet 和 WiFi。模 2 运算（XOR 代替减法）使硬件能以线速实时计算——帧传输完 CRC 也算完，不增加延迟。

**Q: 三类 MAC 协议分别是什么？各有什么优缺点？**
**A:** (1) **信道划分（TDMA/FDMA）**：高负载高效公平，低负载浪费带宽；(2) **随机访问（ALOHA/CSMA/CD）**：低负载高效，高负载碰撞增多，Slotted ALOHA 最大效率仅 37%，CSMA/CD 通过先听后发 + 边发边听 + 指数退避大幅提高效率；(3) **轮流（Polling/Token Passing）**：兼顾高低负载，但有单点故障和延迟问题。DOCSIS（电缆接入）是三类的混合体。

**Q: MAC 地址和 IP 地址有什么区别？为什么要两个地址？**
**A:** MAC 是 48 位扁平地址（flat），烧录在 NIC ROM，搬到哪都不变——像身份证号，用于同一子网内的逐跳转发。IP 是 32 位分层地址，随子网变化——像邮政地址，用于全网端到端路由。两者分工正交：IP 负责"寄到哪"，MAC 负责"这一段交给谁"。换子网不换网卡，换网卡不改 IP——这就是分层的灵活性。

**Q: ARP 协议做了什么？跨子网路由时 MAC 地址如何变化？**
**A:** ARP 通过广播查询（dest MAC = FF-FF-FF-FF-FF-FF）+ 单播响应将 IP 映射为 MAC，结果缓存到 ARP 表（TTL ~20 分钟）。跨子网路由时，IP 数据报的源/目的 IP 端到端不变，但帧的 MAC dest 每跳改变——第一跳 dest MAC = 路由器 MAC，最后一跳 dest MAC = 目的主机 MAC。

**Q: CSMA/CD 算法的完整三步是什么？二进制指数退避的具体参数有哪些？**
**A:** CSMA/CD = 载波侦听多路访问/碰撞检测。三步：(1) **先听后发（Carrier Sense）**：侦听信道，空闲则等 IFG（96 bit time）后发送，忙则持续侦听。(2) **边发边听（Collision Detection）**：发送时持续监测线路电压，检测到碰撞 → 立即中止，发送 48-bit Jam Signal 强化碰撞信号。(3) **二进制指数退避（Binary Exponential Backoff）**：第 m 次碰撞（m ≤ 10），从 {0, 1, …, 2^m-1} 随机选 K，等 K×512 比特时间后重试；m > 10 窗口封顶 1024 不再增大；16 次碰撞后放弃上报。参数记忆：512 bit time = 最小帧长 64 字节 = 冲突窗口；效率公式 = 1/(1 + 5·t_prop/t_trans)。

**Q: 为什么 WiFi 用 CSMA/CA 而不用 CSMA/CD？**
**A:** 碰撞检测需要边发边听，但无线网络中自身发射功率（100mW）远大于远端信号（几 μW）——发送时听不到别人的碰撞。这是隐蔽站问题（Hidden Terminal Problem）。WiFi 用碰撞避免（CA）：RTS/CTS 预约信道 + 等 ACK，没收到 ACK 就推断碰撞并重传。

### 简答题预测 + 标准答案

**Q1: 简述链路层的主要职责和提供的六种服务。哪些服务在以太网中不常用，为什么？**（6-8 分）

**标准答案**：

链路层负责在物理相邻的节点之间传输数据报，数据单元为帧（frame），实现在 NIC 上。

六种服务：(1) 成帧与链路接入；(2) 相邻节点间可靠交付；(3) 流控；(4) 差错检测；(5) 差错纠正；(6) 半双工/全双工。

以太网不常用**可靠交付**和**差错纠正**——因为光纤/双绞线误码率极低（10⁻¹² 以下），与其逐跳确认增加延迟，不如把可靠性推到端到端让 TCP 处理。无线 WiFi 因误码率高需要这两项服务。

---

**Q2: 对比三类多路访问协议（信道划分、随机访问、轮流），说明各自代表协议和适用场景。**（8-10 分）

**标准答案**：

| 类别 | 代表协议 | 机制 | 优点 | 缺点 |
|------|---------|------|------|------|
| **信道划分** | TDMA, FDMA | 静态分配时隙/频带 | 高负载高效公平，无碰撞 | 低负载严重浪费带宽 |
| **随机访问** | Slotted ALOHA, CSMA/CD | 发送前侦听，碰撞后随机退避 | 低负载高效，去中心化 | 高负载碰撞增多；Slotted ALOHA 最高仅 37% |
| **轮流** | Polling, Token Passing | 集中轮询或令牌传递 | 高低负载均高效公平 | 轮询开销、单点故障、令牌恢复复杂 |

DOCSIS（电缆接入）是混合体：下行 FDM 广播，上行 TDM + 竞争随机访问 + 二进制退避。

---

**Q3: 解释 CSMA/CD 的完整工作流程，包括二进制指数退避机制。**（8-10 分）

**标准答案**：

CSMA/CD 三步：
1. **先听后发（Carrier Sense）**：发送前侦听信道。空闲 → 等待帧间间隔（IFG, 96 bit time）→ 发送整帧。忙 → 持续侦听，直到空闲。
2. **边发边听（Collision Detection）**：发送过程中持续监测线路电压。若检测到碰撞 → 立即停止，发送 jam signal 强化碰撞信号。
3. **随机退避重试（Binary Exponential Backoff）**：第 m 次碰撞（m ≤ 10），从 {0, 1, …, 2^m-1} 中随机选 K，等待 K×512 比特时间后重试。碰撞越多退越久，自适应减少再次碰撞概率。m > 10 时窗口不再增大；m = 16 次碰撞后放弃，上报错误。

**关键**：CSMA/CD 的效率取决于传播延迟与帧传输时间的比值——帧越长或距离越短，效率越高。

---

**Q4: 画图解释跨子网路由中 IP 地址和 MAC 地址的变化规律。**（6-8 分）

**标准答案**：

主机 A（子网 1）经路由器 R 发送到主机 B（子网 2）：

第一跳（A→R）：帧 dest MAC = R 的 MAC（不是 B 的 MAC！）——因为 A 在子网 1 只能直接和 R 通信。
第二跳（R→B）：帧 dest MAC = B 的 MAC。

**核心规律**：IP 数据报的源/目的 IP 端到端不变；帧的 MAC dest 每跳改变（逐跳指向下一跳的 MAC 地址）。

**为什么**：MAC 地址只在同一 LAN 内有效——它是"这一段的收件人"。IP 地址全网唯一——是"最终收件人"。

---

**Q5: 简述 ARP 的工作过程。为什么用广播而不是问交换机？**（6-8 分）

**标准答案**：

ARP 工作过程：
1. 发送方查 ARP 表 → 目标 IP 不在表中
2. 发送方广播 ARP 查询（dest MAC = FF-FF-FF-FF-FF-FF）："谁是目标 IP？请告诉我你的 MAC"
3. 目标主机识别出自己的 IP → 单播 ARP 响应，告知 MAC 地址
4. 发送方存入 ARP 表（TTL ~20 分钟），用此 MAC 封装帧

**为什么不用交换机**：交换机工作在链路层（第 2 层），只看 MAC 地址不认 IP。ARP 需要 IP→MAC 的映射，交换机提供不了——必须自己广播查询。

---

**Q6: Slotted ALOHA 的最大效率为什么是 1/e ≈ 37%？**（6-8 分）

**标准答案**：

效率 = 一个时隙内恰好一个节点发送的概率。N 个节点各以最优化概率 p = 1/N 发送，总效率 = N × (1/N) × (1-1/N)^(N-1)。当 N → ∞ 时，极限 = 1/e ≈ 37%。

含义：最优情况下，仅 37% 时隙有效传输，37% 空闲，26% 碰撞浪费。CSMA/CD 通过**先听后发**避免了大量不必要的碰撞，效率远超 37%。
