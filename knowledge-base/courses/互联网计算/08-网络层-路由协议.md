## 一句话总结

路由协议的本质是在图上找最短路径。两种哲学：**链路状态（Link State, LS）**——每个路由器拥有全网地图，用 Dijkstra 集中式计算，O(n²) 复杂度但鲁棒；**距离向量（Distance Vector, DV）**——每个路由器只知道邻居的"报价"，用 Bellman-Ford 方程分布式迭代，好消息传得快但坏消息会**计数到无穷**。因特网用**自治系统（AS）**两层路由解决规模问题：AS 内部跑 OSPF（链路状态 + 层次化区域），AS 之间跑 BGP（下一章）。

## 场景设定：路怎么走，谁说了算？

第 06 章我们钻进一台路由器内部，看到它怎么根据转发表把分组扔到正确的出口。第 07 章讲了 IP 地址从哪来。但中间缺了一个关键问题：

**转发表里的条目是谁填进去的？**

假设全网有 1000 台路由器。每台路由器的转发表需要告诉它："去目的网络 X，下一跳是路由器 Y"。这 1000 张转发表不能手工填——拓扑随时在变（链路断了、新路由器上线、流量拥塞），必须由**路由协议自动计算**。

这就是**控制平面（Control Plane）**的职责。与之对照：**数据平面（Data Plane）**只管"来了一个分组，查表转发"（第 06 章做的事）。控制平面决定"表里填什么"，数据平面执行"按表转发"。

```
控制平面（Control Plane）：决定路径 → 计算转发表
数据平面（Data Plane）：    执行转发 → 使用转发表
```

控制平面的实现又有两种架构：

| 架构 | 做法 | 例子 |
|------|------|------|
| **Per-router control**（传统） | 每台路由器自己跑路由算法，相互交换路由消息 | 本章讲的 LS 和 DV |
| **SDN control**（软件定义） | 远程控制器统一计算，下发流表给路由器 | 第 07 章的 OpenFlow、第 09 章展开 |

本章聚焦传统 per-router 控制平面——路由协议如何让一群彼此不完全了解全网的路由器，协同算出正确的最短路径。

## 1. 路由问题的图抽象

### 1.1 把网络画成一张图

路由问题天然是图论问题。把网络抽象为图 `G = (N, E)`：

- **N（节点）**：路由器
- **E（边）**：路由器之间的物理链路
- **边的代价 c(a,b)**：由网络管理员定义。可以是恒定 1（跳数），也可以基于带宽（带宽越大代价越小）、延迟、拥塞程度

```
例图（本章所有算法都基于这张图）：

        5
    v ----- w
  3 |       | 5
    |   2   |
    u ----- z
    |       |
  2 |   1   | 2
    x ----- y
        1

N = { u, v, w, x, y, z }
E = { (u,v):2, (u,x):1, (v,w):3, (v,x):2, (w,z):5, (w,y):1, (x,y):1, (y,z):2 }
```

注意：`c(u,x) = 1` 而 `c(u,v) = 2`，意味着从 u 直连 x 比直连 v "更近"——代价是管理员定义的，不一定等于物理距离。

### 1.2 路由算法的分类维度

路由算法可以从两个正交维度分类：

**维度一：全局信息 vs 分布式信息**

| 类型 | 知识范围 | 算法 |
|------|---------|------|
| **全局（Global）** | 所有路由器拥有完整拓扑 + 所有链路代价 | **链路状态（Link State, LS）** |
| **分布式（Decentralized）** | 每台路由器只知道自己到邻居的代价，通过迭代交换信息逐步了解全网 | **距离向量（Distance Vector, DV）** |

课件原话："global: all routers have complete topology, link cost info" vs "decentralized: iterative process of computation, exchange of info with neighbors — routers initially only know link costs to attached neighbors."

**维度二：静态 vs 动态**

| 类型 | 变化速度 | 适应场景 |
|------|---------|---------|
| **静态（Static）** | 人工配置，变化缓慢 | 小型、拓扑固定的网络 |
| **动态（Dynamic）** | 周期性更新，或响应链路代价变化 | 互联网——拓扑随时在变 |

## 2. 链路状态路由 — Dijkstra 算法

### 2.1 核心思想

**每个路由器都有全网地图。** 通过**链路状态广播（Link State Broadcast）**，每台路由器把自己的邻居信息和链路代价洪泛给全网所有其他路由器。最终每台路由器拥有完全相同的拓扑数据库，然后**各自独立**跑 Dijkstra 计算以自己为根的最短路径树。

> 关键：LS 中每个节点独立计算，不依赖别人的计算结果。这是它鲁棒性的根源。

### 2.2 Dijkstra 算法符号定义

| 符号 | 含义 |
|------|------|
| `c(x,y)` | 从 x 到 y 的直接链路代价；若不是邻居则为 ∞ |
| `D(v)` | **当前估计的**从源到 v 的最短路径代价（迭代中不断更新） |
| `p(v)` | 从源到 v 的路径上，v 的**前驱节点**（用于回溯完整路径） |
| `N'` | 已确认最短路径的节点集合（"永久的"、不会再被更新） |

### 2.3 算法步骤

```
1  Initialization:
2    N' = {u}                      // 只有源节点是"确定的"
3    for all nodes v:
4      if v adjacent to u:
5        D(v) = c(u,v)             // 邻居的代价已知
6      else:
7        D(v) = ∞                  // 非邻居暂时无穷大
8
9  Loop:
10   find w not in N' such that D(w) is minimum
11   add w to N'                   // w 的最短路径从此确定
12   for each neighbor v of w, if v not in N':
13     D(v) = min(D(v), D(w) + c(w,v))   // 松弛：走 w 中转会不会更近？
14 until all nodes in N'
```

### 2.4 完整算例——以 u 为源

网络拓扑再现：

```
        5
    v ----- w
  2 |   3   | 5
    |        |
    u        z
    |        |
  1 |   1   | 2
    x ----- y
        1
```

逐步执行（每一列代表一个目的节点，每一步代表一次"确定一个节点 + 松弛"）：

| Step | N' | D(v),p(v) | D(w),p(w) | D(x),p(x) | D(y),p(y) | D(z),p(z) |
|------|-----|-----------|-----------|-----------|-----------|-----------|
| 0 | {u} | 2,u | 5,u | 1,u | ∞ | ∞ |
| 1 | {u,x} | 2,u | 4,x | — | 2,x | ∞ |
| 2 | {u,x,y} | 2,u | **3,y** | — | — | 4,y |
| 3 | {u,x,y,v} | — | 3,y | — | — | 4,y |
| 4 | {u,x,y,v,w} | — | — | — | — | 4,y |
| 5 | {u,x,y,v,w,z} | — | — | — | — | — |

**逐步详解**：

**Step 0（初始化）**：N' = {u}。u 的邻居是 v(x=2)、w(x=5)、x(x=1)。非邻居初始化为 ∞。

**Step 1（选 x）**：不在 N' 中且 D 最小的是 x（D=1）。将 x 加入 N'。松弛 x 的邻居：
- v：min(2, 1+2) = 2 → 不变（直接走更近）
- w：min(5, 1+3) = 4 → **更新！** 走 u→x→w 的代价 4 比直接 u→w 的 5 更小
- y：min(∞, 1+1) = 2 → **更新！** 首次知道可以到达 y

**Step 2（选 y）**：D(v)=2 和 D(y)=2 并列最小。任选 y（另一个选 v 也行，结果相同）。松弛 y 的邻居：
- w：min(4, 2+1) = 3 → **更新！** u→x→y→w 代价 3，比 u→x→w 的 4 更优
- z：min(∞, 2+2) = 4 → **首次知道**可以到达 z

**Step 3（选 v）**：D(v)=2 最小。松弛 v 的邻居 w：min(3, 2+3) = 3 → 不变。

**Step 4（选 w）**：D(w)=3 最小。松弛 w 的邻居 z：min(4, 3+5) = 4 → 不变。

**Step 5（选 z）**：只剩 z，加入 N'，算法结束。

### 2.5 最终结果：最短路径树 + 转发表

从 u 出发的最短路径树：

```
         v
        /
       u —— x —— y
             \    \
              w    z
```

转发表（填入第 06 章路由器的转发表中）：

| 目的地 | 出链路 |
|--------|--------|
| v | (u,v) — 直接走 v |
| x | (u,x) — 直接走 x |
| y | (u,x) — 经 x |
| w | (u,x) — 经 x→y→w |
| z | (u,x) — 经 x→y→z |

> 注意到 w 和 z 都走 (u,x) 出口——因为它们的路径都以 x 为第一跳。这就是"下一跳"的含义：**路由器只决定发给哪个邻居，后面怎么走是下家的事。**

### 2.6 复杂度分析

| 维度 | 复杂度 | 解释 |
|------|--------|------|
| **计算复杂度** | O(n²) | n 次迭代，每次扫描全部不在 N' 中的节点找最小值；共 n(n+1)/2 次比较。可用堆优化到 O(n log n) |
| **消息复杂度** | O(n²) | 每台路由器广播自己的链路状态到 n 个路由器，每条广播跨越 O(n) 条链路。n × O(n) = O(n²) 条消息跨越的链路总数 |

### 2.7 震荡问题（Oscillations）

当**链路代价依赖于流量**时，Dijkstra 可能震荡。考虑以下场景：

```
所有流量去往 a，从 d、c、b 进入，速率分别为 1、e(<1)、1。
链路代价 = 方向性 + 流量相关

时刻 T0：初始路由 → 代价分布 → 重算路由
时刻 T1：新路由使流量全部走另一条路 → 代价反转 → 重算路由
时刻 T2：又切回来 → 又反转 → ...
```

所有路由器同步重算 → 同步切换 → 流量规律性震荡。**解决方案**：让代价更新不同步——每台路由器加随机延迟（random delay），打破同步。

## 3. 距离向量路由 — Bellman-Ford 方程

### 3.1 核心思想：不看地图，相信邻居

LS 是"拿到全地图自己规划"。DV 完全不同——**每台路由器只知道"我离每个目的地有多远"，并且定期把自己的这个"距离表"告诉所有邻居**。

你不需要知道全网拓扑。你只需要知道：(1) 走到每个邻居的直接代价，(2) 每个邻居声称他们走到各目的地的代价。然后取 min。

这就是 Bellman-Ford 方程：

> **Dₓ(y) = minᵥ { c(x,v) + Dᵥ(y) }**
>
> 从 x 到 y 的最短路径 = 所有邻居 v 中，选"x 到 v 的直连代价 + v 声称到 y 的代价"中最小的那个。

### 3.2 一个具体例子

```
已知 u 的三个邻居 v、x、w，它们各自声称到 z 的代价：
  Dᵥ(z) = 5
  Dₓ(z) = 3
  Dʷ(z) = 3

u 到各邻居的直连代价：
  c(u,v) = 2, c(u,x) = 1, c(u,w) = 5

Dᵤ(z) = min(2+5, 1+3, 5+3) = min(7, 4, 8) = 4
下一跳 = x（因为 1+3=4 最小）
```

**你不需要知道 x 具体怎么到 z 的——你只需要信任 x 说的"我离 z 有 3 远"。** DV 的优雅和脆弱都在这里。

### 3.3 分布式迭代机制

每个节点做三件事，循环往复：

```
等待（本地链路代价变化 或 收到邻居的DV消息）
    ↓
用 Bellman-Ford 方程重算自己的 DV
    ↓
如果 DV 变了 → 通知所有邻居
如果 DV 没变 → 什么也不做（自终止，Self-Stopping）
```

关键特性：
- **异步（Asynchronous）**：没有全局时钟，各节点各自响应本地事件
- **分布式（Distributed）**：不需要全局拓扑
- **自终止（Self-Stopping）**：只有 DV 变化才通知——网络稳定后，路由协议停止发送消息

### 3.4 信息扩散：每次迭代传播一跳

```
t=0: 节点 c 的状态只有 c 自己知道
t=1: c 的状态传播到 b（1 跳），b 的 DV 计算可能受影响
t=2: c 的状态传播到 a 和 e（2 跳）
t=3: c 的状态传播到 d、f、h（3 跳）
t=4: c 的状态传播到 g、i（4 跳）
```

每经过一次迭代，信息向外扩散一跳。n 跳外的变化需要 n 次迭代才能被感知——这和 LS 的"洪泛到全网"本质不同。

### 3.5 实际算例——9 节点网格的 DV 收敛过程

```
    a --- b --- c
    |     |     |
    d --- e --- f
    |     |     |
    g --- h --- i

初始（t=0）：每个节点只知道直接邻居的代价
t=1：收到邻居 DV → BF 方程更新 → 发新 DV
t=2：收到新 DV → 继续更新 → 发新 DV
... 直到所有节点收敛
```

以节点 b 为例，t=1 时：

```
b 收到来自 a、c、e 的 DV。对于目的地 f：

D_b(f) = min{
  c(b,a) + D_a(f),   // 经 a：代价未知（a 还不知道 f）
  c(b,c) + D_c(f),   // 经 c：1 + ∞ = ∞（c 的 DV 中到 f 还是 ∞）
  c(b,e) + D_e(f)    // 经 e：1 + 1 = 2  ← 选这个！
} = 2
下一跳 = e
```

随着迭代次数增加，越来越多的目的地被"发现"，代价逐渐收敛到全局最优。

## 4. 计数到无穷 — DV 的阿喀琉斯之踵

### 4.1 好消息传得快

```
      y
  4 /   \ 1
   x     z
     50 (直接链路：但 x-z 不走这条，代价 50 太大了)

初始：D_y(x)=4, D_z(x)=5（经 y: 1+4=5）

t0: 链路 (x,y) 代价从 4 降为 1（好消息！）
    y 检测到变化 → D_y(x)=min(1, 1+5)=1 → 通知 z
t1: z 收到 y 的新 DV → D_z(x)=min(50, 1+1)=2 → 通知 y
t2: y 收到 z 的 DV → D_y(x)=min(1, 1+2)=1 → DV 不变 → 停止
```

代价降了，两次交互就收敛——**好消息传得快。**

### 4.2 坏消息传得慢——计数到无穷

```
初始：D_y(x)=4, D_z(x)=5（经 y）

t0: 链路 (x,y) 代价从 4 暴涨为 60（坏消息！！）
    y: D_y(x) = min(60, c(y,z) + D_z(x)) = min(60, 1+5) = 6
    → y 居然选了走 z！（y 不知道 z 到 x 的路径其实经过 y 自己！）
    → y 通知 z："我到 x 的代价变成 6 了"

t1: z 收到 y 的 DV
    z: D_z(x) = min(50, 1+6) = 7  ← z 也选了走 y！
    → z 通知 y："我到 x 的代价变成 7 了"

t2: y: D_y(x) = min(60, 1+7) = 8
    → 通知 z

t3: z: D_z(x) = min(50, 1+8) = 9
    → 通知 y

...一直递增...

t44: D_y(x) = min(60, 1+49) = 50 → 终于选 60（直接链路）
```

**y 和 z 互相以为对方有更好的路，其实都在绕圈子。** 这就是路由环路（Routing Loop）——分组在 y 和 z 之间来回跳，直到 TTL 耗尽。每次迭代代价 +1，像在"计数到无穷"。

### 4.3 根因与对策

**根因**：DV 中每个节点只看邻居的"报价"，**不知道邻居的路径是否经过自己**。z 对 y 说"我到 x 代价是 5"，y 不知道这 5 其实 y→z→y→z→... 的环路。这就是所谓的"缺乏全局视角"——LS 永远不会遇到这个问题，因为每个 LS 节点有全网拓扑，一眼就能看出环路。

**毒性逆转（Poison Reverse）** 是常用的缓解手段：

> 如果 z 到 x 的路由经过 y，那么 z **对 y 谎称 D_z(x) = ∞**。

这样 y 永远不会选 z 作为去 x 的下一跳，环路从源头被切断。但毒性逆转只对两个节点的简单环路有效——涉及三个或更多节点的环路，仍可能逃逸。

## 5. LS vs DV — 两种哲学的全面对比

| 维度 | Link State（LS） | Distance Vector（DV） |
|------|-----------------|---------------------|
| **知识范围** | 全网拓扑（通过洪泛获得） | 仅邻居（通过 DV 交换迭代获得） |
| **核心算法** | Dijkstra（集中式计算） | Bellman-Ford（分布式迭代） |
| **计算复杂度** | O(n²)，可优化到 O(n log n) | 取决于收敛速度，无明确上界 |
| **消息复杂度** | n 个路由器各广播 O(n) 条 → O(n²) | 仅邻居间交换，但收敛时间不定 |
| **收敛速度** | O(n²)，有明确上界 | 变化不定；好消息快，坏消息慢 |
| **路由环路** | 不会出现（每个节点有全局拓扑） | 可能出现，count-to-infinity |
| **鲁棒性-单点故障** | 一个节点谎报链路代价 → 影响有限（仅影响经过该链路的路径） | 一个节点谎报路径代价 → **黑洞效应（black-holing）**，错误通过 DV 传播到全网 |
| **哲学类比** | 电子地图：自己规划 | 路口问路：相信路人口碑，但路人可能指错 |

**一句话总结**：LS 用更高的消息开销换取正确性和收敛速度；DV 用更低的通信开销换取简单性，但牺牲了收敛速度和鲁棒性。

课件原话道出了关键区别："LS: router can advertise incorrect *link cost* — each router computes only its own table. DV: router can advertise incorrect *path cost* — each router's DV is used by others: error propagates through network."

## 6. 自治系统 — 互联网如何解决规模问题

### 6.1 为什么需要自治系统？

前面讨论的 LS 和 DV 都假设"所有路由器同等、网络扁平"。但互联网不是这样的：

**规模问题（Scale）**：全球几十亿个目的地。不可能存进一张路由表——内存放不下。路由消息交换会**淹没所有链路带宽**——每台路由器向全网洪泛链路状态？互联网上有上百万台路由器。

**管理自治（Administrative Autonomy）**：互联网是网络的网络。南京大学、中国移动、Google——每个网络管理员都希望**控制自己网络内的路由策略**。南大不想让中移动决定自己内部流量怎么走。

### 6.2 两层路由架构

解决方案：将路由器聚合成**自治系统（Autonomous System, AS）**——同一管理机构下的路由器集合。

```
         ┌────────── AS3 ──────────┐
         │  3a ──── 3b ──── 3c    │
         │           │             │
         └───────────┼─────────────┘
                     │
    ┌────────────────┼────────────────┐
    │   AS1          │         AS2    │
    │   1a ──── 1b   │   2a ──── 2b   │
    │    │           │                │
    │   1d ──── 1c   │   2c           │
    └────────────────┴────────────────┘
```

| 路由层次 | 范围 | 协议 | 做什么 |
|---------|------|------|--------|
| **Intra-AS（AS 内部）** | 同一 AS 内的路由器 | OSPF, RIP, EIGRP | 计算 AS 内部的最短路径 |
| **Inter-AS（AS 之间）** | 不同 AS 的网关路由器之间 | BGP（第 09 章） | 通告"我可达哪些网络前缀" |

**网关路由器（Gateway Router）** 同时参与两层路由——AS 内部跑 OSPF 和同 AS 路由器交换；对外连到其他 AS，跑 BGP 交换可达信息。

关键设计：**AS 之间只通告"可达哪些网络"，不暴露内部拓扑**。外部世界不需要知道 AS 内部有多少台路由器、怎么连的——只需要知道"去 200.23.16.0/20 走那个 AS 的网关"。

## 7. OSPF — 最主流的 AS 内部路由协议

### 7.1 协议定位

OSPF（Open Shortest Path First，开放最短路径优先）是目前互联网最广泛使用的 AS 内部路由协议。另外两个历史上出现过的是 RIP（经典 DV，每 30 秒交换一次 DV，已基本淘汰）和 EIGRP（思科私有 → 2013 年开放，DV 变种）。

### 7.2 OSPF 的核心机制

OSPF 不是一条算法，而是一整套"信息收集 → 地图绘制 → 路径计算 → 规模控制"的流水线。分五步理解：

**Step 1 — 发现邻居（Hello）**：每台路由器在直连链路上周期性发送 Hello 消息，发现直连的邻居并建立邻接关系（adjacency）。这一步回答"我连着谁"。

**Step 2 — 洪泛 LSA（洪泛）**：每台路由器把自己和邻居的连接信息写进**链路状态通告（LSA）**，洪泛给全网所有路由器。关键设计——LSA 只包含**发出者自己的**直连信息（"我是 u，连 v 代价 2、连 x 代价 1"），不包含别人的信息、不包含路径、不包含全局拓扑。洪泛之后，每台路由器收集到所有 LSA，存入**链路状态数据库（LSDB）**。同一 Area 内所有路由器的 LSDB 完全相同。

> **LSA 是什么？用拼图类比**：6 个人各拿一块拼图碎片——u 的碎片上只有"u—v, u—x"，x 的碎片上只有"x—u, x—v, x—w, x—y"。单独看任何一块碎片都不知道全貌。但洪泛让每个人都拿到全部 6 块碎片，拼在一起就得到完整地图。**LSA 是拼图碎片，洪泛是让所有人拿到所有碎片的过程，LSDB 是拼完的图。**

**Step 3 — 各自跑 Dijkstra**：每台路由器拿着 LSDB 这张完整地图，以**自己为根节点**运行 Dijkstra 算法，算出到每个目的地的最短路径和下一跳。**注意**：地图是共享的（人人一样），但路径是各自算的（以自己为起点）。这就是 LS 鲁棒性的根源——你算错了不影响我。

**Step 4 — 填入转发表**：计算结果 → `<目的网络, 出接口, 下一跳>` → 填入第 06 章的转发表。数据平面查表转发。

**OSPF 的核心特征总结**：

| 特征 | 说明 |
|------|------|
| **类型** | 链路状态（Link State）协议 |
| **信息分发** | 每个路由器向 AS 内所有路由器**洪泛（flood）**链路状态通告（LSA） |
| **传输方式** | LSA **直接承载在 IP 数据报上**（协议号 89），不使用 TCP/UDP |
| **计算方式** | 每个路由器拥有完整 AS 拓扑，独立运行 Dijkstra |
| **代价指标** | 灵活——可基于带宽、延迟等多种因素；管理员可自定义 |
| **安全认证** | 所有 OSPF 消息必须经过认证，防止恶意注入虚假路由 |

> "直接走 IP 而非 TCP/UDP"：OSPF 需要把 LSA 洪泛给 AS 内**所有**路由器。若用 TCP，需要与每台路由器各建一条连接（O(n²) 条）——管理灾难；且 TCP 是单播，无法一发到所有邻居。OSPF 直接走 IP 协议号 89 + 组播（`224.0.0.5`），一跳到达所有邻居，自己实现确认和重传保证可靠洪泛。

### 7.3 层次化 OSPF — "省-市-区"三级行政

AS 内有 5000 台路由器会怎样？每台发一条 LSA → 5000 × 5000 = 2500 万次消息传送，任何一条链路断了又要重新洪泛。每台路由器要存 5000 条 LSA——拓扑数据库爆炸。

**类比**：中国政府管 14 亿人，不是一个人直接管——是省 → 市 → 区 → 街道的层级。每个层级只管理自己范围内的事，跨层级的请示上级。

OSPF 的解决方案完全一样：**两级层次**——把 AS 划分为多个**区域（Area）**+ 一个**骨干（Backbone, Area 0）**：

```
              ┌─────────────────────────────┐
              │    Backbone（骨干 / "国务院"） │
              │   Area 0 / 0.0.0.0           │
              │   ┌──────┐    ┌──────┐       │
              │   │ ABR1 │    │ ABR2 │       │
              │   └──┬───┘    └──┬───┘       │
              └──────┼──────────┼────────────┘
                     │          │
          ┌──────────┴──┐  ┌───┴──────────┐
          │   Area 1    │  │   Area 2     │
          │ ("仙林校区") │  │ ("鼓楼校区") │
          │ LS 洪泛仅   │  │ LS 洪泛仅    │
          │ 在本区域     │  │ 在本区域     │
          └─────────────┘  └──────────────┘
```

四种路由器角色对应现实：

| OSPF 角色 | 类比 | 职责 |
|-----------|------|------|
| **内部路由器（Internal Router）** | 一个省内的县级官员 | 只在 Area 内洪泛 LSA，计算本 Area 内路由。本 Area 之外的拓扑一概不知。 |
| **区域边界路由器（ABR）** | 省长 + 驻京办主任 | **汇总**本 Area 的目的地信息通告给 Backbone；把 Backbone 的信息带回本 Area。是 Area 和 Area 0 之间的唯一通道。 |
| **骨干路由器（Backbone Router）** | 国务院部委 | 只在 Backbone 运行 OSPF，处理跨 Area 路由转发。 |
| **边界路由器（Boundary Router）** | 外交部 | 连接其他 AS，注入外部路由信息（第 09 章 BGP 结合）。 |

**具体例子**——南京大学 AS 划了两个 Area：

- Area 1（仙林校区）：计科楼、软院楼、电子楼、图书馆的交换机互连
- Area 2（鼓楼校区）：商学院、法学院、医学院的交换机互连
- Backbone（Area 0）：连接两个校区的核心主干链路 + 两台 ABR

**场景 A — 计科楼访问软院楼**：都在 Area 1 内部。Area 1 内所有路由器已通过内部 LSA 洪泛拥有本 Area 详细拓扑，计科楼路由器自己跑 Dijkstra 算出"走电子楼中转更近"。**Backbone 不参与，Area 2 完全不知道这件事。** 本地事务本地处理。

**场景 B — 计科楼访问鼓楼商学院**：跨 Area 了。计科楼路由器**没有** Area 2 的详细拓扑。它的路由表里关于"商学院网络"只有一条："去商学院？走 ABR1"。它不知道也不关心中间经过哪些路由器。ABR1 收到后，沿 Backbone → ABR2 → Area 2 送达。**外部不需要内部细节，只知道方向。**

**关键设计意图**：每个路由器只需知道本 Area 的详细拓扑；到外 Area 目的地只知道"走哪个 ABR"。LSA 洪泛仅限同一 Area 内部——一个 Area 的拓扑变化不会触发全 AS 范围的洪泛。

### 7.4 OSPF 的代价指标 — "高德地图的导航偏好"

OSPF 的链路代价不是固定 1（跳数），管理员可自定义：

```
链路代价 = f(带宽, 延迟, 可靠性, 费用, ...)

例：
  - 光纤链路（10Gbps）→ 代价 1（快）
  - 老旧铜缆（100Mbps）→ 代价 100（慢）
  - 卫星链路（高延迟）→ 代价 50
```

**类比**：高德地图让你选"高速优先"、"最短路径"、"避免收费"。代价指标就是你选的不同偏好。管理员可通过设置代价引导流量——视频会议走高带宽链路，普通 Web 走普通链路。这与 RIP 只用跳数（15 跳就不可达）形成鲜明对比。

### 7.5 OSPF 的安全认证 — "小区门禁卡"

OSPF 所有消息必须经过认证。为什么？**没有认证的恐怖场景**——攻击者在校园网用一台笔记本跑假 OSPF 进程，洪泛假 LSA："我连接了百度服务器，代价为 1！" 全 AS 路由器的 Dijkstra 都会相信，把所有去百度的流量引向这台笔记本——黑洞或中间人攻击。

OSPF 的认证像小区门禁卡：只接受持有合法密钥的路由器的消息，陌生人的通告直接丢弃。

## 难点突破

### 难点 1：Dijkstra 算法中"松弛"的真正含义

**直觉**：你已经确定了一些节点的最短路径（在 N' 中）。现在你把一个"当前看起来最近"的新节点 w 加入 N'。问题是：**经由 w 中转，能不能让还没进 N' 的某些节点更近？**

松弛操作 `D(v) = min(D(v), D(w) + c(w,v))` 就是在做这个检查。`D(v)` 是"之前知道的最好走法"，`D(w) + c(w,v)` 是"先按最短路径走到 w，再走一步直接到 v"。

**关键**：D(v) 在 v 进 N' 之前只是一个**上界**（upper bound）——可以持续被新的 w 更新得更小。只有当 v 自己被选为 w（即选进 N'）的那一刻，才确认这个上界就是真正的下界——不可能再有更短的路径了。这是 Dijkstra 算法正确性的核心。

### 难点 2：为什么坏消息要"计数到无穷"而不是立刻选直接链路？

以 y—z—x 的 count-to-infinity 为例：y 到 x 的直接链路代价暴涨到 60。

问题的根不是"y 不知道直接链路代价是 60"——y 知道。问题是 y 在计算 `min(60, 1 + D_z(x))` 时，发现 z 报的 D_z(x)=5 比 60 小得多，所以**选择相信 z 的路更好**。

但 z 的 D_z(x)=5 是**过时的**——这个值是基于 y 到 x 代价为 4 时算出来的。当 y 的代价变成 60 后，z 并不知道——直到 y 通知它。而 y 通知 z 的是"我现在到 x 的代价是 6（经过 z！）"，z 收到后更新自己的值为 7……循环开始。

**本质**：DV 的分布式异步特性使得信息的变化需要时间传播。当代价增加时，旧的"乐观估计"在系统中残留，引导节点做出错误选择。LS 不会遇到这个问题——每个节点收到洪泛的代价变化后立即更新全局拓扑，不存在"旧信息污染"。

### 难点 3：OSPF 为什么直接把 LSA 放在 IP 上而不是用 TCP？

OSPF 需要**可靠洪泛（reliable flooding）**——每个 LSA 必须被 AS 内所有路由器收到并确认。如果用 TCP：

- 每对路由器之间需要建立 TCP 连接 → O(n²) 条连接，管理灾难
- TCP 是单播——要把 LSA 发给所有路由器，需要 n 条 TCP 连接各发一遍

OSPF 的做法：**直接走 IP + 自己实现确认/重传。** 用组播地址（`224.0.0.5` 和 `224.0.0.6`）发送 LSA，一跳就到所有邻居。OSPF 自己处理丢包重传——协议内部维护每个 LSA 的确认状态，未确认的会重发。

## 关键原句

> "Routing protocol goal: determine 'good' paths (equivalently, routes), from sending hosts to receiving host, through network of routers"
>
> 路由协议的目标：确定"好"的路径，从发送主机到接收主机，经过路由器组成的网络。

> "global: all routers have complete topology, link cost info ... decentralized: iterative process of computation, exchange of info with neighbors ... routers initially only know link costs to attached neighbors"
>
> 全局：所有路由器拥有完整拓扑和链路代价信息……分布式：迭代计算、与邻居交换信息……路由器最初只知道连接到邻居的链路代价。

> "Dₓ(y) = minᵥ { c(x,v) + Dᵥ(y) }"
>
> 从 x 到 y 的最短路径代价 = 对所有邻居 v，取（直接代价 + v 声称的代价）的最小值。

> "bad news travels slow — count-to-infinity problem"
>
> 坏消息传得慢——计数到无穷问题。

> "aggregate routers into regions known as 'autonomous systems' (AS) (a.k.a. 'domains')"
>
> 将路由器聚合成称为"自治系统"（也称为"域"）的区域。

> "OSPF: Open Shortest Path First ... classic link-state ... each router floods OSPF link-state advertisements (directly over IP rather than using TCP/UDP) to all other routers in entire AS"
>
> OSPF：经典的链路状态协议……每台路由器将 OSPF 链路状态通告（直接在 IP 上而非用 TCP/UDP）洪泛到整个 AS。

> "two-level hierarchy: local area, backbone. link-state advertisements flooded only in area, or backbone"
>
> 两级层次：本地区域、骨干。链路状态通告仅在区域或骨干内洪泛。

> "when link costs depend on traffic volume, route oscillations possible"
>
> 当链路代价依赖于流量时，可能出现路由震荡。

## 记忆卡片

> **Q: 路由协议要解决什么问题？控制平面和数据平面的分工是什么？**
> **A:** 路由协议负责计算从源到目的地的"好"路径，填入转发表。控制平面**决定路径**（计算转发表），数据平面**执行转发**（查表搬分组）。两者分工：控制平面是大脑，数据平面是肌肉。路由协议跑在控制平面。

> **Q: LS 和 DV 的根本哲学差异是什么？各自的代表算法？**
> **A:** **LS（链路状态）**：每个路由器拥有全网拓扑（通过洪泛获得），用 Dijkstra 集中计算最短路径，鲁棒但消息开销大。**DV（距离向量）**：每台路由器只知道邻居的"报价"，用 Bellman-Ford 方程分布式迭代，简单但可能出现计数到无穷。类比——LS 是电子地图自己导航，DV 是在路口问路人"去 XX 怎么走"。

> **Q: Dijkstra 算法的每一步具体做什么？**
> **A:** (1) 在尚未确认的节点中，找当前估计值 D(w) 最小的节点 w；(2) 将 w 加入 N'（确认其最短路径已确定）；(3) 对 w 的所有不在 N' 中的邻居 v，执行松弛：D(v) = min(D(v), D(w) + c(w,v))——"走 w 中转会不会更近？"

> **Q: 什么是计数到无穷？为什么只发生在 DV 中？**
> **A:** 链路代价突然增大时，两个节点互相以对方为下一跳（因为双方的 DV 中仍存有旧的乐观估计），导致代价估算不断递增的恶性循环。只出现在 DV 中，因为 DV 节点不知道邻居的路径是否经过自己（缺乏全局拓扑），而 LS 每个节点有全网地图，一眼就能看出环路。缓解手段：毒性逆转（对经由某节点的目的地向该节点谎报 ∞）。

> **Q: OSPF 有哪些核心特征？**
> **A:** (1) 链路状态协议——洪泛 LSA → 全 AS 拥有相同拓扑 → 各自跑 Dijkstra；(2) LSA 直接承载在 IP 上（协议号 89），不用 TCP/UDP；(3) 灵活的代价指标（带宽、延迟等）；(4) 所有消息必须认证——防止恶意注入；(5) 支持两级层次（Area + Backbone）——LSA 洪泛仅限区域内部，ABR 汇总跨区域信息。

> **Q: 互联网为什么需要自治系统（AS）？**
> **A:** 两个驱动力：(1) **规模**——几十亿目的地无法存进一张路由表，路由消息交换会淹没链路；(2) **管理自治**——不同网络有各自的路由策略，各机构希望控制自己网络内的路由。AS 将路由器分组，AS 内部跑 OSPF 等协议，AS 之间跑 BGP 交换可达性——外部只知"可达哪些前缀"，不暴露内部拓扑。

> **Q: LS 和 DV 在鲁棒性上有什么差异？**
> **A:** **LS**：一个节点谎报链路代价——影响有限，因为每个节点只用自己的拓扑独立计算路由表，错误不传播。**DV**：一个节点谎报路径代价（"我到每个地方都有超低代价路径"）→ 邻居用这个假报价更新自己的 DV → 流量被引向该恶意节点 → **黑洞效应（black-holing）**，错误通过 DV 交换传播到全网。这是 DV 的致命安全弱点。

## 考点梳理

### 必考简答题

**1. 比较链路状态（LS）和距离向量（DV）两种路由算法。**（★★★）

**答**：LS 通过洪泛使每个路由器拥有全网拓扑，用 Dijkstra 集中计算最短路径；消息复杂度 O(n²)，收敛 O(n²)，不会出现路由环路，对谎报链路代价有较好鲁棒性（每节点独立计算）。DV 基于 Bellman-Ford 方程分布式迭代，节点只与邻居交换距离向量；消息仅在邻居间传递但收敛时间不定，可能出现**计数到无穷**问题，一个节点谎报路径代价会导致错误传播到全网（黑洞效应）。LS 以更高开销换正确性和收敛速度，DV 以更低开销换简单性但牺牲鲁棒性。

**2. Dijkstra 算法的计算过程——"松弛"的含义是什么？**（★★★）

**答**：松弛操作 `D(v) = min(D(v), D(w) + c(w,v))` 的含义是：**经由新确认的节点 w 中转，能否让到达 v 的路径比当前已知的更短？** D(v) 在 v 被确认前只是一个上界，每次新节点加入 N' 时都可能被更新得更小。只有在 v 自己进 N' 的那一刻，D(v) 才从"上界"变成"确切最短距离"。

**3. 计数到无穷问题的原因和解决方案。**（★★★）

**答**：原因：DV 节点只看邻居报价，不知道邻居的路径是否经过自己。当链路代价增大时，旧的乐观估计残留在系统中，两个节点互相选对方为下一跳形成环路，代价每次迭代 +1。解决方案：**毒性逆转（Poison Reverse）**——若到某目的地的路由经过某邻居，则对该邻居谎报该目的地的代价为 ∞，从源头阻断环路。但仅对两节点环路有效。

**4. OSPF 为什么直接把 LSA 放在 IP 上而不是用 TCP/UDP？**（★★）

**答**：OSPF 需要**可靠洪泛**——把 LSA 发给 AS 内**所有**路由器。若用 TCP 需要与每台路由器建立连接（O(n²) 条），且 TCP 是单播。OSPF 直接走 IP 协议号 89 + 组播（`224.0.0.5`），一跳到达所有邻居，自己维护确认和重传机制——比在 n 条 TCP 连接上各发一遍高效得多。

**5. 自治系统（AS）解决了什么问题？**（★★）

**答**：(1) **规模**——全球几十亿目的地，路由表放不下，路由消息淹没链路。AS 聚合后，AS 间只通告网络前缀可达性，不暴露内部拓扑。(2) **管理自治**——网络是网络的网络，不同机构需要控制自己的路由策略。AS 内部统一协议（OSPF），AS 间用 BGP 传递策略化路由。

### 必考计算题

**类型一：Dijkstra 逐步执行**（★★★）

> 给定网络拓扑和链路代价，从指定源节点出发，逐步执行 Dijkstra 算法，给出每一步的 N'、D(v)、p(v)，画最短路径树和转发表。

**答题格式**：列出每一步的表格（Step / N' / 各节点 D 和 p），然后画最短路径树，最后从最短路径树推导转发表（目的地→出链路）。

**类型二：Bellman-Ford 方程计算**（★★★）

> 已知节点 x 的各邻居到目的地 y 的声称代价，以及 x 到各邻居的直接代价，求 Dₓ(y) 和下一跳。

**解法**：`Dₓ(y) = min{c(x,v₁)+Dᵥ₁(y), c(x,v₂)+Dᵥ₂(y), ...}`。取 min 值对应的邻居为下一跳。

**类型三：DV 信息扩散分析**（★★）

> 在某链路代价变化后，分析 DV 协议需要多少次迭代才能收敛到稳定状态。

**解法**：追踪每次迭代中各节点的 DV 更新。"好消息"（代价降低）1-2 次迭代收敛；"坏消息"（代价增大）可能计数到无穷，迭代次数 = 新代价 − 旧代价量级。

### 易错点

- **Dijkstra 中 D(v) 在 v 进 N' 之前是上界不是最终值**——常误以为每次更新后 D(v) 就是最短的
- **DV 中"邻居的报价"可能包含回环路径**——z 说"我到 x 有代价 5"，但它到 x 的路径可能经过 y，而 y 正在向 z 询问去 x 的路
- **毒性逆转只对两节点回路有效**——三节点以上的环路可能逃逸
- **OSPF 是 LS 协议，不是 DV**——常与 RIP（DV）混淆。OSPF = 洪泛 LSA + Dijkstra，RIP = 交换 DV + Bellman-Ford
- **LS 节点不会传播别人的计算结果**——每个节点独立计算自己的路由表。DV 节点会把别人的报价当作自己计算的基础
- **Dijkstra 的振荡发生在代价依赖流量时**——如果代价固定（如跳数），不会震荡
