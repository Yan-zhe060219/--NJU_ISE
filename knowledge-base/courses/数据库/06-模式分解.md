## 一句话总结

模式分解是规范化理论的操作层面——将关系模式拆分为若干子模式。一个好的分解必须同时满足**无损连接**（能把子关系还原成原关系）和**保持函数依赖**（原依赖仍能在子模式中检验），二者往往不可兼得，需要权衡。

## 核心概念

### 1. 模式分解的定义

R(U, F) 的分解 ρ = {R₁(U₁, F₁), R₂(U₂, F₂), ..., Rₙ(Uₙ, Fₙ)}，满足 U = ∪Uᵢ 且各 Uᵢ ⊆ U。Fᵢ 是 F 在 Uᵢ 上的投影（即 F⁺ 中包含在 Uᵢ 中的依赖）。

### 2. 分解的两种性质

**无损连接（Lossless Join）**：对 R 的任何实例 r，r = πU₁(r) ⋈ πU₂(r) ⋈ ... ⋈ πUₙ(r)。即：分解后再自然连接，不会多出或丢失元组。

**保持函数依赖（Dependency Preservation）**：F⁺ = (∪Fᵢ)⁺。即：所有原依赖都能在某个子模式中检验，不需要连接回原表。

### 3. 三种分解准则

| 准则 | 要求 |
|------|------|
| 最低要求 | 无损连接 |
| 中等要求 | 无损连接 + 保持函数依赖 |
| 最高要求 | 无损连接 + 保持函数依赖 + 每个子模式达到指定的范式 |

### 4. 无损连接的判别

**引理 6.5**（二元分解的无损连接判定）：ρ = {R₁, R₂} 是无损连接的 ⇔ (U₁ ∩ U₂) → (U₁ − U₂) ∈ F⁺ 或 (U₁ ∩ U₂) → (U₂ − U₁) ∈ F⁺。

即：**公共属性能函数确定其中一个子模式的独有属性**。

### 5. 候选码的计算（补充算法）

核心思路：用属性闭包算法。将属性分为四类：
- **L 类**：只出现在 F 左侧 → 必属于所有候选码
- **R 类**：只出现在 F 右侧 → 不属于任何候选码
- **N 类**：不出现在 F 中 → 必属于所有候选码
- **LR 类**：同时出现在两侧 → 待定

从 L∪N 出发计算闭包，若不等于 U 则加入 LR 类属性尝试。

### 6. BCNF 分解算法（算法 6.5）——「一刀两半」法

**口诀**：找到肇事依赖 X→Y，算 X⁺，沿 X⁺ 边界一刀两半，X 留在两边当桥梁。

**步骤**：
1. 找到违反 BCNF 的依赖 **X→Y**（X 不是超码）
2. 计算 **X⁺**（X 的闭包）
3. 拆成两个子模式：**(X⁺)** 和 **((U − X⁺) ∪ X)**
4. X 同时出现在两边——这是无损的关键：X 在左边子模式是超码，公共属性能决定左边全部 → 引理 6.5
5. 递归检查每个子模式，直到全部满足 BCNF
6. 去重：被子模式包含的删掉

**实例**：R3(B, C, D, F)，FD = {DF→BC, B→D}，候选码 DF 和 BF

- B→D 违反 BCNF（B⁺ = {B,D}，不是全属性）→ 肇事依赖
- B⁺ = {B, D}
- 拆：**R31(B, D)** + **R32(B, C, F)**
  - R31 的 FD：{B→D}，候选码 B → BCNF ✅
  - R32 的 FD：由 B→D 和 DF→BC 推导出 BF→C → BCNF ✅
- R31 被 R2(A,B,D) 包含 → 删掉 R31
- 最终 BCNF 分解：R1(A,E)、R2(A,B,D)、R3(B,C,F)
- ✅ 无损连接 | ❌ 不保持依赖（DF→BC 丢失）

> **3NF vs BCNF 权衡**：3NF 总能无损 + 保持依赖；BCNF 总能无损但可能丢依赖。考试中如果题目要求"保持函数依赖"，优先选 3NF。

### 7. 3NF 分解算法（算法 6.3/6.4）

**步骤**：
1. 先求 F 的极小函数依赖集 F_min
2. 对 F_min 中每个依赖 X→Y，建子模式 (X∪Y)
3. 检查是否有候选码被任意子模式包含 → 没有则加一个候选码子模式
4. 去重：子模式被包含就删掉

> **保证**：3NF 分解总能同时满足无损连接 + 保持函数依赖。

## 记忆卡片

**Q1: 无损连接和保持函数依赖分别是什么意思？**
A1: 无损连接：分解后的子关系通过自然连接能还原原关系；保持函数依赖：原所有依赖都能在子模式中检验。

**Q2: 二元分解无损连接的判别条件？**
A2: 公共属性能函数确定至少一个子模式的独有属性：(U₁∩U₂)→(U₁−U₂) 或 (U₁∩U₂)→(U₂−U₁)。

**Q3: 如何快速找到候选码？**
A3: L 类和 N 类属性必属于候选码，R 类必不属于。从 L∪N 计算闭包，不够再加 LR 类属性。

## 考点标注

### 必考点

1. **无损连接判别（引理 6.5）** — 二元分解的无损判定，给定具体关系模式判断分解是否无损
2. **保持函数依赖判定** — 给定 F 和分解 ρ，判断是否保持依赖（计算投影 + 比较闭包）
3. **候选码计算（L/N/R/LR 分类法）** — 给一组函数依赖，求所有候选码
4. **分解三准则** — 最低/中等/最高要求分别是什么，概念辨析
5. **无损 vs 保持依赖的权衡** — 为什么 BCNF 分解可能丢失函数依赖，而 3NF 总能两者兼顾

### 常见题型

- **判断题**：给分解方案，判断是否无损 / 是否保持依赖
- **计算题**：给 R(U,F)，求所有候选码
- **简答题**：解释无损连接的含义，为什么重要
- **综合题**：给一个低范式关系模式，要求分解到 3NF/BCNF 并验证无损+保持依赖

## 示例考题

### 题 1 — 候选码计算（★★★）

> 设有关系模式 R(A, B, C, D)，函数依赖 F = {B→D, A→C, C→AB}。求 R 的所有候选码。

**答案**：

分类属性：
- L 类（仅左）：无
- R 类（仅右）：D 只在 B→D 右侧出现
- LR 类（左右都出现）：A、B、C
- N 类（不出现）：无

但仔细看：C→AB 说明 C 也在左侧；A→C 说明 A 也在左侧；B→D 说明 B 也在左侧。D 仅出现在右侧 → **D 是 R 类，不属于任何候选码**。

从 C 出发：C⁺ = {C, A, B, D} = U → **C 是候选码**
从 A 出发：A⁺ = {A, C, B, D} = U → **A 是候选码**
从 B 出发：B⁺ = {B, D} ≠ U，加入 A → AB⁺ = {A, B, C, D} = U → AB 不是最小（A 单独已经够），加入 C → CB⁺ = {C, A, B, D} = U → CB 不是最小（C 单独已经够）

**候选码：A, C**

### 题 2 — 无损连接判定（★★★）

> R(U, F)，U = {A, B, C, D, E}，F = {A→BC, CD→E}。
> 分解 ρ = {R1(A, B, C), R2(A, D, E)}。判断是否无损连接。

**答案**：

U₁ = {A, B, C}，U₂ = {A, D, E}
U₁ ∩ U₂ = {A}
U₁ − U₂ = {B, C}
U₂ − U₁ = {D, E}

检查：(U₁∩U₂) → (U₁−U₂)，即 A → BC？

A⁺（在 F 下）= {A, B, C} ⊇ {B, C} ✓

**A → BC ∈ F⁺ → 无损连接 ✓**

---

### 题 3 — 保持函数依赖（★★★）

> R(U, F)，U = {A, B, C}，F = {A→B, B→C}。
> ρ = {R1(A, B), R2(A, C)}。判断是否保持函数依赖。

**答案**：

子模式的依赖投影：
- F₁ = F⁺ 中属性全在 {A, B} 内的依赖：A→B ✓
- F₂ = F⁺ 中属性全在 {A, C} 内的依赖：A→C（由 A→B, B→C 推导出）

现在检查 B→C：
- B→C 的属性涉及 {B, C}，不全在 R1({A,B}) 中，也不全在 R2({A,C}) 中
- 计算 G = F₁ ∪ F₂ = {A→B, A→C}，求 G⁺
- B→C 是否在 G⁺ 中？在 G 下 B⁺ = {B}，不包含 C

**B→C ∉ (F₁∪F₂)⁺ → 不保持函数依赖 ✗**

（注：正确的保持依赖的分解是 R1(A,B) 和 R2(B,C)，此时 F₁={A→B}, F₂={B→C}, F₁∪F₂ 能推出所有原依赖）

---

### 题 4 — 概念辨析（★）

> "无损连接"中的"无损"是指什么不丢失？

**答案**：指**信息（元组）**不丢失，不是指函数依赖不丢失。无损连接保证分解后的子关系通过自然连接能精确还原原关系的所有元组，不会多出虚假元组也不会丢失真实元组。函数依赖的保持是另一个独立标准。

### 题 5 — 综合（★★★）

> R(U, F)，U = {学号, 课程号, 教师, 教室}，
> F = {(学号,课程号)→教师, 教师→教室, 课程号→教室}。
>
> (1) 求候选码 (2) 判断 R 属于几范式 (3) 分解到 3NF 并验证无损+保持依赖

**答案**：

**(1)** 分类：
- L 类：学号、课程号（只出现在左侧）
- R 类：教室（只出现在右侧）
- LR 类：教师（左右都出现）

X = L∪N = {学号, 课程号}
X⁺ = {学号, 课程号, 教师, 教室} = U → **候选码：(学号, 课程号)**

**(2)** 非主属性：教师、教室。
- 教师对码是部分依赖吗？(学号,课程号)→教师，但课程号不能单独→教师，学号也不能单独→教师 → 完全依赖 ✓
- 传递依赖？码→教师→教室，存在传递依赖 → **最高 2NF，不是 3NF**

**(3)** 3NF 分解（消除传递依赖）：
- ρ = {R1(课程号, 教师, 教室), R2(学号, 课程号, 教师)}
- R1 的候选码：课程号（因为课程号→教师, 教师→教室, 课程号→教室）
  - 但有传递依赖课程号→教师→教室，所以 R1 是 2NF
  - 进一步拆：R11(教师, 教室), R12(课程号, 教师)
- 最终 3NF 分解：ρ = {R11(教师, 教室), R12(课程号, 教师), R2(学号, 课程号, 教师)}

**验证无损**：R12 和 R2 的公共属性 {教师, 课程号}，检查...（从略）

**验证保持依赖**：三个子模式分别保有 教师→教室、课程号→教师、(学号,课程号)→教师，且课程号→教室可由前两者推导 → 保持依赖 ✓
