## 一句话总结

事务是**不可分割的工作单位**——"要么全做，要么全不做"。通过 COMMIT（提交）和 ROLLBACK（回退）确保数据库在任何情况下（并发、故障、异常）都能保持一致性状态。

## 核心概念

### 1. 事务的定义

事务（Transaction）是用户定义的一个数据库操作序列，是**恢复和并发控制的基本单位**。

事务 vs 程序：一个程序通常包含多个事务。事务可以是一条 SQL 语句、一组 SQL 语句或整个程序。

### 2. 事务的 ACID 特性

- **原子性（Atomicity）**：事务中的操作要么全做，要么全不做
- **一致性（Consistency）**：事务执行前后，数据库从一个一致状态到另一个一致状态
- **隔离性（Isolation）**：并发执行的事务互不干扰
- **持久性（Durability）**：已提交的事务对数据库的改变是永久的

### 3. COMMIT 与 ROLLBACK

- **COMMIT**：提交事务，所有更新操作结果永久写入物理数据库，不可撤销
- **ROLLBACK**：回退事务，撤销事务对数据库的所有已完成的修改，将数据库恢复到事务开始前的状态
- **保存点（Savepoint）**：事务中途设置的回退点，可以回退到指定保存点而非全部撤销

### 4. 事务的启动方式

事务的启动是**隐式的**：
1. DDL 命令：每条单独作为事务，提交前一个活动事务
2. 自动提交模式：每条命令作为单独事务
3. DML 命令：如当前有活动事务则加入，否则自动启动新事务

### 5. 事务控制语句

- `SET AUTOCOMMIT ON|OFF` — 设置自动提交
- `SET TRANSACTION READONLY|READWRITE` — 只读/读写事务
- `SET TRANSACTION ISOLATION LEVEL ...` — 设置隔离级别（READUNCOMMITTED / READCOMMITTED / REPEATABLEREAD / SERIALIZABLE）

## 难点突破

### 事务的核心价值——为什么需要事务？

**关键场景**：银行转账。A 账户减 200 元 + B 账户加 200 元，这两步必须（原子性地）全做或全不做。如果在"A 已扣、B 未加"时系统崩溃，钱就凭空消失了。

**事务解决**：将这两步打包为一个事务 → 崩溃后 ROLLBACK → A 的扣款被撤销 → 数据库回到一致状态。

三个破坏因素（并发、异常中断、系统崩溃）都需要事务来应对。

## 记忆卡片

**Q1: 事务的 ACID 四大特性？**
A1: 原子性（全做或全不做）、一致性（数据库从一致→一致）、隔离性（并发互不干扰）、持久性（提交后永久保存）。

**Q2: COMMIT 和 ROLLBACK 的区别？**
A2: COMMIT 提交确认，修改永久生效不可撤销；ROLLBACK 撤销回退，废弃当前事务的所有修改，回到事务开始前的状态。

**Q3: 保存点（Savepoint）的作用？**
A3: 在事务中途设置回退点，可回退到指定保存点而不必废弃整个事务——相当于"部分回退"。

### 简答题预测 + 答案

**Q1: 解释事务的 ACID 四特性，各举一个违反的典型场景。**（10-12 分）

**答：**
- **原子性 Atomicity**：事务中操作要么全做要么全不做。违反：转账 A1 扣款成功但 A2 加款失败 → 钱消失
- **一致性 Consistency**：事务执行结果使 DB 从一致状态到另一个一致状态。违反：转账后 A1+A2 金额之和变了
- **隔离性 Isolation**：并发事务互不干扰。违反：T1 读到 T2 未提交的修改（脏读），T2 后来回滚
- **持久性 Durability**：事务一旦提交，改变永久生效。违反：COMMIT 后系统崩溃，重启后数据丢失

**Q2: 事务的三种隐式启动方式？**（5 分）

**答：** ①DDL 命令：每条 DDL 作为单独事务执行，先将当前 active 事务自动提交；②自动提交模式：每条数据库访问命令作为一个单独事务，DBMS 自动 COMMIT/ROLLBACK；③DML 命令：DBMS 检查当前是否有 active 事务——有则加入，无则自动启动新事务。

**Q3: 四种隔离级别从低到高？各级别的封锁策略差异？**（8-10 分）

**答：** READUNCOMMITTED（无读锁）→ READCOMMITTED（读前申请共享锁，读后立即释放）→ READREPEATABLE（读前申请共享锁，维持到事务结束）→ SERIALIZABLE（可串行化调度）。不管何种级别，写操作前必须申请排它锁且维持到事务结束。级别越高隔离越好但并发性能越低。

**Q4: 保存点的作用？ROLLBACK 和 ROLLBACK TO savepoint 的区别？**（5 分）

**答：** 保存点是事务内部设置的回退标记。`ROLLBACK TO sp` 只放弃保存点之后的操作，事务可继续执行；不带保存点的 `ROLLBACK` 结束并放弃整个事务。
