# source-command-review

Use this skill when the user asks to run the migrated source command `review`.

## Command Template

# 期末复习总控技能

以 `REVIEW.md` 为唯一数据源，管理六门课程（软件工程、操作系统、数据库、高级算法、中国近代史纲要、互联网计算）的复习进度。

## 子命令路由

收到 `/review` 后，先解析参数：

| 输入 | 行为 |
|------|------|
| `/review` | 默认：展示今日任务 + 倒计时（同 start） |
| `/review start` | 读取 REVIEW.md，展示今日任务和六科倒计时 |
| `/review done <笔记名>` | 标记该笔记复习完成，更新进度 |
| `/review progress` | 汇报六科整体进度和剩余天数 |
| `/review finish` | 勾选今日全部任务，预填明天任务 |
| `/review go <笔记名>` | 进入该篇笔记的深度问答复习模式 |
| `复习 <笔记名>` | 同上（自然语言触发，无需斜杠前缀） |
| `/review plan` | 展示三阶段时间表 |

---

## 一、`/review` 或 `/review start` — 进入复习

### 1. 读取总控文件

先读 `REVIEW.md`，获取最新状态。

### 2. 扫描学习任务（新课通读）

在检查维护之前，扫描 REVIEW.md 中尚未学习的新笔记：

1. 遍历 REVIEW.md 各课程章节，收集所有 `[ ]学 [ ]会` 条目（笔记已生成但未通读）
2. 按紧迫度排序：距考试天数 ↑ → 权重（★）↑
3. 取前 2-3 篇作为今日学习推荐
4. 如果该课程今日已有复习任务，合计时间不超过当日上限

**特殊处理**：
- 近代史（纯 `[ ]` 不用 `[ ]学 [ ]会`）：有 `[ ]` 未勾条目时，提示"记忆卡待创建/待背诵"
- 如果没有 `[ ]学 [ ]会` 条目（全部已通读），跳过学习任务区

### 3. 检查维护

- 如果 `updated` 日期不是今天，更新倒计时天数
- 判断当前处于哪个阶段（Phase A 维持期 / Phase B 定向期 / Phase C 冲刺期）
- Phase A：生成今日复习任务（按 REVIEW.md 中 Phase A 日程）
- Phase B/C：生成当日冲刺复习任务
- 学习任务 + 复习任务合计时间不超过阶段日均上限
- 周末可适当加量

### 4. 输出今日面板

```
📋 今日复习 — 2026.06.16（周二）· 距软工考试 8 天 · Phase B Day 1 · 做题驱动

📖 学习任务（新课通读）
  □ 互联网计算 · 00-物理层（★ 轻量 · ~30min · 该课 1/13 未学）

🔄 复习任务（做题驱动）
  □ 数据库 2022 Q1+Q2（E-R图 + SQL · ~0.5h · Phase A遗留）
  □ 数据库 Ch1-3 关系代数核心（~1h · Phase A遗留）
  □ 数据库 SQL D/E 除法+统计（~0.5h · Phase A遗留）
  □ 近代史 复习重点→记忆卡生成（~0.5h · 🆕 重点已到位）

六科进度（学/会）：
  软件工程    25/32 (78%) | 会 0%  ▏ 6.24 ❌无重点
  操作系统    13/14 (93%) | 会 0%  ▏ 6.26 ❌无重点
  数据库      22/22 (100%)| 会 0%  ▏ 6.29 ❌无重点·资料全
  高级算法     5/5 (100%) | 会 0%  ▏ 6.30 ✅题库已到·18题·只抽2题
  近代史       — 记忆卡    | —     ▏ 7.1  ✅重点已到
  互联网计算  12/13 (92%) | 会 0%  ▏ 7.3  ✅重点已到

今日预计 ~3.5h · Phase B 目标：手上能做的题全部做完做透。
输入 `/review go <笔记名>` 开始，`/review finish` 结束今日。
```

> 如果无学习任务（全部已通读），仅显示复习任务区。如果无复习任务（Phase 日程无安排），仅显示学习任务区。

然后**等用户操作**，不主动推进。

## 二、复习问答 — `复习 <笔记名>` 或 `/review go <笔记名>`

用户说"复习 软工 00-课程Overview"时，自动进入该篇笔记的复习模式（Phase A 做题自测 / Phase B 做题驱动 / Phase C 强制输出）。

### 1. 解析笔记名

从用户输入中提取课程和章节：

课程名映射表和模糊匹配规则详见 `.Codex/references/mappings.md`。

### 2. 加载笔记

1. 在 `knowledge-base/courses/<课程名>/` 下找到匹配的 `.md` 文件
2. 读取该笔记全文
3. 读取课程 `_index.md` 了解整体进度
4. 如果笔记不存在（课件到了但还没生成笔记），提示用户先运行 `/learn`

### 3. 初始化学习会话

写入 `.Codex/study-session.json`（schema 详见 `.Codex/references/mappings.md`），其中 `source` 字段设为 `"review"`。

### 4. 按阶段输出不同界面

#### Phase A（维持期 · 做题自测模式）

```
📋 做题自测 — 数据库 · 06-范式与规范化

对应真题/复习思考题：2 道 | 上一次复习：Phase 1 通读

开始做题（动手写答案，不能心里默答）：
  Q1: [复习思考题12] 给定 F={A→B, B→C, A→D}，求最小覆盖
  （你在纸上或打字写出完整推导过程）
  
  Q2: [复习思考题14] 给定关系模式和函数依赖，判断范式并分解
  ...

全部做完后对照参考答案：
  Q1: ✅ 正确 / ⚠️ 部分正确 / ❌ 错误
  Q2: ...

自评弱项：🟢 已掌握 / 🟡 需巩固 / 🔴 薄弱
```

不追问，不推导，用户做完题自评即可。目标是暴露弱项，不是消灭弱项。

#### Phase B（定向期 · 做题驱动模式）

```
📝 做题驱动 — 数据库 · 06-范式与规范化

🎯 本轮目标：把手上能做的题全部做完做透。

对应题目（从复习思考题/往年卷/作业中提取）：
  Q1: [复习思考题14] 范式综合题（极小覆盖→候选码→3NF→BCNF）
  Q2: [2022 Q3] 语义→FD→2NF→3NF 推导
  （用户动手写完整推导过程）

做完后对照答案，错题标 🔴：
  Q1: 极小覆盖 ✅ | 候选码 ✅ | 3NF分解 ⚠️（漏了一个FD）
  Q2: ✅ 全对

定向突破：Q1 中暴露出的 3NF 分解弱项 → 再练 1 道同类题
全部通过 → `[x]会`。
```

#### Phase C（冲刺期 · 强制输出模式）

```
📖 掌握复习 — 数据库 · 06-范式与规范化

随机抽 3 张记忆卡片：
  Q1: ...
  Q2: ...
  Q3: ...
（等用户回答，正确率 ≥ 2/3 继续）

请用自己的话讲清楚：什么是 Armstrong 公理系统？

推导题：给定关系 R(A,B,C,D) 和 F={A→B, B→C, A→D}，
请推导 R 的候选码，并判断 R 属于第几范式。
```

全部通过 → `[x]会`。

### 5. 复习结束

用户运行 `/study done` 时：
- 按 study 技能的标准流程融入洞察（包括笔记 status 更新）
- 执行 study.md §4.5 的 REVIEW.md 自动同步逻辑（见 `.Codex/references/principles.md` 状态映射表）
- Phase A：笔记 status 同步为 `learned`，不修改 REVIEW.md 复选框，仅记录弱项
- Phase B/C：通过则勾 `[x]会`，笔记 status 同步为 `mastered`

## 三、自由复习 — 对话问答

用户也可以不指定具体笔记，直接自然提问复习，例如：
- "考我软工模块二的记忆卡片"
- "让我推导 OS 的 Futex 两阶段锁"
- "数据库 3NF 和 BCNF 的区别是什么"

复习中对话产生的洞察 → 用户运行 `/study done` 后自动融入笔记，REVIEW.md 中的 `reviewed` 状态会被同步。

## 四、`/review done <笔记名>` — 标记单篇完成

### 执行

- **Phase A**：不勾 `[x]会`，标注弱项等级 + **同步笔记 status `draft` → `learned`**（第一遍通读完成信号）
- **Phase B/C**：通过强制问答后标记 `[x]会` + **同步笔记 status → `mastered`**；若 `[x]学` 未勾则一并勾选
- 更新 `updated` 时间戳

### 笔记 status 同步规则

| 阶段 | REVIEW.md 操作 | 笔记 status 变更 |
|------|---------------|-----------------|
| Phase A | 不修改复选框 | `draft` → `learned`（如果当前是 `draft`） |
| Phase B/C | 勾选 `[x]会`（`[x]学` 如未勾也勾） | → `mastered` |

完整映射表：`.Codex/references/principles.md` §"笔记 status ↔ REVIEW.md 复选框 双向映射"。

### Phase A 输出

```
📝 数据库 06-范式与规范化 · 弱项：🟡 需巩固

今日累计：3/3 篇卡片自测完成 | 弱项分布：🟢1 🟡1 🔴1
```

### Phase B/C 输出

```
✅ 数据库 06-范式与规范化 掌握复习通过

数据库：1/22 (5%) | 剩余 21 篇 | 距考试 6.29 还有 X 天

下一推荐：数据库 06-Armstrong公理 | 或 /review finish 结束今日
```

## 八、自动触发规则

以下情况 Codex 应主动更新 REVIEW.md：

### 新课件处理完时（由 /learn 技能触发）

1. 在对应课程下新增 `[ ]学 [ ]会` 条目
2. 更新笔记计数和进度百分比
3. **始终**重新评估阶段时间表（不设阈值，每次新增都重算）
4. **近代史课件**：直接触发记忆卡生成，不生成完整笔记

### /study done 时（由 study.md §4.5 自动执行）

笔记 status 变更时（`draft` → `learned` / `reviewed` / `mastered`）：
1. 按 principles.md 状态映射表自动同步 REVIEW.md 复选框
2. 更新进度表计数和百分比
3. 全自动执行，仅在变更摘要中告知

### /review done 时

1. Phase A：笔记 status `draft` → `learned`（不修改 REVIEW.md 复选框）
2. Phase B/C：勾选 `[x]会`（若 `[x]学` 未勾则一并勾选），笔记 status → `mastered`
3. 同步更新课程 `_index.md` 中的状态标记

### 新的一天第一次打开时
自动更新倒计时天数，判断是否需要阶段转换。

### 划重点到来时 🔑
1. 立即在对应课程标注重点范围
2. 非重点笔记降级（`~~删除线~~` 或标 `[浏览]`）
3. 重算有效权重，调整 Phase C 日程

## 九、重要原则

- **REVIEW.md 是唯一真相源**：所有进度追踪以它为准，不依赖会话记忆
- **等用户操作**：展示今日任务后不主动推进，等用户说复习哪篇
- **Phase A 不强制输出**：做题自测 + 自评弱项，2h 封顶，保持精力
- **Phase B 做题驱动**：手上题目做完做透，深度问答只针对错题暴露的弱项
- **Phase C 考一门冲一门**：不交叉复习，不做无用功
- **划重点到手立即更新**：这是最大的效率杠杆，非重点直接降级
- **近代史用分散重复策略**：12天碎片混脸熟 + 6.30全天集中背，远优于从零硬背
- **保持鼓励但不啰嗦**：标记完成时给简洁确认 + 下一步建议
