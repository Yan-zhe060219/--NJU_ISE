# 学习辅助技能

## 输入判断（首先执行）

收到路径或 URL 后，先判断类型：

- **课程文件夹**（路径是目录，如 `inbox/数据结构/`）→ 课程批量模式
- **课程文件夹 + `--resume`** → 从中断处继续
- **课程文件夹 + `--single`** → 只处理下一篇未处理的文件
- **课程文件夹 + `--force`** → 重新处理所有文件（忽略 `.learned`）
- **单个文件**（路径是文件）→ 单文件模式
- **URL**（YouTube / 网页）→ 单文件模式（URL 内容视为单文件）

---

## 一、课程批量模式（核心）

### 1. 初始化检查

```
第一步：列出目标文件夹中的所有文件
第二步：检查是否存在 .learned 文件
第三步：计算待处理列表 = 所有文件 - .learned 中已记录的文件
第四步：告知用户进度："发现 N 个文件，其中 M 个未处理"
```

`.learned` 文件格式（纯文本，一行一个已处理文件名）：
```
第一章-绪论.pdf
第二章-线性表.pdf
```

### 2. 文件预处理（自动提取文本）

读取文件之前，先将待处理列表中所有支持的文件提取为 `.txt`：

```bash
# 统一提取：MarkItDown 优先处理所有格式，失败自动回退到 extract_pdfs/extract_pptx
python tools/extract_file.py <目标文件夹>

# 含公式/表格的复杂 PDF：使用 MinerU 引擎
python tools/extract_file.py <目标文件夹> --backend mineru

# 最全面的三级回退：MarkItDown → 传统 → MinerU
python tools/extract_file.py <目标文件夹> --backend auto
```

- 此步骤**静默执行**，无需用户确认
- 如果所有文件都已提取，脚本自动跳过
- 提取的 `.txt` / `.md` 保存在课程文件夹的 `.cache/` 子目录中，与原始文件隔离
- **支持的格式**：PDF、PPTX、DOCX、XLSX/XLS、图片（jpg/png/gif/bmp/webp）、HTML、CSV、JSON、XML、IPYNB、EPUB
- **提取策略（三级回退）**：
  - 第一级：MarkItDown（微软开源，支持 12+ 种格式 → Markdown/Text）
  - 第二级：传统回退（PDF → `extract_pdfs.py` EasyOCR 扫描件；PPTX → `extract_pptx.py` 演讲者备注）
  - 第三级：**MinerU** — 仅在 `--backend auto` 模式下生效，当 MarkItDown 和传统回退均失败时调用。适合公式密集、表格复杂、扫描版 PDF。输出格式为 `.md`
- **引擎选择指南**：
  - 默认（`--backend markitdown`）：适合大多数课件，速度快
  - MinerU（`--backend mineru`）：适合**数学/物理/工程**类含 LaTeX 公式的 PDF，或含大量表格的文献
  - 自动（`--backend auto`）：不确定时使用，MarkItDown→传统→MinerU 三级保障
- **硬性约束：只读 `.cache/<文件名>.txt`（或 .md）**，绝不直接读取原始 PDF/PPTX/DOCX 等二进制文件。原因：
  - 原始二进制文件需要多模态输入，当前 API 不支持
  - 即使 API 支持，切换回 deepseek 等纯文本模型后也无法工作
  - 扫描件 PDF 由回退脚本自动调用 EasyOCR 处理，`.txt` 一定存在
  - MinerU 输出 `.md` 格式，Claude 可直接 Read
  - 此约束确保 kimi / deepseek / 任意纯文本模型都能处理

**PPTX 特殊说明：**
- PPTX 提取内容包括幻灯片正文 + 演讲者备注（备注往往是老师补充的关键信息）
- 如果某页 PPTX 全是图片/图表，提取结果文本量极少，在笔记中标注 `[此页主要为图片/图表，需手动查看原文件]`，不要尝试直接读原始 PPTX 文件
- PPTX 内容通常比 PDF 稀疏（提纲式），笔记分析时会自动标注"来源为幻灯片，内容偏提纲，建议结合课堂讲解"

**新增格式说明：**
- DOCX/XLSX：Word/Excel 文件，MarkItDown 直接提取文本和表格
- 图片：MarkItDown 提取 EXIF 元数据 + 自动 OCR，适合老师发的截图/板书照片
- HTML/CSV/JSON/XML：MarkItDown 直接转换结构化数据为 Markdown 表格

### 3. 读取课程上下文（处理第一个文件之前）

从课程文件夹名推断课程名称（如 `inbox/数据结构与算法/` → 课程名 = "数据结构与算法"）。

先扫描所有待处理文件的标题/第一页，建立全局视角：
- 这门课大概讲什么
- 各章节之间的逻辑关系
- 哪些是重点章节

### 4. 创建知识库课程目录

在 `knowledge-base/courses/<课程名>/` 下创建：
- `_index.md` — 课程总索引（随着处理逐步更新）
- 每处理完一个文件，生成对应的笔记文件

`_index.md` 模板：
```markdown
---
course: "<课程名>"
tags: []
created: YYYY-MM-DD
status: learning
---

# <课程名>

## 课程概述
<随着处理进度逐步填充>

## 章节笔记

<!-- 每处理完一章，按顺序添加链接 -->

## 重要概念索引
<!-- 提取跨章节的关键概念 -->

## 学习进度
- [ ] 第1章 - 待处理
- [ ] 第2章 - 待处理
...
```

### 5. 逐文件处理

对每个待处理文件，**逐个**执行以下步骤（处理完一个再处理下一个）：

a) 用 Read 工具读取文件（**优先读 `.cache/<文件名>.txt`**，不存在时才读原始文件）。将文件内容暂存，供后续检测和分析使用。

a-ii) 源语言检测（auto-detection）：
  读取文件内容的前 500 行，执行以下检测：
  1. 统计中文字符数：Unicode 范围 一-鿿 的字符数量
  2. 统计总非空白可打印字符数（包括中文、英文、数字，不含空白/换行）
  3. 计算中文占比 = 中文字符数 / 总非空白可打印字符数
  4. 判定：
     - 中文占比 > 0.10 → source_lang = "zh"（中文源材料）
     - 中文占比 ≤ 0.10 → source_lang = "en"（英文源材料）
  5. 记录 source_lang 供后续步骤使用

b) 深度分析（见下方"深度分析框架"）。若 source_lang = "en"，在分析过程中额外提取 5-8 句关键英文原句和 8-15 个核心术语的中英文对照。

c) 根据 source_lang 选择对应模板生成笔记：
   - source_lang = "en" → 使用"模板 A：英文源材料（中英双语增强版）"
   - source_lang = "zh" → 使用"模板 B：中文源材料（标准中文版）"
   用 Write 保存到 `knowledge-base/courses/<课程名>/<序号>-<章节名>.md`
d) 将该文件名追加到 `.learned` 文件
e) 更新课程 `_index.md`：标记章节为已完成，添加笔记链接，补充课程概述
f) 报告进度：`[N/M] 已处理：<章节名>`
   → 若项目根目录存在 REVIEW.md，执行"七、自动更新复习计划"
g) **暂停询问**：每处理完 3 个文件，问用户"继续处理还是先复习？"

### 6. 课程收尾

所有文件处理完成后：
- 完善课程 `_index.md` 的"课程概述"和"重要概念索引"
- 在 `knowledge-base/courses/_index.md` 中添加课程链接
- 尝试将课程中的重要概念与 `knowledge-base/cs/`、`math/` 等主题目录建立双向链接
- 输出一份"本课程学习路线图"：建议的复习顺序和重点关注章节
- **若项目根目录存在 REVIEW.md，执行"七、自动更新复习计划"的完整流程**（包括批量新增条目、重算百分比、必要时调整阶段时间表）

## 二、单文件模式

处理单个本地文件或 URL 时：

1. 判断该文件是否位于某个课程文件夹内
   - 如果是 → 笔记保存到 `knowledge-base/courses/<课程名>/`，完成后更新 `.learned`
   - 如果不是 → 按内容分类保存到 `knowledge-base/cs/` / `math/` / `software-eng/` / `other/`

2. 读取内容 → 深度分析 → 生成笔记 → 更新对应索引
   → 若项目根目录存在 REVIEW.md 且笔记属于某复习课程，执行"七、自动更新复习计划"

## 三、特殊标志

| 标志 | 行为 |
|------|------|
| `--resume` | 读取 `.learned`，跳过已处理的，从下一个开始 |
| `--single` | 只处理下一篇未处理的文件（适合每天学一点） |
| `--force` | 忽略 `.learned`，重新处理所有文件（覆盖旧笔记，重新检测源语言并选择对应模板） |
| `--force <文件名>` | 只重新处理指定的那一个文件 |

## 四、深度分析框架

分析每个文件时回答以下问题：

1. **这章讲什么？** — 3 句话概括（保留原文关键术语和定义措辞）
2. **核心概念清单** — 提取 3-8 个关键概念。**描述必须尽可能贴合课件原文**：优先使用课件中的定义句、关键描述句，不要为"通俗易懂"而自由改写。考试按课件原话评分，表述偏差可能导致失分。如果课件中某概念没有明确的定义句，才用自己的话归纳，但仍保留原文术语
3. **为什么是这个顺序？** — 这章在课程中的位置，和前一章的关联
4. **最难的 2 个点** — 标注学生容易卡住的地方，给出突破方法
5. **一句话记忆法** — 如果这章只能记住一句话，记住什么
6. **和已有知识的关联** — 搜索知识库，尝试建立链接

如果 source_lang = "en"（英文源材料），在上述分析之外额外执行：
- **提取关键英文原句**：从原文中精选 5-8 句最能概括核心概念的英文陈述句。选择标准：
  - 优先选取定义性陈述、定理表述、核心洞察
  - 避免引言性、过渡性或动机性句子
  - 每句控制在 1-3 行以内
- **整理术语对照表**：提取 8-15 个本章最关键的技术术语，列出英文、中文翻译和一句话说明

## 六、重要原则

- **每个文件只生成一篇笔记**，不要把一份课件拆成多篇
- **逐个处理**，不要一口气读完所有文件再写笔记 — 容易丢失细节
- **笔记质量 > 处理速度**：宁愿多花时间写透一个概念
- **标注来源**：source 字段写文件名，方便日后回溯原文
- **贴合原文，应对考试**：参见 `.claude/references/principles.md` 中的"术语保真"原则
- **笔记状态管理**：模板默认 `status: draft`。完整状态生命周期（draft → learned → reviewed → mastered）及与 REVIEW.md 复选框的映射，参见 `.claude/references/principles.md` §"笔记 status ↔ REVIEW.md 复选框 双向映射"
- **遇到无法读取的文件**（MarkItDown、回退脚本、MinerU 三级均失败、或图片 OCR 无文字）：在笔记中标注 `⚠️ 需手动查看原文件`，建议用户用其他方式处理。**绝不尝试直接 Read 原始二进制文件作为多模态输入**——这会破坏跨模型兼容性

## 七、自动更新复习计划

**每次通过 `/learn` 生成新笔记后**，检查项目根目录是否存在 `REVIEW.md`。如果存在，自动同步更新复习计划。

### 触发时机

- 课程批量模式：每处理完一个文件后（步骤 5.f 之后，执行 A/B/C），以及课程收尾时（步骤 6，执行完整流程 A/B/C/D/E）
- 单文件模式：笔记生成并更新索引后（执行 A/B/C/D/E，因为是单文件所以 D 立即执行）
- `--force` 重新处理：如果覆盖了旧笔记导致笔记总数变化，也触发

### 匹配规则

从笔记 frontmatter 的 `course` 字段或课程文件夹名，匹配 REVIEW.md 中的课程：

课程名映射表和模糊匹配规则详见 `.claude/references/mappings.md`。

### 更新内容

匹配到课程后，执行以下更新：

#### A. 新增条目
在 REVIEW.md 中对应课程的章节列表末尾（"待补充"之前）新增一条：
```
- [ ] <序号>-<章节标题>
```
如果该课程下已有"待补充"分区，检查新增的笔记是否正好填充了某个待补充条目——如果是，删除该待补充行，用新笔记替代。

#### B. 更新笔记总数
- 课程小节标题：`### <课程名>（N篇）` → N+1
- 顶部进度表：对应课程的"笔记数"列 +1
- 进度百分比：用 `已复习数 / 新总数` 重新计算

#### C. 重新计算倒计时（如果 updated 日期不是今天）
更新所有课程的剩余天数和 `updated` 时间戳。

#### D. 调整阶段时间表（每次新增笔记后触发）

**任何新增笔记后，始终重新评估阶段时间表。** 不设阈值——课件永远在结课前到达，保留阈值只会让排期滞后于实际情况。

调整流程：
1. 计算新总量和剩余天数（从 REVIEW.md frontmatter `exams` 和 `classes_end` 读取）
2. 如果某阶段日均负担超过 3 篇，将部分笔记向后挪或提前
3. 如果日均负担 < 1 篇，考虑从后续阶段提前拉入内容
4. **硬约束**：考试日期和 `classes_end` **永远不改**
5. 在 REVIEW.md 的"调整说明"区域追加一行变更记录：
   ```
   | <日期> | 计划调整：<课程名> +N 篇（总计 M） | <影响简述> |
   ```

**单次 1-2 篇**：调整通常很小（日均变化 < 0.2 篇），仅更新计数和百分比，但**仍执行重算**以保持排期精确。
**单次 ≥ 3 篇**：可能触发阶段性重排（如压缩非重点模块、调整 Phase 内分配）。具体幅度取决于课程体量和剩余天数。

#### E. 新增课程检测
如果处理了一个 REVIEW.md 中不存在的课程（新课程），在 REVIEW.md 底部输出提示：
```
📢 检测到新课程"<课程名>"（N篇笔记）。如需纳入复习计划，请手动添加考试日期到 REVIEW.md frontmatter，Claude 会在下次 /review 时自动生成追踪条目。
```

### 不需要更新
- **今日任务**：不自动修改，由用户通过 `/review` 管理
- **已复习标记**：不自动勾选
- **考试日期**：永远不改

### 示例

### 与 review 技能的协作

`/learn` 负责**新增条目和调整计划**，`/review` 负责**日常执行和进度追踪**。两者通过 REVIEW.md 这个唯一数据源协作：

```
/learn 生成笔记 → 自动更新 REVIEW.md（新增条目+调整计划）
    ↓
/review start  → 读取 REVIEW.md → 展示今日任务
/review done   → 勾选条目 → 更新进度
/review finish → 勾选今日 → 预填明天
    ↓
/learn（新课件）→ 再次更新 REVIEW.md → 循环
```

如需了解 review 技能的完整规则，参见 `.claude/commands/review.md`。
