# 学习问答模式

将学习过程中的 Q&A 对话沉淀到知识库，形成"学习→提问→沉淀→复习"闭环。

## 子命令路由

收到 `/study` 后，先解析参数：

| 输入 | 行为 |
|------|------|
| `/study start <课程名>` | 进入学习问答模式 |
| `/study start <课程名> --chapter N` | 聚焦特定章节 |
| `/study done` | 结束会话，提取洞察，更新知识库 |
| `/study status` | 查看当前会话状态 |
| `/study cancel` | 取消会话，不保存 |
| `/study list` | 列出知识库中已有课程 |

---

## 一、`/study start <课程名>`

### 1. 定位课程

搜索顺序：
1. `knowledge-base/courses/<课程名>/` — 已有笔记的课程
2. 模糊匹配 — 课程名包含关键词即可（如"OS"匹配"操作系统"）
3. `inbox/<课程名>/` — 有课件但还没生成笔记的课程

### 2. 课程不存在时

```
未找到课程"<课程名>"。

已有课程：
- 操作系统 (knowledge-base/courses/OS/)

选项：
1. 输入正确课程名重试
2. 如果这是新课程，先运行 /learn inbox/<课程名>/ 从课件生成笔记
3. 手动创建 knowledge-base/courses/<课程名>/ 目录和 _index.md
```

### 3. 课程存在时 —— 加载上下文

依次读取：
1. 课程 `_index.md` — 了解整体进度
2. 所有章节笔记（读文件列表，然后读每篇笔记的内容）
3. 若指定了 `--chapter N`，重点读那一章，其他章只读 frontmatter + 标题

### 4. 初始化会话状态

用 Bash 写入 `.claude/study-session.json`：

```json
{
  "active": true,
  "course": "操作系统",
  "courseDir": "knowledge-base/courses/OS",
  "startedAt": "YYYY-MM-DDTHH:MM:SS",
  "focusChapter": null,
  "chapterFile": null,
  "source": "study",
  "phase": null
}
```

### 5. 进入问答模式 —— 输出摘要

```
📚 进入学习问答模式 — 操作系统

课程进度：4/16 章已生成笔记，状态均为 draft
已有笔记：
  ✅ 01-操作系统概述 (draft)
  ✅ 02-操作系统的各种视角 (draft)
  ✅ 03-多处理器编程 (draft)
  ✅ 04-互斥 (draft)

当前聚焦：全部章节（可用 --chapter N 聚焦单章）

可以开始提问了。我会把有价值的讨论沉淀到对应笔记中。
退出时运行 /study done 保存洞察。
```

然后**不做任何事，等用户提问**。用户问什么答什么，但回答时：
- 关联到具体章节（"这个问题涉及第 N 章的概念 X"）
- 如果已有笔记中有相关内容，引用它
- 用学习语境回答（解释"为什么"、给类比、联系前后章节）

## 二、自由问答阶段

无固定流程。AI 在回答时遵循以下原则：

### 回答风格
- 先说"这属于课程的哪个部分"（关联章节）
- **术语保真优先**：核心概念的定义、关键描述、专有名词必须使用课件原文措辞。详见 `.claude/references/principles.md`。
- 用通俗语言解释，给类比（确保术语原文已给出后）
- 联系笔记中已有的概念
- 如果用户的理解有偏差，温和纠正
- 当用户要求将讨论内容整理到笔记中时，**所有概念表述同样必须贴合课件原文**，避免出现"把硬件变成高级抽象"替代"提供简洁易用的物理层抽象"这类自由改写

### 不需要特殊标记
用户不需要标记"这是学习问题"——在 `/study start` 之后的对话自然就是学习问答。

## 三、`/study done` —— 结束会话并沉淀

### 1. 检查会话状态

先读 `.claude/study-session.json` 确认有活跃会话。若无活跃会话：

```
当前没有活跃的学习会话。使用 /study start <课程名> 开始学习。
```

### 2. 回顾对话，提取洞察

回顾从 `/study start` 到现在的全部对话，筛选出**有沉淀价值的洞察**。

**值得保存的：**
- 用户表示"不理解""没懂"，AI 解释后用户表示理解的概念
- 对话中推导出了比原始笔记更深的理解
- 用户发现了笔记中的错误或遗漏
- 用户提出了笔记未覆盖的新问题并得到了有价值的答案
- 跨章节的概念关联被揭示

**不值得保存的：**
- 简单确认（"好的""明白了"但没有实质内容）
- 纯行政/操作性问题（"这个文件在哪""帮我运行个命令"）
- 与课程无关的闲聊

### 2.5 融入前：确保理解透彻

每条洞察在融入笔记前，先在脑中还原对话的推理链路：

1. **问题背景** — 用户当时在困惑什么？为什么会问这个问题？
2. **推理链路** — AI 是怎么解释的？用了什么类比或推导？关键转折点在哪里？
3. **新认识** — 对话结束后用户获得了什么新认识？和之前的理解有什么不同？

还原思考过程是为了**准确判断融入位置和方式**，不是把过程写进笔记。融入后笔记应看不出修改痕迹。

### 3. 将洞察映射到章节

对每条洞察，判断它属于哪一章：
- 如果用户明确提到了章节/概念 → 找到对应的笔记文件
- 如果洞察跨多个章节 → 可以同时更新多个笔记
- 如果无法确定章节 → 放入课程 `_index.md` 的"重要概念索引"

### 4. 融入笔记文件

**不追加、不另起段落。** 将洞察直接修改到笔记的对应小节中，融入后像从未被修改过。

按洞察类型选择融入目标：

| 洞察类型 | 融入目标 | 方式 |
|----------|---------|------|
| 对某个核心概念有了更深理解 | `## 核心概念` 下对应小节 | 在原段落中补充细节、类比或推导过程 |
| 澄清了一个之前卡住的难点 | `## 难点突破` | 新增或改善突破方法，保留有效的旧内容 |
| 发现了与另一章节/课程的联系 | `## 关联` / frontmatter `related` | 添加链接，简述关联逻辑 |
| 突然悟到的"一句话概括" | `## 一句话总结` | 如有更精炼的表达则替换，否则不强行改 |
| 新的记忆卡片 | `## 记忆卡片` | 增量添加 Q&A，删掉冗余的旧卡片 |
| 纠正了之前的错误理解 | 对应位置 | 直接修正，不留"旧理解→新理解"的修订痕迹 |

类型标签参考（用于判断融入位置）：
- **澄清** — 对话帮助理清了某个易混淆概念
- **深化** — 对话推导出了比原笔记更深的理解
- **修正** — 对话中发现并修正了原笔记的错误
- **关联** — 对话中发现了跨章节/跨课程的新联系

融入原则：
- **融入后像从未被修改过** — 阅读体验和原笔记一致，看不出"后来补的"
- **宁精勿多** — 一个真正理解的概念比三个半懂的好
- **保持原文风格** — 笔记已有自己的语气和结构，融入时匹配之
- **不记录"学习过程"** — "我今天学到了"、"经过讨论发现"等元信息不进入笔记
- 如果对话显示用户对该章理解到位 → `status` 更新为 `reviewed`（无论当前是 `draft` 还是 `learned`）
- 如果用户已初步通读但深度不够 → `status` 从 `draft` 更新为 `learned`

### 4.5. 同步 REVIEW.md（笔记 status 变更时）

如果前一步骤中笔记的 `status` 从 `draft` 变更为 `learned` / `reviewed` / `mastered`，自动同步 REVIEW.md。

**前置条件**：笔记 status 发生变更，且笔记所属课程在 REVIEW.md 中有追踪。

**同步步骤**：

1. 重新读取 REVIEW.md（获取最新版本，防并发覆盖）
2. 根据笔记的 `course` 字段和章节号，在 REVIEW.md 对应课程章节中查找匹配条目
   - 匹配方式：笔记标题关键词 + 课程名映射表（`.claude/references/mappings.md`）
3. 按状态映射表更新复选框：

| 笔记 status 变更 | REVIEW.md 操作 |
|-----------------|---------------|
| `draft` → `learned` | `[ ]学` → `[x]学`，`[ ]会` 不动 |
| `draft` → `reviewed` | `[ ]学` → `[x]学`，`[ ]会` 不动 |
| `draft` → `mastered` | `[ ]学` → `[x]学`，`[ ]会` → `[x]会` |

4. 更新 REVIEW.md 顶部进度表：
   - 重新计算该课程 `[x]学` 条目数 → 更新"已学"列
   - 重新计算 `[x]会` 条目数 → 更新"已掌握"列
   - 重新计算"学进度"和"会进度"百分比
5. 更新 REVIEW.md frontmatter 的 `updated` 为今天
6. **全自动执行，静默同步。** 在变更摘要中告知即可，不打断用户流程

**不触发同步的情况**：
- `status` 未变更（仍是 `draft` 或已是目标状态）→ 跳过
- 笔记课程不在 REVIEW.md 中 → 跳过，在摘要中提示
- 在 REVIEW.md 中找不到匹配条目 → 跳过，提示用户检查

**完整映射表**：详见 `.claude/references/principles.md` §"笔记 status ↔ REVIEW.md 复选框 双向映射"。

### 5. 更新课程 _index.md

- 若 `status` 有变更，同步更新 _index.md 中的状态标记
- 若有跨章节概念被揭示，补充到"重要概念索引"

### 6. 清除会话状态

```bash
# 删除会话文件或将其 active 设为 false
```

### 7. 输出变更摘要

```
📝 学习会话结束 — 知识库已更新

本次提取 3 条洞察，已融入对应笔记：

  操作系统概述 (01-操作系统概述.md)
  + 核心概念：上下文切换 vs 模式切换的本质区别 (澄清)
    → 在原段落中补充了触发条件和开销量级的对比
  + 难点突破：从"幻术师"视角理解虚拟内存 (深化)
  ↻ status: draft → reviewed

  互斥 (04-互斥.md)
  + 难点突破：自旋锁在单核 CPU 上无意义的严格推导 (深化)
  + 🔗 related: 新增关联 → 03-多处理器编程

每条洞察已直接融入笔记的对应小节，阅读体验和原笔记一致。
```

## 五、`/study cancel`

读 `.claude/study-session.json`，确认后清除：

```
⚠️ 确认取消操作系统学习会话？

本次对话中的 Q&A 将不会保存到知识库。
要继续取消吗？输入 "确认取消" 来确认。
```

用户确认后，将 `.claude/study-session.json` 的 `active` 设为 `false` 或删除文件。

```
  - (无)

```

## 七、会话文件管理

会话文件 schema 和生命周期详见 `.claude/references/mappings.md`。

操作要点：
- **创建**：`/study start` 时写入
- **读取**：`/study status`、`/study done` 时读取
- **清除**：`/study done` 或 `/study cancel` 后将 `active` 设为 false
- **过期**：若会话超过 24 小时未活动，`/study start` 新会话时自动覆盖

注意：会话文件用 Bash 的 Write/Read 操作，路径为项目根目录下的 `.claude/study-session.json`。

## 八、重要原则

所有核心原则统一维护在 `.claude/references/principles.md`，包括：
- **术语保真** — 核心概念定义必须使用课件原文措辞
- **融入而非追加** — 对话洞察直接融入笔记对应小节
- **宁缺毋滥** — 只提取真正有深度的洞察
- **不记录学习过程** — 元信息不进入笔记

以下为 study 特有的补充原则：
- **丰富有脉络**：每条洞察要还原对话的思考过程（背景→讨论→收获），用完整段落而非一句话总结
- **映射要准**：洞察归属哪一章要判断准确，不确定时宁可放 _index.md
- **保持自然**：用户在问答阶段不需要任何特殊格式，像正常聊天一样提问即可
- **中断可恢复**：如果会话文件还在但对话上下文已丢失，AI 应能靠 session 文件知道"之前在学什么课程"
