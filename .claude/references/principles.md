# 共享原则

> **被引用者：** learn.md, study.md, review.md
> **修改本文件时**，需同步检查上述三个命令文件是否引用了被改动的具体规则。

---

## 术语保真

核心概念的定义、关键描述、专有名词必须使用课件原文措辞。"通俗语言解释"和"类比"是在术语准确前提下的辅助手段，不能替代原文表述。考试按课件原话评分，用自己的话改写可能导致失分。

适用场景：
- `/learn` 生成笔记时：核心概念的定义和关键描述应尽可能使用课件原文措辞
- `/study` 问答时：回答中涉及核心概念时必须先用原文措辞，再用通俗语言解释
- `/review` 复习问答时：同上

---

## 融入而非追加

对话中产生的洞察直接融入笔记对应小节，不追加独立段落，不留"学习对话补充"痕迹。融入后阅读体验和原笔记一致。错误必须直接修正，不留旧痕迹。

融入规则详见 CLAUDE.md 中的"洞察融入规则"表格。

---

## 宁缺毋滥

- 笔记：一个真正理解的概念比三个半懂的好
- 问答沉淀：不是每句对话都值得保存，只提取真正有深度的洞察
- 记忆卡片：增量添加，删掉冗余的旧卡片

---

## 不记录学习过程

"我今天学到了"、"经过讨论发现"等元信息不进入笔记。笔记应看起来像从未被修改过。

---

## 英文碎片化课件重构为叙事笔记

当原课件为全英文且内容碎片化（PPT 式、知识点分散在各页）时，笔记必须重构为**情景化叙事结构**，使得用户不看原课件、只看笔记，也能达到同等的复习效果。

核心要求：
1. **串联上下文**：知识点之间必须有逻辑递进关系，不能是独立条目罗列。"接下来要解决的问题是…""这引出了下一个关键概念…"
2. **场景驱动**：用"你是一个帧/数据报/分组…"或具体使用场景作为叙事主线，在每个场景中引入相关概念
3. **严格覆盖原文**：不遗漏课件中的任何定义、机制、协议细节、关键数据。重构是"重新组织"不是"删减"
4. **类比辅助**：每个抽象概念配至少一个生活类比（快递、导航、排队…），帮助直观理解
5. **对比用表格**：相似机制、竞争方案、不同层次的概念——统一用表格对照
6. **语气对话感**：用"你"为主角，设问引导思考，不写教科书式定义堆砌

适用场景：
- `/learn` 生成英文源课件笔记时
- `/review` 重构笔记时（用户显式要求"重构"或按其他笔记风格统一时）

判断标准：读笔记的体验应像读一本**有情节的技术故事**，而非术语词典。

## Git 安全原则

> **被引用者：** CLAUDE.md（工作流节）
> **适用范围：** 所有会话，无例外

### 频繁提交

每完成一个逻辑上独立的修改单元后，立即 commit 并 push。判断标准：

- 一个文件的一个完整小节写完
- 一个 bug 修复完成
- 一个功能点实现完成
- 一次重构完成
- 约 20-50 行有意义的修改

**不等**到"今天的活全干完"再提交——那样回退成本太高，且容易在后续修改中丢失中间状态。

### 删除前必提交

在执行任何删除操作之前（删除文件、删除大段内容、`git rm`、`rm`），**必须**先 commit 当前所有修改并 push。这确保：

- 删除的内容永远可以从 git history 中恢复
- 不存在"删了之后后悔但找不回来"的情况
- 杜绝不可挽回的操作

删除操作本身完成后也要立即 commit（message 以 `delete:` 开头），明确标记删除动作。

### Push 策略

每次 commit 后立即 push 到远程仓库。本地 commit 在硬盘故障、误操作 `git reset --hard` 等场景下无法保护数据，push 到远程才真正安全。

### 操作前检查

在执行以下高风险操作前，必须先确认工作区干净（已 commit + push）：

- `git reset --hard`
- `git clean -fd`
- 批量删除文件
- `rm -rf` 任何目录
- 覆盖写入重要文件

## REVIEW.md 的 /learn 与 /review 职责边界

> **这是最容易出错的规则，修改 REVIEW.md 前必须重读本节。**

### 核心规则

`/learn` 生成笔记后自动更新 REVIEW.md 时：

- **新增条目必须使用 `- [ ]学 [ ]会`**（`学` 和 `会` 都**未勾选**）
- 即使同课程下已有条目标记为 `[x]学`，新条目也**绝不**复制该格式
- `/learn` **绝不自动勾选 `[x]学`**——"生成笔记" ≠ "学过"
- `/review` 是唯一能勾选 `[x]学` 和 `[x]会` 的命令

### 两个标记的含义

| 标记 | 含义 | 谁勾选 |
|------|------|--------|
| `[x]学` | 第一遍通读完成（已标注考点、已有 Q&A） | `/review` |
| `[x]会` | 掌握复习通过（主动问答输出合格） | `/review` |

### 容易出错的原因

在 REVIEW.md 中，同课程下的旧条目往往是 `[x]学 [ ]会` 的形式（Phase 1 已通读）。看到这个模式后，容易下意识给新条目也写成 `[x]学 [ ]会`。**这是错的**。新条目必须是 `[ ]学 [ ]会`。

### /learn 更新 REVIEW.md 后的自查

- [ ] 新条目的 `学` 是否**未勾选**（`[ ]学`）？
- [ ] 进度表的"已学"数是否只计入已勾选 `[x]学` 的条目？
- [ ] 学进度百分比是否基于正确的已学数计算？

## 笔记 status ↔ REVIEW.md 复选框 双向映射

> **被引用者：** learn.md, study.md, review.md
> **修改本文件时**，需同步检查上述三个命令文件中引用状态映射的逻辑是否仍然正确。

### 状态定义

Note files (`knowledge-base/courses/<course>/<note>.md`) 的 frontmatter 中 `status` 字段取值：

| status 值 | 含义 | 设置场景 |
|-----------|------|---------|
| `draft` | 笔记已生成，未学习 | `/learn` 创建笔记时自动写入 |
| `learned` | 第一遍学完（已通读、已标注考点、已有 Q&A） | `/review done` Phase A，或 `/study done` 初步通读 |
| `reviewed` | 深度问答通过（洞察已融入，理解达到一定深度） | `/study done` 对话确认理解到位 |
| `mastered` | 掌握复习通过（强制主动问答输出合格） | `/review done` Phase B/C 通过 |

### 双向映射

| 笔记 status | REVIEW.md 复选框 | 设置场景 |
|------------|-----------------|---------|
| `draft` | `[ ]学 [ ]会` | `/learn` 创建笔记后在 REVIEW.md 新增条目 |
| `learned` | `[x]学 [ ]会` | `/review done` Phase A 通读完成时同步 |
| `reviewed` | `[x]学 [ ]会` | `/study done` 深度问答通过时同步（与 learned 同效果） |
| `mastered` | `[x]学 [x]会` | `/review done` Phase B/C 强制问答通过时同步 |

### 同步规则

1. **前向同步（笔记 status → REVIEW.md 复选框）：**
   - `/study done`：笔记 status 变更后，按映射表自动更新 REVIEW.md，不询问
   - `/review done` Phase A：更新笔记 status 为 `learned`，**不**修改 REVIEW.md 复选框
   - `/review done` Phase B/C：更新笔记 status 为 `mastered`，同时勾选 `[x]会`（若 `[x]学` 未勾则一并勾选）

2. **后向同步（REVIEW.md 新增条目 → 笔记 frontmatter）：**
   - `/learn` 新增笔记时：笔记 status 已设为 `draft`，REVIEW.md 新增 `[ ]学 [ ]会` 条目
   - 两者起始状态一致，无需额外同步

3. **永不降级：**
   - `learned` / `reviewed` / `mastered` 不会自动退回到 `draft`
   - 如需重置，手动修改笔记 frontmatter 并将 REVIEW.md 中对应复选框改回

4. **`learned` vs `reviewed` 的区别：**
   - 两者对 REVIEW.md 复选框的同步效果**完全相同**（都是 `[x]学 [ ]会`）
   - 区别仅用于笔记文件内部追踪理解深度：
     - `learned` = 第一遍通读完成
     - `reviewed` = 深度问答产出洞察后，理解超过纯通读水平

### 各命令的同步职责

| 命令 | 修改笔记 status | 修改 REVIEW.md 复选框 |
|------|----------------|---------------------|
| `/learn` | 设置为 `draft` | 新增 `[ ]学 [ ]会` 条目 |
| `/study done` | `draft` → `learned` / `reviewed` | 自动同步 `[x]学` |
| `/review done` Phase A | `draft` → `learned` | 不修改 |
| `/review done` Phase B/C | → `mastered` | 同步 `[x]会`（及 `[x]学` 如未勾） |
