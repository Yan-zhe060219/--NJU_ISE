# 操作系统

## 课程概述

本课程是南京大学软件学院的操作系统课程（2026 春，钮鑫涛）。以 OSTEP (Three Easy Pieces) 为主线教材，围绕三大主题展开：**虚拟化**、**并发**、**持久化**。配套 OSPP、OSC、CSAPP 等经典教材，编程语言为 C/C++，实验基于 Online Judge。

本批笔记覆盖了课程的**并发**、**虚拟化**和**持久化**三大模块，按教学顺序从第 1 章到第 14 章。三个模块已全部覆盖，OS 课件学习完毕 🎉。

## 重要概念索引

### 并发（Concurrency）

| 概念 | 出处 | 一句话 |
|------|------|--------|
| **竞态条件** | Ch3, Ch4 | 多线程同时访问共享数据且至少一个写 → 不确定结果 |
| **互斥 (Mutex)** | Ch4 | 最多一个线程在临界区内 |
| **自旋锁 (Spin Lock)** | Ch4 | 基于 CAS 原子指令的忙等锁 |
| **原子指令 (CAS/LL-SC)** | Ch4 | 硬件提供的原子 test-and-set |
| **Ticket Lock** | Ch5 | fetch-and-add 排队，保证有界等待 |
| **Futex** | Ch5 | Linux 两阶段锁：fast path 用户态 CAS + slow path 内核阻塞 |
| **锁的粒度** | Ch5 | 细粒度锁提高并发度，但需正确配对 |
| **中断死锁** | Ch5 | 内核中自旋锁 + 中断 → 死锁（push_off/pop_off 解决） |
| **Lost Wakeup** | Ch5, Ch6 | unlock→wakeup 和 lock→wait 之间的窗口导致永久阻塞 |
| **条件变量** | Ch6 | cond_wait/cond_signal，灵活但需 while 循环（Hansen/Mesa） |
| **信号量** | Ch6 | P/V 操作，自带整数状态，自然表达资源数 |
| **读者-写者锁** | Ch7 | 允许多读者并发，三种策略（读者优先/写者优先/公平） |
| **RCU** | Ch7 | 无锁读，更新分 removal+reclamation，read-mostly 场景 |
| **死锁** | Ch7, Ch8 | 等待环，四条件（互斥/持有等待/不可抢占/循环等待） |
| **银行家算法** | Ch8 | 死锁避免——判断资源请求是否导致不安全状态 |
| **原子性违背 (AV)** | Ch8 | 该原子化的代码段被插入 |
| **顺序性违背 (OV)** | Ch8 | 事件未按预期顺序发生 |
| **TSan/ASan** | Ch8 | 动态检测工具：happens-before 图检测数据竞争 |

### 虚拟化（Virtualization）

| 概念 | 出处 | 一句话 |
|------|------|--------|
| **进程** | Ch9 | 拥有独立地址空间的运行实体 = 线程 + 地址空间 + 资源 |
| **PCB** | Ch9 | 进程控制块，内核维护的进程元信息 |
| **fork()** | Ch9 | 完整复制当前进程状态机 |
| **execve()** | Ch9 | 用新程序覆盖当前进程 |
| **COW (写时复制)** | Ch9 | 父子共享物理内存，写时再拷贝（利用 page fault） |
| **僵尸/孤儿进程** | Ch9 | 僵尸=已终止但 PCB 未回收；孤儿=父进程先终止被 init 接管 |
| **管道** | Ch9 | fork+fd 继承 → 单向 IPC |
| **信号** | Ch9 | 用户态中断模拟，异步通知 + IPC |
| **机制与策略分离** | Ch10 | 机制=context-switch+队列；策略=选谁运行 |
| **护航效应** | Ch10 | FCFS 下短任务被长任务拖后腿 |
| **SJF/SRTF** | Ch10 | 执行时间最短优先（抢占版），平均等待最优 |
| **MFQ** | Ch10 | 多级反馈队列，动态优先级，现代 OS 默认策略 |
| **CFS** | Ch10 | Linux 完全公平调度器，红黑树按 vruntime 排序 |
| **EDF** | Ch10 | 最早截止日期优先，动态优先级最优，利用率 100% |
| **优先级反转** | Ch10 | 高优先级等低优先级释放锁 → 优先级继承/优先权极限 |
| **地址翻译** | Ch11 | f: ⟨pid, virtual address⟩ → physical address，MMU 硬件自动完成 |
| **Base & Bound** | Ch11 | 早期保护机制：基址和界限寄存器限定进程可访问的物理内存范围 |
| **内部碎片 / 外部碎片** | Ch11 | 内碎=分区内未用空间；外碎=分区之间不连续的小空洞 |
| **Buddy System** | Ch11 | 2 的幂分配器，伙伴地址仅一位不同，合并效率 O(1) |
| **Slab 分配器** | Ch11 | 从 Buddy 拿大块→切成固定小块，快速分配小内存对象 |
| **分段** | Ch11 | 按逻辑单元（代码/堆/栈）映射，段大小可变，有外部碎片 |
| **分页** | Ch11 | 固定大小页映射到帧，无外部碎片，页表存储映射关系 |
| **多级页表** | Ch11 | 用时间换空间：树形页表只分配实际使用的分支 |
| **TLB** | Ch11 | 硬件缓存最近地址翻译，利用局部性原理加速，命中则 fast path |
| **ASID** | Ch11 | 带标记的 TLB 条目，避免上下文切换时全量 flush |
| **交换 (Swapping)** | Ch12 | 物理内存不足时整进程换出到磁盘，现代 OS 仅低内存时启用，移动 OS 不支持 |
| **虚拟内存** | Ch12 | 只加载活跃页面，内存是所有页面的 cache，进程拥有近乎无限内存的幻觉 |
| **缺页异常 (#PF)** | Ch12 | 引用不在物理内存的页时触发，OS 调入缺失页后重新执行引发异常的指令 |
| **按需分页** | Ch12 | 缺页后才调入的懒加载策略，可配合预取提升效率 |
| **页面置换** | Ch12 | 无空闲帧时选 victim 换出；FIFO → Belady 异常；Optimal → 基准；LRU → Second Chance/Clock |
| **Belady 异常** | Ch12 | 帧数增反导致缺页增，不满足栈算法属性的算法均可能发生（LRU/Optimal 除外） |
| **NRU** | Ch12 | 引用位+修改位的四分类法，(0,0) 最适合替换，为脏页赋高优先级减少 I/O |
| **抖动 (Thrashing)** | Ch12 | 进程几乎全时处理缺页异常，CPU 利用率极低；调度器加进程反而加剧恶性循环 |
| **工作集 W(t,x)** | Ch12 | (t-x,t) 内使用的页集合；全在内存则流畅，否则抖动；all-or-nothing 策略 |
| **PFF** | Ch12 | 缺页异常频率算法：根据进程缺页率动态增减分配的帧数 |
| **ZFOD** | Ch12 | 按需零填充：全零帧共享只读，写时缺页触发克隆，用于 bss/堆/栈 |
| **mmap** | Ch12 | 内存映射文件：将文件映射为内存区域，缺页时从磁盘读入，实现共享内存和零拷贝 I/O |

### 持久化（Persistence）

| 概念 | 出处 | 一句话 |
|------|------|--------|
| **块设备 / 字符设备** | Ch13 | 块设备以固定大小块存储（磁盘），字符设备传递字符流（键盘） |
| **端口映射 vs 内存映射 I/O** | Ch13 | PMIO 用 in/out 指令 + 端口号；MMIO 映射到内存地址用 load/store |
| **轮询 vs 中断** | Ch13 | 轮询无切换开销但浪费 CPU；中断不浪费 CPU 但有切换开销 |
| **DMA** | Ch13 | 直接内存访问——让专用芯片搬运数据，解放 CPU |
| **LBA** | Ch13 | 逻辑块地址，0…N-1 线性地址，屏蔽磁盘物理几何 |
| **T = seek + rotation + transfer** | Ch13 | 磁盘访问时间三要素，寻道 > 旋转延迟 > 传输 |
| **SSTF / SCAN / C-SCAN** | Ch13 | 最短寻道优先（会饥饿）→ 电梯算法（来回扫描）→ C-SCAN（单扫+快复位） |
| **FTL** | Ch13 | 闪存转换层，虚拟块→物理页映射，实现写时复制、磨损均衡、垃圾回收 |
| **设备驱动程序** | Ch13 | 上半部分（系统调用路径）+ 下半部分（中断例程），抽象层使 FS 独立于磁盘类型 |
| **inode** | Ch14 | Unix 文件控制块，存储文件元信息（权限/大小/时间戳/块指针），含 15 指针的直接+间接索引 |
| **文件描述符** | Ch14 | 每进程私有的整数索引，引用打开文件，避免每次解析路径和查权限 |
| **硬链接** | Ch14 | 同一 inode 的多个目录别名，只能同文件系统内，引用计数为 0 时删除 |
| **软链接** | Ch14 | 存储目标路径的独立文件（链接类型），可跨文件系统和链接目录，删除目标产生悬空引用 |
| **超级块** | Ch14 | 文件系统总元数据：类型、inode 数、块数、inode 表起始地址，挂载时读取 |
| **多级索引** | Ch14 | 直接指针 + 单/双/三级间接指针，4KB 块 + 4B 指针 → 最大 4TB 文件 |
| **FAT** | Ch14 | 链表的集中化变体——所有指针放一张表，可载入内存减少 I/O，但大磁盘内存开销大 |
| **FFS** | Ch14 | 快速文件系统，用块组（柱面组）实现数据局部性，将相关内容放同一组减少寻道 |
| **崩溃一致性** | Ch14 | 多步 I/O 更新中崩溃导致元数据不一致；fsck 事后修复 + 日志（预写日志）事前预防 |
| **预写日志** | Ch14 | 日志三步协议：写入（TxB→内容→TxE）→ 提交 → 检查点；崩溃后重放已提交事务 |
| **元数据日志** | Ch14 | 只日志元数据不日志用户数据（避免写两次），先写数据块再写元数据日志确保指针不指向垃圾 |
| **LFS** | Ch14 | 日志结构文件系统，永远顺序 append-only 写，通过 imap+CR 追踪 inode，SSB 实现 GC |
| **页缓存统一** | Ch14 | 现代系统将虚拟内存页缓存和文件系统缓存合并，灵活分配内存 |

## 学习路线图

建议复习顺序和重点关注：

1. **打地基** → 第 1、2 章（OS 视角与架构），第 9 章（进程抽象）
2. **并发主线** → 第 3 → 4 → 5 → 6 → 7 → 8 章（这是最大块的连续知识链）
   - 重点掌握：互斥的演进（Peterson→CAS→SpinLock→Ticket Lock→Futex）
   - 重点掌握：条件变量的 Hansen/Mesa 语义和 while 循环
   - 理解 RCU 的设计哲学（trade-off：读极致快 vs 写多版本开销）
   - 死锁四条件 + lock ordering 是最实用的预防手段
3. **调度** → 第 10 章（策略对比 + 优先级反转的实际教训）
4. **实验配合** → 从第 3 章起就可开始写并发代码（锁、条件变量、信号量）
